1. 参数与位宽
================================================================================

  N            = 4
  FE_NUM       = 4
  MAX_DEP      = 7
  ISSUE_WIDTH  = 4
  ROB_DEPTH    = 32
  ROB_ID_W     = 5
  SEQ_W        = 6

  RESULT_BANKS = 8
  PACKET_W     = 128
  DESC_W       = 5

新架构可综合RTL使用SystemVerilog。顶层外部报文端口和模块内部重复lane/FE通路均使用
packed array表达；不为固定lane展开独立编号端口。状态数组只能由一个明确
的always_ff进程拥有，纯组合选择器使用always_comb并提供完整默认赋值。

1.1 参数与类型组织

  - ppe_types_pkg保存必须跨模块一致的基线配置、由其推导的公共位宽，以及rob_id_t、
    seq_tag_t、delay_t等被多个模块使用的窄类型；package常量使用localparam，表示它们
    不能在单个子模块例化处独立覆盖。
  - ISSUE_DEPTH固定由ROB_DEPTH派生，ISSUE_WIDTH固定由FE_NUM派生，RESULT_BANKS固定由
    MAX_DEP+1派生；ROB_ID_W、SEQ_W和HISTORY_ID_W均由基础配置计算，不重复写数值。
  - CAND_WINDOW_DEPTH、RETURN_FUTURE_DEPTH和READY_ENQUEUE_WIDTH属于跨模块接口或
    调度结构配置，在package中统一定义，例化处禁止使用裸常数覆盖。
  - PACKET_W和DESC_W直接影响可复用模块端口宽度，允许作为顶层及相关子模块参数；
    当前唯一受支持的系统基线仍为128和5，顶层负责一致传递。
  - 只在单模块内部使用的FIFO深度、计数器宽度、指针加法宽度及私有typedef保留为
    localparam或模块内类型，不提升到package。
  - 仅用于展开循环的过程索引统一使用int；参与实际组合数据通路的计数、索引和临时
    算术变量必须使用由配置推导的显式小位宽类型。所有always_comb/always_ff块使用描述
    功能的显式标签；只有状态所有权可以清晰分离时才拆分always_ff，存在同址更新优先级
    的状态数组必须继续由同一个进程拥有。

2.3 典型无依赖报文数据流

  1) I0在bkps允许时把外部输入捕获到两项elastic FIFO的寄存tail槽位；
  2) D0在内部alloc_ready有效时为FIFO head分配seq，Issue Table和A0从seq低位索引
     本地entry，并将无依赖报文标记为ISSUE_READY；
  3) D2A0组合形成4项shortlist，D2A1选择报文和目标FE并捕获grant；
  4) D2B写相对未来返回表并锁定Issue Table entry；
  5) D3从ROB读取原始packet并向FE发出请求，issue entry释放；
  6) FE返回，W0按完整seq tag低位写ROB并设置result_valid；
  7) 报文到达ROB head且DONE后，R0将数据装入输出寄存器；
  8) 同一退休沿更新对应retired history bank并释放ROB entry。

2.4 典型依赖等待数据流

  1) I0捕获依赖报文到elastic FIFO，D0从寄存head分配seq并预计算完整target seq tag，
     target ROB/history索引由tag低位导出；
  2) D0通过G0查询active ROB/history小位宽状态，并检查同周期completion/retirement
     bypass；ready时进入ISSUE_READY，否则进入ISSUE_WAIT_DEP；
  3) 目标FE返回时，W0写active ROB并以完整tag唤醒ISSUE_WAIT_DEP entry；
  4) 被唤醒报文最早下一周期进入READY并由D2A选择；
  5) D3通过G0按四级优先级gather权威依赖数据并向FE派发；
  6) 目标退休前从active ROB读取，退休沿可由retirement bypass读取，退休后从history读取。

2.5 典型保序阻塞数据流

  1) 多个FE乱序返回，W0分别写入对应ROB entry；
  2) 后序ROB entry可以先DONE，但R0只检查ROB head开始的连续DONE项；
  3) head未DONE时retire_count=0，后序DONE结果继续保存在ROB；
  4) head完成后的下一周期，R0一次退休最多4个连续DONE报文；
  5) 输出顺序由ROB head确定，与FE完成顺序无关。

2.6 FE固定延迟流水行为

每个FE每周期最多接收一路请求，允许多个请求同时在途，并允许输入和输出在同一周期
发生。请求在cycle n接收且desc_delay=d时，固定在cycle n+d+1返回。行为模型可用
四个未来输出槽表达：

  slot0：下一周期输出
  slot1：下两周期输出
  slot2：下三周期输出
  slot3：下四周期输出

接收请求时将结果预约到slot[d]，每周期输出当前slot0并将slot1..3向低位推进。
同一FE每个未来周期只有一个输出槽；新请求如果与已有在途请求预约同一输出周期，
属于PPE协议违规。FE无ready或重放能力，正常RTL不得产生这种输入。

FE内部数据算法对PPE保持黑盒。仓库行为模型只需与验证VIP保持一致；PPE功能正确性
依赖的是输入数据、依赖数据和delay被正确送达，以及返回周期和请求关联正确。

================================================================================
3. Ingress与Scheduler内部数据结构
================================================================================

3.1 Issue Entry

Issue table深度为32，以ROB ID作为entry索引，主要数据结构为：

  typedef enum logic [1:0] {
      ISSUE_FREE,
      ISSUE_WAIT_DEP,
      ISSUE_READY,
      ISSUE_SELECTED
  } issue_state_e;

  typedef struct packed {
      issue_state_e        state;
      logic [SEQ_W-1:0]    seq_tag;
      logic [SEQ_W-1:0]    target_seq_tag;
      logic [1:0]          delay;
      logic                dep_required;
  } issue_entry_t;

状态与依赖字段必须满足：

  - ISSUE_FREE：entry无效，其余字段不作要求；
  - ISSUE_WAIT_DEP：dep_required=1且依赖尚不可用；
  - ISSUE_READY：无依赖，或dep_required=1且依赖已经可用；
  - ISSUE_SELECTED：已经被ppe_fe_scheduler不可撤销地选中，依赖必定满足。

candidate_present作为独立于issue_entry_t的成员资格账本，表示对应READY entry已经
存在于8项候选窗。未进入候选窗的READY entry直接保留在状态表中，后续周期继续发现。
packet不在Issue Table保存；target ROB ID固定从target_seq_tag低位派生，不单独保存。

3.2 Ingress Input Buffer and Sequence State

Ingress保存两项整批elastic FIFO：

  slot_lane_valid[2][N]
  slot_packet[2][N][127:0]
  slot_desc[2][N][4:0]
  slot_rd_ptr
  slot_wr_ptr
  slot_count[1:0]
  bkps_q

Ingress维护：

  next_seq_tag[5:0]

外部in_valid/in_packet/in_desc只允许作为slot_wr_ptr所选槽位寄存器的D输入，不得作为
槽位写使能，也不得进入FIFO控制、rank、descriptor decode、ROB容量或bkps next-state
组合逻辑。槽位写使能只由bkps_q和slot_wr_ptr生成。空批只根据head槽位的寄存
lane-valid识别。FIFO head的寄存lane valid、
packet和desc是D0功能处理的唯一输入。宽packet/desc数组在对应slot无效时不要求复位。
next_seq_tag按2^SEQ_W回绕。不保存独立residue计数器或entry字段。

3.3 Ready Queue and Arbitration State

Scheduler维护4组两项本地候选缓冲；匹配时每bank组合形成1项shortlist：

  candidate_valid[0..7]
  candidate_seq_tag[0..7][5:0]
  candidate_delay[0..7][1:0]
  candidate_present[ROB_DEPTH]
  ready_admit_row_rr_ptr[0..3][2:0]
  candidate_way_rr_ptr[0..3]
  shortlist_valid[0..3]
  shortlist_candidate_onehot[0..3][7:0]
  shortlist_seq_tag[0..3][5:0]
  shortlist_delay[0..3][1:0]

entry按ROB ID低2位分为4个交错bank，每bank包含8个row和两个固定候选槽。
候选槽bank对应way0，槽4+bank对应way1。每个bank仅在至少一个本地槽沿前无效或
本周期被D2B删除时，从本地row轮询起点提名至多1项，并直接写入优先空闲way。
各bank row指针每周期固定前进一步。不同bank之间不存在候选compact、重排或共享
写入仲裁；每bank每周期最多写一个候选槽。未进入候选缓冲的READY entry继续保存在
Issue Table状态表中。candidate_present只覆盖8个本地候选槽；提名时置位，D2B删除时清位。

3.4 Per-FE State

shortlist是D2A内部组合可见集合，不保存为状态，不改变Issue Entry状态或
candidate_present。D2A0对每个bank的两个本地候选屏蔽pending grant，并按
candidate_way_rr_ptr执行固定2选1；每bank最多贡献一个shortlist项。未匹配项仍保留
在本地候选槽，candidate_way_rr_ptr每周期翻转以避免固定way队头长期阻塞。

四个FE的相对未来返回表在模块内部扁平为24项，索引为{fe_id, slot[0..5]}。Scheduler
为每个FE保存一组D2A1 pending grant：

  grant_valid
  grant_seq_tag[5:0]
  grant_candidate_id[2:0]
  grant_delay[1:0]

Issue table为每个FE保存一组D2B到D3 selected-metadata流水寄存器：

  selected_valid
  selected_seq_tag[5:0]

ppe_fe_scheduler保存每FE相对返回表：

  future_valid[FE_NUM][0..5]
  future_seq_tag[FE_NUM][0..5][5:0]

grant寄存器是D2A到D2B的控制流水；selected-metadata寄存器是D2B到D3的控制流水。
D2B将寄存的grant_candidate_id解码为grant_candidate_onehot送回Issue Table，Issue Table从对应有效候选槽取得完整tag，
再从tag低位临时派生issue entry索引。候选槽one-hot不得作为报文身份用于ROB或依赖查询。
D3在每个周期消费当前valid issue bundle
并通过G0读取权威依赖数据。合法选择不可撤销，依赖bundle的权威data_valid必须成立；
D2B允许在D3消费当前bundle的同一上升沿为该FE写入下一selected tag，不因当前bundle
存在而产生隔周期气泡。

沿前future slot0表示本上升沿返回，slot1..5表示随后1..5个上升沿。每个非复位沿先
消费slot0并向低位移位；本沿D2B提交的grant在沿后写slot[delay+1]。D2A1检查新grant时，
delay 0..2分别检查沿前future slot3..5，并把当前pending grant的slot[delay+2]作为
虚拟占用；delay 3目标超出沿前已存在预约最远一沿，天然为空。只有valid位参与空闲
判断，seq_tag在valid=0时不要求清零。返回时ROB写地址从完整tag低位临时派生。

3.5 FE Arbitration State

  candidate_way_rr_ptr[0..3]
  fe_rr_ptr[1:0]

每个candidate_way_rr_ptr指向对应bank下一周期优先观察的本地way，并且每周期翻转；
fe_rr_ptr指向下一次归一化FE lane零对应的物理FE，存在任意成功分配后推进一位。

若D2A在cycle n捕获grant，D2B在cycle n+1提交select和返回预约，所选请求将在
cycle n+2由D3送入FE。delay=d的目标返回沿为cycle n+d+3。D2A在cycle n沿前检查
future slot[d+3]；同周期尚未写入future表的grant_q位于概念slot[delay+2]，必须
一并检查。D2B沿后把grant_q写入slot[delay+1]，
其后每沿移位，恰在目标返回沿前位于slot0。

3.6 Dependency Control State

Scheduler不保存非权威依赖数据副本，也不保存fallback或replay状态。Completion并行
比较32项窄target tag；依赖满足由ISSUE_WAIT_DEP/ISSUE_READY唯一表达。128 bit结果始终
由backend active ROB或retired history拥有。

================================================================================
4. Backend内部数据结构
================================================================================

4.1 ROB Entry

ROB深度为32，每个entry至少包含：

  valid
  seq_tag generation
  result_valid / done
  fe_out_data[127:0]

fe_out_data同时作为最终输出数据和依赖结果，不保存两份128 bit数据。

物理实现将entry metadata与128 bit result data分离。Result data按ROB ID低2位组织为：

  result_bank = rob_id[1:0]
  result_row  = rob_id[4:2]
  result_data[4][8][127:0]

该banking只改变内部连线和选择结构，不改变以完整seq_tag低5位定义的ROB物理索引。
基线SEQ_W=6且ROB_ID_W=5，entry物理索引已经隐含完整seq_tag低5位，因此metadata只
保存seq_tag[5] generation。访问时以请求tag低5位选择entry，并比较保存的generation
与请求tag[5]；退休tag按{generation, rob_id}重构。该压缩物理编码与完整6 bit tag
比较语义等价，禁止只比较ROB ID。
Active dependency读取仍支持每周期最多4路任意ROB ID；同周期最多4路writeback ID互异，
但允许落入相同result bank，因此每个entry必须保留独立写使能，不能引入bank冲突停顿。
Allocation packet先按rob_id低2位捕获到4组A1 bank-local寄存器。密集allocation tag保证
同一批次每个bank最多命中一次；A1下一沿按row写统一data阵列。A1只延迟宽packet写入，
valid、seq_tag和result_valid仍在A0 allocation沿更新。

4.2 ROB Global State

  head_ptr[4:0]
  occupancy[5:0]

  free_count = ROB_DEPTH - occupancy

head_ptr按32自然回绕。Allocation物理索引由alloc_seq_tag低位直接产生，不保存tail_ptr。
occupancy范围为0..32。Allocation只使用沿前free_count，不组合借用本周期retire_count；
退休释放的credit在下一周期由更新后的occupancy反映。

4.3 Retired History Bank

共8个bank。每个bank保存：

  valid
  seq_tag[5:3]
  result_data[127:0]

bank编号直接等于seq_tag[2:0]。不保存独立seq_residue字段；bank命中必须同时检查
valid和保存的seq_tag高3位，低3位由被访问bank隐含。二者合并等价于完整seq_tag比较。

4.4 Retire Output State

  start_lane[1:0]
  out_valid[N]
  out_packet[N][127:0]

所有out_valid/out_packet必须由寄存器驱动。

5. 模块间逻辑接口
================================================================================

5.0 Top输入寄存边界与寄存反压

ppe_top将原始顶层packed in_valid、in_packet和in_desc只连接到ppe_ingress输入
捕获端口。其他PPE子模块不得读取这些原始端口。ppe_ingress的bkps_o由bkps_q寄存器
直接驱动，不得由FIFO占用、ROB状态、retire前缀或当前in_valid组合赋值。

Top外部lane端口直接使用packed array：

  in_valid_i[N]
  in_packet_i[N][127:0]
  in_desc_i[N][4:0]
  bkps_o

5.1 Ingress -> ROB/Issue Table：Registered-Head Allocation

Ingress对FIFO寄存head保持原始lane索引，不对128 bit packet做物理压缩。送往ROB的
request接口为：

  alloc_req_valid_o[N]
  alloc_seq_tag_o[N][SEQ_W-1:0]
  alloc_packet_o[N][127:0]
  alloc_ready_i

alloc_req_valid是FIFO head保存的lane-valid向量，不受alloc_ready门控；backend据此统计
寄存请求批次大小并组合返回alloc_ready。ROB内部定义：

  alloc_fire = alloc_req_valid & {N{alloc_ready}}

并只对alloc_fire更新entry metadata并捕获bank-local原始packet，不需要由ingress把
accepted valid绕回ROB。原始packet在下一A1沿写入统一data阵列。送往Issue Table的
accepted allocation接口为：

  issue_alloc_valid_o[N]
  alloc_seq_tag_o[N][SEQ_W-1:0]
  alloc_target_seq_tag_o[N][SEQ_W-1:0]
  alloc_delay_o[N][1:0]
  alloc_dep_required_o[N]

其中：

  issue_alloc_valid = alloc_req_valid & {N{alloc_ready}}

Issue Table只接收issue_alloc_valid。Ingress在
|alloc_req_valid && alloc_ready时弹出FIFO head并推进next_seq_tag。Issue table和backend
分别从alloc_seq_tag低位派生本地entry索引。不存在allocation ROB ID请求/响应或独立residue接口。
完整desc不跨越ingress边界：desc[1:0]解码为alloc_delay，desc[4:2]是否非零解码为
alloc_dep_required；实际依赖距离已经体现在alloc_target_seq_tag中。

5.2 Allocation Physical Index

完整alloc_seq_tag是allocation的唯一跨模块身份。Issue table和backend在模块内部独立
派生：

  alloc_rob_id = alloc_seq_tag[ROB_ID_W-1:0]

该低位切片只作为本地数组索引，不形成端口或持久metadata字段。基线ROB_DEPTH=32且
seq tag密集分配，因此无需backend向issue table返回allocation ID或accept响应。采用此
映射时要求ISSUE_DEPTH=ROB_DEPTH=2^ROB_ID_W；非2次幂ROB必须先重新定义物理索引规则。

5.3 Issue Table <-> Backend：Dependency Resolve

D0为最多N个新allocation发出小位宽状态请求：

  dep_status_valid[N]
  dep_status_target_seq_tag[N][SEQ_W-1:0]
  dep_status_available[N]

D3为最多ISSUE_WIDTH个已选依赖报文发出数据请求：

  dep_gather_valid[ISSUE_WIDTH]
  dep_gather_target_seq_tag[ISSUE_WIDTH][SEQ_W-1:0]
  dep_gather_data_valid[ISSUE_WIDTH]
  dep_gather_data[ISSUE_WIDTH][127:0]

Backend组合解析每路请求，active ROB和history索引均由target seq tag低位内部派生，
不跨模块传递target ROB ID或residue。D0只使用available；D3使用data_valid和data。
正常状态下ISSUE_SELECTED且dep_required的D3查询必须data_valid，否则属于内部一致性错误，不通过
fallback/replay恢复。

请求无效时响应定义为：

  - dep_status_valid=0时，dep_status_available必须为0；
  - dep_gather_valid=0时，dep_gather_data_valid必须为0；
  - dep_gather_data_valid=0时，dep_gather_data不作功能要求，实现应赋0以抑制无意义切换。

Issue Table直接管理请求资格、completion wakeup比较和D3响应语义适配，不设置中间
dependency模块或额外流水边界。

5.4 Issue Table <-> FE Scheduler

ppe_issue_table接收D0 accepted allocation bundle：

  issue_alloc_valid[N]
  alloc_seq_tag[N][SEQ_W-1:0]
  alloc_target_seq_tag[N][SEQ_W-1:0]
  alloc_delay[N][1:0]
  alloc_dep_required[N]

Issue Table直接形成D0 status query并接收available：

  dep_status_valid[N]
  dep_status_target_seq_tag[N][SEQ_W-1:0]
  dep_status_available[N]

同时接收completion_valid[FE_NUM]和完整completion_seq_tag[FE_NUM]。Completion并行比较
ISSUE_WAIT_DEP entry的完整target tag，不传递completion ROB ID。

ppe_issue_table拥有READY发现、candidate_present和4组两项本地候选缓冲。候选接口维度使用
独立参数CAND_WINDOW_DEPTH，不借用输入lane数量N：

  candidate_valid[CAND_WINDOW_DEPTH]
  candidate_seq_tag[CAND_WINDOW_DEPTH][SEQ_W-1:0]
  candidate_delay[CAND_WINDOW_DEPTH][1:0]

首版CAND_WINDOW_DEPTH=8。每个candidate_valid对应的entry必须处于
ISSUE_READY；ISSUE_FREE、ISSUE_WAIT_DEP和ISSUE_SELECTED entry禁止出现在候选窗口。
候选接口不携带packet或target tag。

ppe_fe_scheduler接口为：

  clk
  rst_n

  candidate_valid[CAND_WINDOW_DEPTH]
  candidate_seq_tag[CAND_WINDOW_DEPTH][SEQ_W-1:0]
  candidate_delay[CAND_WINDOW_DEPTH][1:0]
  fe_out_valid[FE_NUM]

  select_valid[FE_NUM]
  select_candidate_onehot[FE_NUM][CAND_WINDOW_DEPTH]
  completion_valid[FE_NUM]
  completion_seq_tag[FE_NUM][SEQ_W-1:0]

ppe_fe_scheduler先从每bank两项candidate中提取至多1项形成4项shortlist，再由静态4x4网络生成grant，
不将legal matrix、RR起点或返回表暴露为端口。D2A1结果写入内部grant寄存器；D2B
下一周期把寄存候选槽one-hot作为select原子输出给Issue Table，并把grant写入future表。
不存在外部reserve握手或ready。模块内部保存candidate_way_rr_ptr、fe_rr_ptr、grant、
future_valid和future_seq_tag，不保存shortlist、issue entry、READY队列、packet或
dependency data。

D2A0将槽bank和槽4+bank视为该bank的两个本地way，屏蔽grant占用槽后执行固定2选1。
candidate_way_rr_ptr逐周期翻转本地way优先级；shortlist槽号固定等于bank号。
不做8项compact、全宽旋转、动态数组索引或跨8项前缀rank。FE轮转起点仅在产生grant后推进。
D2A1为每个shortlist候选使用错位FE起点并行提名；同一FE按shortlist顺序接受至多
一个提名。全合法矩阵必须形成
4项唯一配对。算法不承诺任意稀疏合法矩阵下的最大基数，但candidate和FE轮转不得形成
永久饥饿。grant保存完整tag和delay供D2B返回预约，不把tag回送Issue Table。

select_valid[fe]=1表示上一周期D2A1已完成不可撤销匹配，且该沿对应FE返回槽预约成功。
Issue table在该沿按select_candidate_onehot读取本地候选槽，将entry锁定为ISSUE_SELECTED
并保存per-FE selected metadata；选择不得取消或rollback。下一
周期直接形成按FE编号排列的D3 metadata bundle：

  issue_valid[FE_NUM]
  issue_seq_tag[FE_NUM][SEQ_W-1:0]
  issue_delay[FE_NUM][1:0]
  issue_dep_required[FE_NUM]
  issue_target_seq_tag[FE_NUM][SEQ_W-1:0]

issue_valid=0时其余issue bundle字段输出0。合法选择在下一周期必然进入FE；Issue table
在该FE接收沿自动将对应旧entry转为ISSUE_FREE，不需要外部再次回送物理ID或commit。
同一沿允许ppe_fe_scheduler为该FE锁存下一项选择，从而保持逐周期发射。接口没有ready。

Issue Table仅对issue_valid且issue_dep_required的bundle形成ROB gather请求，同时以
issue_valid和issue_seq_tag形成ROB source packet请求。合法source read和依赖issue的
gather data_valid必须为1，但它们不参与issue_valid或entry释放条件。下游生成：

  fe_dep_valid = issue_valid && issue_dep_required

不设置独立issue_dep_valid端口。

5.5 Scheduler -> FE

每个FE使用一组独立命名端口：

  fe_in_valid0..3
  fe_in_data0..3[127:0]
  fe_dep_valid0..3
  fe_dep_data0..3[127:0]
  fe_desc_delay0..3[1:0]

每个FE每周期最多接受一路fe_in_valid。delay=d的请求固定在接收后的第d+1周期返回。
接口没有ready；scheduler必须通过6项相对未来表保证同一FE的所有在途请求目标输出周期
互不冲突。FE返回同周期允许接收新的无冲突请求。

5.6 FE/Scheduler Tag -> Backend Writeback

ppe_fe_scheduler接收fe_out_valid，并以每个FE的future slot0进行关联：

  completion_valid[FE_NUM]
  completion_seq_tag[FE_NUM][SEQ_W-1:0]

合法状态下：

  completion_valid[fe] = fe_out_valid[fe] && future_valid[fe][0]
  completion_seq_tag[fe] = future_seq_tag[fe][0]

completion valid/tag同时送Issue Table执行wakeup并送backend执行writeback。每个FE到
backend的数据接口为：

  wb_valid0..3
  wb_seq_tag0..3[5:0]
  wb_data0..3[127:0]

其中wb_valid/wb_seq_tag直接使用对应completion事件，wb_data直接来自FE，不经过
ppe_fe_scheduler。Backend内部以wb_seq_tag低ROB_ID_W位生成本地写地址。

5.7 ROB -> Retire Output -> Top

ppe_rob向ppe_retire_output提供：

  retire_valid[N]
  retire_data[N][127:0]

ppe_rob不输出物理lane编号或start_lane。ppe_retire_output不向ppe_rob返回ready、accept
或其他流控信号。

对外接口分别由对应状态所有者驱动：

  ppe_ingress       -> bkps
  ppe_retire_output -> out_valid[N]
  ppe_retire_output -> out_packet[N][127:0]

5.8 Top -> PPE子模块/FE：Internal Reset

ppe_top使用外部rst_n实现唯一的两级复位同步器，生成internal_rst_n。
internal_rst_n异步拉低、同步释放，并作为ingress、scheduler、ppe_rob、
ppe_retire_output和四个FE
的共享低有效复位。各子模块不得再次同步复位或产生独立释放时序。

================================================================================
6. Ingress I0/D0：输入捕获、缓冲与分配
================================================================================

6.1 I0 Two-slot Elastic Input Capture

在上升沿且bkps_q=0时，ingress将全部lane的in_valid、in_packet和in_desc无条件写入
slot_wr_ptr选择的寄存槽位，同时推进写指针和占用计数。原始输入不参与任何其他状态
更新。两项槽位本身构成有序FIFO，不存在capture到FIFO的第二次宽数据搬移。下一周期
仅根据寄存head lane-valid判断：空批直接释放；非空批在alloc_ready时完成allocation
并释放。tail capture与head release允许同沿发生。

6.2 D0 Registered-Head Rank

对于lane i：

  lane_rank[i] = elastic FIFO head中lane编号小于i且valid=1的lane数量

固定N=4基线使用静态平衡网络，不以循环累加器形成串行依赖：

  lower_pair_count = valid[0] + valid[1]
  upper_pair_count = valid[2] + valid[3]
  lane_rank[0] = 0
  lane_rank[1] = valid[0]
  lane_rank[2] = lower_pair_count
  lane_rank[3] = lower_pair_count + valid[2]
  head_packet_count = lower_pair_count + upper_pair_count

对非空FIFO head：

  seq_tag[i]        = next_seq_tag + lane_rank[i]
  alloc_req_valid[i] = slot_lane_valid[slot_rd_ptr][i]
  issue_alloc_valid[i] = alloc_req_valid[i] && alloc_ready

当alloc_ready=0或internal_rst_n=0时，所有issue_alloc_valid和ROB内部alloc_fire必须为0，
Issue Table和ROB均不写新entry；FIFO head及next_seq_tag保持。

seq_tag使用固定位宽自然回绕。Ingress不读取ROB指针，也不产生rob_id或residue输出；
backend和issue table之间不存在ROB ID通路。

6.3 Dependency Input Contract

输入协议保证非零dep_offset不大于本次复位后排在当前报文之前的报文数量，其中包括
同周期lane编号更小且同时被接收的报文。Ingress不保存历史计数器，不检测或修改
非法dep_offset。desc_delay始终保持FIFO head中已寄存desc[1:0]不变。

6.4 Dependency Target Precompute

若dep_offset=K且K不为0：

  target_seq_tag = seq_tag - K mod 64

密集seq分配建立并必须保持以下不变量：

  rob_id         = seq_tag[4:0]
  target_rob_id  = target_seq_tag[4:0]
  history_bank   = target_seq_tag[2:0]

ROB和history索引均由完整tag低位组合派生，不作为ingress输出或entry存储字段。

6.5 D0 Allocation Update

|alloc_req_valid && alloc_ready的内部allocation沿同时完成：

  - Issue Table使用alloc_seq_tag低位和ingress metadata写entry；
  - backend使用内部alloc_fire和alloc_seq_tag写ROB；
  - ingress释放elastic FIFO head并按有效lane数量推进next_seq_tag。

外部输入被I0捕获后至少经过一个寄存边界才能进行D0 allocation，不允许组合直通
sequence allocation、ROB、Issue Table、FE或任何顶层输出。

================================================================================
7. Scheduler依赖初始化与事件唤醒
================================================================================

7.1 D0 New Entry Initialization

  dep_offset=0：dep_required <- 0, state <- ISSUE_READY

  dep_offset!=0：向G0发送完整target_seq_tag。G0内部派生target ROB/history索引，并按
  completion bypass、retirement bypass、active ROB和retired history顺序返回ready。
  ready时dep_required <- 1, state <- ISSUE_READY；否则
  dep_required <- 1, state <- ISSUE_WAIT_DEP。该组合状态查询不进入
  bkps路径，不返回或复制128 bit依赖数据。

7.2 Reverse Waiter Wakeup

Completion tag为S时，并行检查32项issue entry。仅当entry处于ISSUE_WAIT_DEP且完整
target_seq_tag等于S时，在本沿把entry状态置为ISSUE_READY。该路径不得读取或选择
packet宽数据，也不保存producer到consumer的反向表。

READY bank提名只读取沿前issue_state，不组合读取completion wake hit。因此被唤醒entry
最早下一周期写入本地候选槽，再由后续D2A选择。

7.3 Simultaneous Initialization and Completion

D0初始化的completion bypass与ISSUE_WAIT_DEP wakeup使用相同的完整tag比较。本周期
新分配entry若目标在同周期completion中命中，则沿后直接进入ISSUE_READY；该entry仍最早从
下一周期参与D2A。若目标active ROB entry存在但result_valid=0且无completion bypass，
G0必须返回not ready，禁止继续使用history。

Completion wakeup在issue_state边界终止，不组合进入候选提名。同周期completion bypass
命中的新allocation直接进入ISSUE_READY。Allocation状态初始化具有最终优先权；完整tag
防止旧身份事件误唤醒。

================================================================================
8. Scheduler D2A/D2B：报文与FE仲裁及预约提交
================================================================================

8.1 READY Discovery and Admission

ISSUE_READY且candidate_present=0的entry可被发现。发现逻辑只使用沿前Issue Entry状态；
D0新allocation和本周期completion wakeup均在本沿更新状态，最早下一周期参与发现。
entry按ROB ID低2位进入4个交错bank，每bank从8个row中轮询提名至多1项。

每bank候选槽固定为bank和4+bank。若至少一个槽沿前无效或本周期被D2B删除，则该bank
允许一次提名；优先写入被删除或无效的way0，否则写way1。提名entry在本沿置
candidate_present。D2B删除和本地提名可以同沿发生，但被删除的旧entry仍由沿前
candidate_present屏蔽，不能被立即重新提名。ISSUE_WAIT_DEP不得进入候选缓冲。
候选接口只读取候选寄存器，不提供组合提名旁路。

8.2 D2A0 Per-bank Two-way Shortlist

8个candidate槽按way组织：槽0..3为四个bank的way0，槽4..7为对应bank的way1。
D2A0先屏蔽grant仍占用的槽，再由每个bank的candidate_way_rr_ptr在两个way间执行
固定2选1，形成最多4项shortlist。shortlist槽号固定等于bank号，同一bank每周期最多
贡献一个候选。若优先way不可用则选择另一way；两者均不可用时该bank shortlist无效。
完整tag和delay仅由本地2选1取得。shortlist不改变Issue Entry状态或
candidate_present，未匹配项保持在原候选槽。

8.3 D2A1 Legal Matrix and Fixed Match

shortlist候选c与FE f的合法条件为：

  delay=0: legal[c][f] = !future_valid[f][3]
  delay=1: legal[c][f] = !future_valid[f][4]
  delay=2: legal[c][f] = !future_valid[f][5]
  delay=3: legal[c][f] = 1

以上future项还需与当前grant虚拟预约比较：grant delay 1/2/3分别占用新请求检查的
slot 3/4/5。delay 3的新请求目标晚于所有沿前预约，不需要第7个future槽。

shortlist c从fe_rr_ptr+c开始按环形FE顺序提名第一个legal FE，使全合法矩阵自然分散
到4个FE；同一FE冲突时按shortlist编号接受一个候选。不允许动态数组索引或跨候选
greedy链。一个候选和一个FE在本周期均最多使用一次。存在grant
时fe_rr_ptr推进一位。

8.4 FE Selection and Return Reservation

一个FE每周期最多接收一个D2A1分配。D2A1成功后pending grant不可撤销；下一周期D2B：

  - Issue table保存该FE的selected valid和完整seq_tag；
  - future table在本沿写入slot[delay+1]；
  - issue entry进入ISSUE_SELECTED。

若某候选无法匹配任何FE，则保持ISSUE_READY并等待后续周期，不得因其他候选成功而丢失。
一旦D2A1 pending grant写入，选择不可取消或rollback；ppe_fe_scheduler必须在产生grant前确认
依赖已经满足，并结合future table确认目标FE返回项可用。
D2A1不得将FE存在其他在途请求作为不可用条件。

8.5 Candidate and RR Update

D2B直接合并候选槽one-hot生成删除mask，并从所选槽完整tag清candidate_present。
每个bank独立判断两个本地槽的无效/删除状态，并写入至多一个新提名；不同bank之间
没有空槽compact或候选搬移。未删除候选保持原槽。候选slot直接读取自身寄存
valid/tag/delay，不动态读取issue entry。若同址issue entry在该沿又被D0重新分配，
D0状态初始化具有最终优先级。


================================================================================
9. Scheduler D3：Operand Read与FE Issue
================================================================================

对每个issue_valid=1的FE：

  - Issue table直接使用D2B沿寄存的seq tag、delay、dep_required和target seq tag；
  - ROB以issue seq tag读取原始packet；该entry的result_valid此时必须为0；
  - dep_required=0时输出fe_dep_valid=0、fe_dep_data=0；
  - dep_required=1时向G0发送完整target_seq_tag；
  - G0按completion bypass、retirement bypass、active ROB、retired history顺序解析；
  - 将packet、dependency和delay路由到目标FE；有依赖时gather data_valid必须为1；
  - 拉高对应FE的fe_in_valid一个周期。

正常请求在FE接收沿：

  - issue entry转为ISSUE_FREE；
  - 保留D2B已经写入的future预约；
  - 当前selected tag被同周期D2B结果替换，若无新选择则清除selected_valid。

D3 source请求满足同周期有效seq_tag低2位互异，因为D2A每个READY bank最多选择一项。
ROB先按低2位把最多4个请求分配到4个data bank，每个bank只执行一次8:1 row读取，再将
结果按原FE编号路由回issue bundle。该共享不改变FE编号接口或source data_valid语义。
依赖target不继承该互异约束，多个target仍可命中同一data bank的不同row。

D3正常路径包含bank-local ROB source packet mux、最多4路active ROB/history 128 bit读取、两级bypass
比较/选择和FE数据路由，是首版重点关注的宽数据路径。依赖entry进入ISSUE_SELECTED后，
其目标结果不会失效：目标退休前由active ROB提供，退休沿由retirement bypass提供，
退休后由history提供。若dep_gather_data_valid=0，属于内部一致性错误；验证侧必须报错，
该情况属于验证必须捕获的内部一致性错误，设计不设置可综合rollback、fallback或replay状态。

================================================================================
10. Backend A0/A1：ROB Allocation
================================================================================

对于本周期每个内部alloc_fire：

  alloc_rob_id = alloc_seq_tag[ROB_ID_W-1:0]
  rob[alloc_rob_id].valid          <- 1
  rob[alloc_rob_id].seq_generation <- alloc_seq_tag[SEQ_W-1:ROB_ID_W]
  rob[alloc_rob_id].result_valid   <- 0
  alloc_data_bank[alloc_rob_id[1:0]] <- {
      valid = 1,
      row   = alloc_rob_id[4:2],
      data  = alloc_packet
  }

A1在下一上升沿将各有效alloc_data_bank写入对应统一data槽。A0到最早D3之间已有
D1、D2A和D2B边界，因此A1不增加报文发射延迟。W0随后以处理结果原址覆盖同一data槽并
置result_valid。无效entry的
数据内容不要求清零。alloc_fire只由ROB本地alloc_req_valid和alloc_ready生成，不设置
alloc_valid输入端口。

D3 source读取使用issue_seq_tag低位索引。仅当ROB valid、完整tag匹配且result_valid=0时
返回source_data_valid和原始packet；此条件区分原始packet与已经覆盖的结果，不允许把
完成结果误作FE输入。物理比较使用低位索引隐含部分与entry保存的tag高位，语义仍为
完整tag匹配。

================================================================================
11. Backend G0：依赖状态与数据解析
================================================================================

11.1 Common Resolve Rule

给定target_seq_tag，先在backend内部派生：

  target_rob_id = target_seq_tag[ROB_ID_W-1:0]
  history_bank  = target_seq_tag[2:0]

然后每路请求按以下顺序解析：

  1) 若任一wb_commit的完整seq_tag匹配：
       satisfied = 1, source = COMPLETION_BYPASS, data = wb_data
  2) 否则若任一retire entry的完整seq_tag匹配：
       satisfied = 1, source = RETIREMENT_BYPASS, data = 沿前rob_data
  3) 否则若rob[target_rob_id].valid且完整seq_tag匹配：
       result_valid=1时satisfied = 1, source = ACTIVE_ROB；
       result_valid=0时satisfied = 0，并立即停止，禁止查询history
  4) 否则以target_seq_tag[2:0]索引history：
       history.valid且完整seq_tag匹配时satisfied = 1, source = HISTORY；
       否则satisfied = 0

完整seq_tag匹配是必需条件，ROB ID或history bank低3位单独匹配不得视为命中。
物理实现中ROB和history分别只保存未被entry/bank索引隐含的tag高位；索引低位与保存
高位共同构成上述完整tag检查。
查询采样沿前，retire entry仍保持active valid、完整tag和result data，因此第2、3级
在物理实现中共用active ROB命中与数据，不重复生成retire head比较；该折叠不改变上述
优先级或沿上可见结果。

11.2 Query Width

D0每周期最多提交N路status query，只返回dep_status_available，不要求切换128 bit数据。
D3每周期最多提交ISSUE_WIDTH路data query，每路返回dep_gather_data_valid和128 bit
data。同一target被多路
请求命中时允许共享一次读取并广播；实现也可描述为等价的独立组合读取。
每个query的target ROB ID、history ID、active完整tag命中和history完整tag命中只生成
一次中间结果，并由available/data选择共同使用。RTL不增加运行时跨query合并器；综合
工具可对相同target请求共享组合读取，独立读取仍是周期语义等价的合法实现。

11.3 Cycle Boundary Rules

Completion bypass可以使D0新entry或ISSUE_WAIT_DEP entry在W0写ROB的同一沿得到available状态，
但该entry最早下一周期参加D2A，不允许同沿completion-to-FE直通。Retirement bypass
读取沿前旧ROB数据，并优先于沿后可能复用同一ROB ID的新allocation。上升沿后，目标
改由已更新history命中。该规则不依赖存储体未定义的read-during-write行为。

================================================================================
12. Backend W0：FE Writeback
================================================================================

每个wb_valid先计算轻量写保护：

  wb_rob_id = wb_seq_tag[ROB_ID_W-1:0]
  wb_commit = wb_valid
           && rob[wb_rob_id].valid
           && rob[wb_rob_id].seq_tag == wb_seq_tag
           && !rob[wb_rob_id].result_valid

仅当wb_commit=1时执行：

  rob[wb_rob_id].data         <- wb_data
  rob[wb_rob_id].result_valid <- 1

同周期最多4个有效writeback seq tag的低ROB_ID_W位必须互不相同。验证侧必须用SystemVerilog assertion
检查FE返回与当前日历槽valid一致、ROB valid、完整tag、未重复完成和同周期ID互异。
任何检查失败都是
验证错误，不设置可综合sticky异常状态，不参与bkps、派发或退休控制。

W0必须捕获全部符合协议的有效FE返回，不允许通过ready反压FE。首版物理实现必须支持
4路任意地址并发写回，不能使用单写端口存储后串行处理。

四路wb_seq_tag低5位先产生共享entry decode。对每个entry：

  wb_entry_commit[entry][f] = wb_valid[f]
                             && wb_rob_id[f] == entry
                             && rob_valid[entry]
                             && rob_seq_generation[entry]
                                == wb_seq_tag[f][SEQ_W-1:ROB_ID_W]
                             && !rob_result_valid[entry]
  wb_entry_write_en[entry] = OR_f wb_entry_commit[entry][f]

协议保证同一entry最多命中一路，因此entry-local固定4选1数据选择没有仲裁语义。每个
128 bit data entry只在allocation或wb_entry_write_en有效时更新；metadata与data使用不同
时序过程，但每个状态元素仍只有一个owner。

entry地址比较隐含wb_seq_tag低5位，generation比较覆盖其余高位，因此上述资格检查
等价于完整seq_tag匹配。每个wb_commit同时形成completion bypass和scheduler wakeup事件，但不写retired
history。事件携带valid、完整seq_tag和128 bit data；本地ROB ID从tag低位派生，wakeup
只使用小位宽字段。

在cycle n上升沿，wb关联信息读取：

  wb_valid   = fe_out_valid && future_valid[fe_id][0]
  wb_seq_tag = future_seq_tag[fe_id][0]

该沿消费slot0并将future表向低位移位。合法协议下fe_out_valid必须与slot0 valid相等。
FE返回、D3发射、D2B select和下一批D2A1 grant捕获允许同沿发生；D2B新预约写入沿后
slot1..4，不会与本周期slot0消费冲突。

================================================================================
13. Backend R0：保序退休与输出
================================================================================

13.1 Consecutive DONE Scan

从head_ptr开始检查最多4项：

  done0 = rob[head+0].valid && rob[head+0].result_valid
  done1 = done0 && rob[head+1].valid && rob[head+1].result_valid
  done2 = done1 && rob[head+2].valid && rob[head+2].result_valid
  done3 = done2 && rob[head+3].valid && rob[head+3].result_valid

  retire_count = done0 + done1 + done2 + done3

所有ROB索引按32自然回绕。

13.2 ROB Logical Retirement Bundle

ppe_rob输出按报文序排列的逻辑退休bundle：

  retire_valid[N]
  retire_data[N][127:0]

retire_valid从slot 0开始连续有效，不得留洞；slot j对应head+j的沿前ROB结果。
该bundle为组合退休事件，供ppe_retire_output在同一上升沿捕获，不使用ready或反压。

固定4-bank result实现对物理bank b读取：

  row[b] = head_ptr[4:2] + (b < head_ptr[1:0])

3 bit row加法自然按8回绕。这样四个bank各执行一次8:1选择，得到连续退休窗口中的四个
数据，再由head_ptr[1:0]控制的rotate-by-1/rotate-by-2固定网络恢复slot 0..3逻辑顺序。
Metadata DONE scan仍按head+j检查，数据置换不得改变dense-prefix valid。

13.3 Retirement Register Update

退休沿在ppe_rob内同时执行：

  - 对每个退休报文写history[rob_seq_tag[2:0]]，保存完整seq_tag和result_data；
  - 清除对应ROB valid/result_valid；
  - head_ptr推进retire_count；
  - occupancy减retire_count并合并同周期allocation数量。

同一退休沿在ppe_retire_output内同时执行：

  - 先将全4路out_valid的next value默认为0，再按start_lane映射K个退休slot；
  - 仅更新本周期out_valid=1的out_packet寄存器，其余out_packet保持；
  - start_lane推进retire_count。

第j个逻辑退休slot映射到lane=(start_lane+j) mod 4，使用沿前start_lane。ROB状态
释放、history更新、输出寄存器装载和start_lane更新属于同一架构退休沿，不新增
流水级或跨模块握手。

固定N=4实现使用两级barrel rotate：第一级由start_lane[0]选择旋转0或1，第二级由
start_lane[1]选择继续旋转0或2。valid和128 bit data经过相同的固定连线置换，不使用
变量物理lane索引。retire_valid合法编码仅为0000、0001、0011、0111和1111，retire_count
直接译码为0..4；其他编码属于验证必须捕获的内部协议错误，不设置可综合恢复路径。
out_packet寄存器仍按物理lane使用mapped_valid作为公共clock-enable语义，RTL不手动
例化ICG。

当前N=4时，同周期退休的连续报文映射到不同history bank，不存在同bank多写。
未来N=8时，连续8个报文也分别映射到8个不同bank。

13.4 Writeback Visibility

W0在本周期刚写回的entry不参与同周期R0退休，最早下一周期被DONE scan看到。

================================================================================
14. 全局反压
================================================================================

Backend只对FIFO寄存head计算内部allocation ready：

  request_count   = popcount(alloc_req_valid[3:0])
  free_count      = ROB_DEPTH - occupancy
  alloc_ready     = (request_count != 0) && (free_count >= request_count)

free_count使用本周期沿前注册状态，当前retirement prefix释放的空间从下一周期开始可用。
这避免retirement scan进入allocation ready和metadata写路径。ROB首次从满载状态释放时
可能保守停顿一次；此后只要退休持续提供credit，retire与allocate仍可每周期并行。

Ingress以两项elastic FIFO吸收寄存反压延迟。定义：

  capture_batch   = !bkps_q
  head_nonempty   = |alloc_req_valid
  allocation_batch = (slot_count != 0) && head_nonempty && alloc_ready
  head_release    = (slot_count != 0) && (!head_nonempty || alloc_ready)

沿后占用按capture与head release统一更新：

  {capture_batch, head_release} = 2'b10：slot_count_d = slot_count_q + 1
  {capture_batch, head_release} = 2'b01：slot_count_d = slot_count_q - 1
  其余组合：slot_count_d = slot_count_q

  bkps_d = (slot_count_d == 2)
  bkps_o = bkps_q

以上逻辑不读取任何当前原始输入。bkps_q=0时，本沿无条件捕获一个内容尚未知的完整
外部批次；若实际捕获为空批，下一周期根据寄存head lane-valid释放。bkps_q=1时不捕获，
当full FIFO的head释放后slot_count_d降为1，bkps在该沿后重新拉低。由于bkps是寄存反馈，
从一项占用到捕获第二项的沿已经预留了完整空槽，不会溢出或部分接收。

FIFO宽数据阵列使用两个显式bank-local写使能：

  slot_bank0_write = capture_batch && !slot_wr_ptr
  slot_bank1_write = capture_batch &&  slot_wr_ptr

每个bank仅由其本地使能更新packet、descriptor和lane-valid；write pointer只在
capture_batch时翻转。不得用动态bank索引形成覆盖全部宽存储的单一写使能mux，也不得
让原始lane-valid参与bank写使能。

复位期间bkps_q置1，slot_count和读写指针清零。复位释放后bkps只能在时钟沿拉低。
原始in_valid不得参与alloc_ready、bkps_d或任何其他功能组合逻辑。

ROB_DEPTH=32且issue table以seq_tag低位索引。ROB entry能够退休意味着对应issue entry
此前已经派发并释放，因此backend释放的物理槽在同沿也可由相同低位的新allocation复用。

================================================================================
15. 同周期并发更新
================================================================================

A0、G0、W0和R0允许同周期作用于不同entry。W0不写history；R0是history唯一写入
通路。G0的completion和retirement bypass读取本周期事件数据，不写任何权威存储。

必须满足：

  - 新allocation entry允许与本周期退休entry重叠，且仅能复用退休前缀释放的entry；
  - 重叠entry的退休输出、retirement bypass和history写入读取沿前旧内容，allocation
    对沿后ROB valid、seq_tag和result_valid具有最终优先权；
  - allocation原始packet由A0按bank捕获并在A1提交；A1目标entry在正常流水下不可能
    同周期收到writeback，RTL仍以A1 packet写作为同址最终优先级；
  - 新writeback entry不在同周期退休；
  - 已DONE退休entry不再次收到writeback；
  - 同周期4路writeback ID互不相同；
  - 同周期allocation和retirement数量统一合并更新occupancy；
  - ROB valid、result_valid、head和occupancy只有ppe_rob一个时序状态所有者；
  - start_lane和out_valid/out_packet只有ppe_retire_output一个时序状态所有者。

必须按统一next-state计算：

  occupancy_next = occupancy + alloc_count - retire_count

valid/result_valid数组在同一个时序always block中按writeback、retire、allocation
顺序更新，使同址allocation最后赋值。退休数据选择仍由沿前数组组合产生，不受同沿
allocation非阻塞赋值影响。禁止多个always block驱动同一状态。

================================================================================
16. 复位
================================================================================

ppe_top是复位同步器的唯一所有者。外部rst_n异步拉低同步器两级寄存器，外部
rst_n拉高后经过两个clk上升沿释放internal_rst_n。PPE全部子模块和FE使用同一个
internal_rst_n。

复位清除：

  - ingress slot_count、读写指针，并将bkps_q置1；
  - issue table unified state；
  - candidate valid、candidate_present、ready_admit_row_rr_ptr、
    candidate_way_rr_ptr和fe_rr_ptr；
  - per-FE selected valid、grant valid和future valid；
  - ROB valid/result_valid/head/occupancy；
  - retired history valid；
  - next_seq_tag；
  - ppe_retire_output中的start_lane和out_valid。

无效状态下不要求清零宽数据数组。复位期间bkps_q=1，所有fe_in_valid和out_valid=0。

================================================================================
18. LLD不变量
================================================================================

  1) 同一issue entry不得被重复选择或重复派发。
  2) selected entry、FE launch和future预约必须成对建立。
  3) 有效future槽的seq_tag在返回前不得被覆盖。
  4) 依赖未满足时不得被select；ISSUE_SELECTED依赖entry的权威gather必须data_valid。
  5) 依赖查询必须完整匹配seq_tag。
  6) FE返回只设置active ROB result并形成completion事件，不直接写retired history。
  7) Active ROB tag命中但result_valid=0时必须等待，禁止继续查询history。
  8) 退休只从ROB head开始并且只退休连续DONE entry。
  9) 输出寄存器装载、ROB释放和history更新属于同一退休事件。
  10) ROB occupancy必须等于有效ROB entry数量。
  11) 无效宽数据内容不影响任何功能判断。
  12) 同一FE的有效future槽唯一对应一个目标返回周期，D2A1不得生成冲突预约，
      D2B不得覆盖有效槽。
  13) 完整seq_tag是唯一跨模块报文身份；allocation、selection、writeback及dependency
      的本地ROB索引必须由对应完整tag低ROB_ID_W位临时导出，不设置ROB ID端口，也不在
      selected pipeline或future table中重复保存ID。Issue Table候选窗按第3.3节保存
      完整seq tag，并仅在entry访问处从低位临时派生物理索引。
  14) candidate_present=1的entry必须处于READY状态并在候选窗中恰好出现一次；
      D2B只能消费有效候选项，等待依赖entry不得进入候选窗。
  15) 原始顶层输入只允许写ingress中slot_wr_ptr所选的elastic FIFO输入槽位；槽位写使能
      不得读取原始输入。bkps_o必须由bkps_q直接驱动，input FIFO在任意合法输入和ROB
      停顿序列下不得溢出、丢批或部分接收。

验证必须覆盖ROB occupancy达到32、ROB物理索引31到0回绕、6 bit seq tag从63到0回绕、
依赖目标跨seq回绕，以及退休释放entry与同沿新allocation复用相同物理索引。
