1. 参数与位宽
================================================================================

  N            = 4
  FE_NUM       = 4
  MAX_DEP      = 7
  ISSUE_WIDTH  = 4
  ROB_DEPTH    = 32
  ROB_ID_W     = 5
  SEQ_W        = 6

  RESULT_BANKS = 8
  PACKET_W     = 128
  DESC_W       = 5

新架构可综合RTL使用SystemVerilog unpacked array表达顶层外部报文端口和模块内部重复
多位lane/FE通路；逻辑索引0固定对应数组元素0，不为固定lane展开独立编号端口。单比特
valid、enable和mask在需要按位运算时仍使用packed vector。其余RTL保持克制的Verilog
风格；状态数组只能由一个明确的时序always进程拥有，纯组合选择器使用always @*并提供
完整默认赋值。

1.1 参数与类型组织

  - ppe_config.vh保存必须跨模块一致的基线配置及公共位宽；配置使用带include guard的
    宏定义，不能在单个子模块例化处独立覆盖。RTL不依赖SystemVerilog package或typedef。
  - ISSUE_DEPTH固定由ROB_DEPTH派生，ISSUE_WIDTH固定由FE_NUM派生，RESULT_BANKS固定由
    MAX_DEP+1派生；ROB_ID_W、SEQ_W和HISTORY_ID_W均由基础配置计算，不重复写数值。
  - CAND_WINDOW_DEPTH、RETURN_FUTURE_DEPTH和READY_ENQUEUE_WIDTH属于跨模块接口或
    调度结构配置，在ppe_config.vh中统一定义，例化处禁止使用裸常数覆盖。
  - PACKET_W和DESC_W直接影响可复用模块端口宽度，允许作为顶层及相关子模块参数；
    当前唯一受支持的系统基线仍为128和5，顶层负责一致传递。
  - 只在单模块内部使用的FIFO深度、计数器宽度和指针加法宽度保留为localparam，不提升
    到共享头文件。
  - 仅用于静态展开循环的过程索引使用integer；参与实际组合数据通路的计数、索引和临时
    算术变量必须使用由配置推导的显式小位宽reg。所有always块使用描述功能的显式标签；
    只有状态所有权可以清晰分离时才拆分时序always，存在同址更新优先级
    的状态数组必须继续由同一个进程拥有。

2.3 典型无依赖报文数据流

  1) I0在bkps允许时把外部输入捕获到两项elastic FIFO的寄存tail槽位；
  2) D0A在寄存credit足够时为FIFO head分配seq并寄存commit bundle，
     同沿ROB提前占用对应容量；
  3) D0B把保证提交的bundle写入ROB entry，并由Scheduler将无依赖报文标记为
     ISSUE_READY；
  4) D1把READY报文写入窄候选槽；
  5) D2A形成4项shortlist，用两个固定2x2网络选择报文和FE并捕获grant；
  6) D2B以grant tag从ROB gather operand并写返回表，D3以寄存operand向FE发出请求；
  7) FE返回，W0按完整seq tag低位写ROB并设置result_valid；
  8) 报文到达ROB head且DONE后，R0将数据装入输出寄存器；
  9) 同一退休沿更新对应retired history bank并释放ROB entry。

2.4 典型依赖等待数据流

  1) I0捕获依赖报文到elastic FIFO，D0A从寄存head分配seq、预计算完整target seq tag
     并取得ROB容量reservation；
  2) D0B提交ROB/Scheduler allocation，写ISSUE_WAIT_DEP并寄存状态探针；
     D0C通过G0查询active ROB/history小位宽
     状态及completion/retirement bypass，available时转ISSUE_READY，否则继续等待；
  3) 目标FE返回时，W0写active ROB并以完整tag唤醒ISSUE_WAIT_DEP entry；
  4) 被唤醒报文最早下一周期进入READY并写入候选槽；
  5) D2A选择候选后，D2B通过G0按固定优先级gather权威依赖数据，随后向FE派发；
  6) gather时目标退休前从active ROB读取，退休后从history读取，
     退休后从history读取。

2.5 典型保序阻塞数据流

  1) 多个FE乱序返回，W0分别写入对应ROB entry；
  2) 后序ROB entry可以先DONE，但R0只检查ROB head开始的连续DONE项；
  3) head未DONE时retire_count=0，后序DONE结果继续保存在ROB；
  4) head完成后的下一周期，R0一次退休最多4个连续DONE报文；
  5) 输出顺序由ROB head确定，与FE完成顺序无关。

2.6 FE固定延迟流水行为

每个FE每周期最多接收一路请求，允许多个请求同时在途，并允许输入和输出在同一周期
发生。请求在cycle n接收且desc_delay=d时，固定在cycle n+d+1返回。行为模型可用
四个未来输出槽表达：

  slot0：下一周期输出
  slot1：下两周期输出
  slot2：下三周期输出
  slot3：下四周期输出

接收请求时将结果预约到slot[d]，每周期输出当前slot0并将slot1..3向低位推进。
同一FE每个未来周期只有一个输出槽；新请求如果与已有在途请求预约同一输出周期，
属于PPE协议违规。FE无ready或重放能力，正常RTL不得产生这种输入。

FE内部数据算法对PPE保持黑盒。仓库行为模型只需与验证VIP保持一致；PPE功能正确性
依赖的是输入数据、依赖数据和delay被正确送达，以及返回周期和请求关联正确。

3. Ingress与Scheduler内部数据结构
================================================================================

3.1 Issue Entry

Issue table深度为32，以ROB ID作为entry索引，主要数据结构为：

  typedef enum logic [1:0] {
      ISSUE_FREE,
      ISSUE_WAIT_DEP,
      ISSUE_READY,
      ISSUE_SELECTED
  } issue_state_e;

  typedef struct packed {
      issue_state_e        state;
      logic [SEQ_W-1:0]    seq_tag;
      logic [SEQ_W-1:0]    target_seq_tag;
      logic [1:0]          delay;
      logic                dep_required;
  } issue_entry_t;

状态与依赖字段必须满足：

  - ISSUE_FREE：entry无效，其余字段不作要求；
  - ISSUE_WAIT_DEP：dep_required=1且依赖尚不可用；
  - ISSUE_READY：无依赖，或dep_required=1且依赖已经可用；
  - ISSUE_SELECTED：已经被PPE_SCHEDULER不可撤销地选中，依赖必定满足。

candidate_present作为独立于issue_entry_t的成员资格账本，表示对应READY entry已经
存在于8项候选窗。未进入候选窗的READY entry直接保留在状态表中，后续周期继续发现。
packet和dependency不在32项Issue Entry或候选槽保存；grant后才读ROB并保存到per-FE
selected候选寄存器，最终dependency mux位于scheduler到FE的内部组合接口。
target ROB ID固定从target_seq_tag低位派生，不单独保存。

3.2 Ingress Input Buffer and Sequence State

Ingress保存两项整批elastic FIFO：

  slot_lane_valid[2][N]
  slot_packet[2][N][127:0]
  slot_desc[2][N][4:0]
  slot_rd_ptr
  slot_wr_ptr
  slot_count[1:0]
  bkps_q

Ingress维护：

  next_seq_tag[5:0]
  alloc_commit_valid[N]
  alloc_commit_seq_tag[N][5:0]
  alloc_commit_target_seq_tag[N][5:0]
  alloc_commit_delay[N][1:0]
  alloc_commit_dep_required[N]
  alloc_commit_slot

外部in_valid/in_packet/in_desc只允许作为slot_wr_ptr所选槽位寄存器的D输入，不得作为
槽位写使能，也不得进入FIFO控制、rank、descriptor decode、ROB容量或bkps next-state
组合逻辑。槽位写使能只由bkps_q和slot_wr_ptr生成。空批只根据head槽位的寄存
lane-valid识别。FIFO head的寄存lane valid、
packet和desc是D0功能处理的唯一输入。宽packet/desc数组在对应slot无效时不要求复位。
next_seq_tag按2^SEQ_W回绕。不保存独立residue计数器或entry字段。commit bundle不复制
128 bit packet，只保存被reservation的FIFO槽位号；D0B提交沿读取该槽的沿前旧packet。
即使同沿外部capture复用该槽，非阻塞更新也保证ROB捕获旧packet。
两个slot各自并行形成窄rank、count、seq、target、delay和dep_required预览，
slot_rd_ptr只选择最终head metadata。FIFO非空时commit metadata寄存器允许预览当前
head；只有alloc_commit_valid表示该预览已经取得reservation并可由D0B提交。

3.3 Ready Queue and Arbitration State

PPE_SCHEDULER维护4组两项本地窄候选缓冲；匹配时每bank组合形成1项shortlist：

  candidate_valid[0..7]
  candidate_seq_tag[0..7][5:0]
  candidate_target_seq_tag[0..7][5:0]
  candidate_delay[0..7][1:0]
  candidate_dep_required[0..7]
  candidate_present[ROB_DEPTH]
  ready_bank_head_row[0..3][2:0]
  candidate_way_rr_ptr[0..3]
  shortlist_valid[0..3]
  shortlist_candidate_onehot[0..3][7:0]
  shortlist_seq_tag[0..3][5:0]
  shortlist_delay[0..3][1:0]
  shortlist_legal[0..3][1:0]
  candidate_pending_block[0..7][2:0]

entry按ROB ID低2位分为4个交错bank，每bank包含8个row和两个固定候选槽。
候选槽bank对应way0，槽4+bank对应way1。每个bank仅在至少一个本地槽沿前无效或
本周期被D2B寄存grant删除时，从ROB提供的本bank最老未退休row开始环形扫描并提名
至多1项，直接写入优先空闲way。8项row以3 bit自然回卷，不保存独立READY扫描指针。
不同bank之间不存在候选compact、重排或共享
写入仲裁；每bank每周期最多写一个候选槽。未进入候选缓冲的READY entry继续保存在
issue状态表中。candidate_present只覆盖8个本地候选槽；提名时置位，D2B消费grant时清位。
candidate_present按已确定的bank和3 bit row局部译码，不从完整ROB ID生成全局动态写索引。
当本bank存在空槽但没有沿前READY winner时，本沿无依赖allocation可直接作为winner，
使用allocation的seq tag和delay写候选。若已有沿前READY winner则其优先，
新allocation只进入ISSUE_READY，避免持续输入饿死旧entry。依赖allocation不得走该旁路。

3.4 Per-FE State

shortlist是D2A内部组合可见集合，不保存为状态，不改变Issue Entry状态或
candidate_present。D2A并行计算两个way的legal：仅一个way合法时选择该way，两个way
均合法时按candidate_way_rr_ptr选择；每bank最多贡献一个shortlist项。未匹配项仍保留
在本地候选槽，candidate_way_rr_ptr每周期翻转以避免固定way队头长期阻塞。

四个FE的相对未来返回表在模块内部组织为[fe_id][slot 0..5]二维数组。Scheduler
为每个FE保存一组D2A grant：

  grant_valid
  grant_seq_tag[5:0]
  grant_target_seq_tag[5:0]
  grant_delay[1:0]
  grant_dep_required
  grant_pending_block[2:0]

Scheduler另保存一份全局grant_candidate_onehot[7:0]。每个candidate bank每周期至多授权
一次，因此无需按FE复制；该one-hot在D2B删除候选并形成下一拍candidate pending。

候选槽只保存完整窄metadata。PPE_SCHEDULER为每个FE保存一组D2B到D3
selected-operand流水寄存器：

  selected_valid
  selected_seq_tag[5:0]
  selected_delay[1:0]
  selected_dep_required
  selected_packet[127:0]

ROB保存D2B gather query：

  gather_dep_required_q[FE_NUM]
  gather_target_seq_tag_q[FE_NUM][SEQ_W-1:0]

PPE_SCHEDULER保存每FE相对返回表：

  future_valid[FE_NUM][0..5]
  future_seq_tag[FE_NUM][0..5][5:0]

每个FE独立拥有一组返回表时序过程；delay通过固定case写slot 1..4，不生成跨FE或跨
24项future tag的动态写选择网络。

shortlist是D2A内部组合可见集合，grant寄存器是D2A到D2B的窄控制流水；
selected-operand寄存器是D2B到FE内部输入的宽数据边界。D2A从候选槽形成完整窄metadata和
candidate one-hot，使用当周期calendar计算legal并执行匹配后捕获不可撤销grant。
D2B删除候选、清candidate_present、将entry转为ISSUE_SELECTED，并使用寄存metadata
请求ROB gather；ROB在请求侧寄存窄query，并在其后组合产生最终dependency data。selected
寄存器只捕获metadata和source packet，FE输入寄存器直接采样ROB返回的内部组合数据；可
同沿捕获下一gather响应，不引入FE隔周期气泡。

沿前future slot0表示本上升沿返回，slot1..5表示随后1..5个上升沿。每个非复位沿先
消费slot0并向低位移位；本沿D2B提交的grant在沿后写slot[delay+1]。D2A检查新grant时，
delay 0..2分别检查沿前future slot3..5。当前grant比新grant早一沿，
其delay 1/2/3分别与新请求delay 0/1/2冲突；delay 3目标超出沿前正式预约最远位置。
只有valid位参与空闲
判断，seq_tag在valid=0时不要求清零。返回时ROB写地址从完整tag低位临时派生。

3.5 FE Arbitration State

  candidate_way_rr_ptr[0..3]
  group_rr_ptr[0..1]

每个candidate_way_rr_ptr指向对应bank下一周期优先观察的本地way，并且每周期翻转。
group_rr_ptr[0]控制Bank0/2到FE0/1的单授权冲突优先级，group_rr_ptr[1]控制Bank1/3
到FE2/3的单授权冲突优先级；两者每周期翻转，因此公平状态不依赖D2A当周期legal或
accept组合结果。

若D2A在cycle n捕获grant，cycle n+1由D2B执行ROB gather并提交返回预约，cycle n+2
由D3寄存operand送入FE。delay=d的目标返回沿为cycle n+d+3。D2A在cycle n沿前检查
future slot[d+3]；
同周期尚未写入future表的grant必须按相对周期一并检查。
D2B沿后把grant写入slot[delay+1]，
其后每沿移位，恰在目标返回沿前位于slot0。

3.6 Dependency Control State

Scheduler不保存非权威依赖数据副本，也不保存依赖数据fallback或replay状态。依赖满足
仍由ISSUE_WAIT_DEP/ISSUE_READY唯一表达，128 bit结果始终由backend active ROB或
retired history拥有。Scheduler额外维护：

  waiter[ROB_DEPTH][MAX_DEP]
  early_wake_hit[ISSUE_DEPTH]

waiter行以producer ROB ID索引，bit k表示seq_tag=producer_seq_tag+(k+1)的消费者正在
等待该生产者。该窄关系只用于提前产生entry-local状态写使能，不代表结果available，
也不替代完整seq tag身份约束。物理注册写使能按ROB ID低2位先选4个bank，再在目标
bank的8个row内生成one-hot；同一bank最多合并4路offset mask，逻辑结果仍写入对应
waiter行。early_wake_hit是寄存一拍的one-hot状态更新token。

================================================================================
4. Backend内部数据结构
================================================================================

4.1 ROB Entry

ROB深度为32，每个entry至少包含：

  valid
  seq_tag generation
  result_valid / done
  fe_out_data[127:0]

fe_out_data同时作为最终输出数据和依赖结果，不保存两份128 bit数据。

物理实现将entry metadata与128 bit result data分离。Result data按ROB ID低2位组织为：

  result_bank = rob_id[1:0]
  result_row  = rob_id[4:2]
  result_data[4][8][127:0]

该banking只改变内部连线和选择结构，不改变以完整seq_tag低5位定义的ROB物理索引。
基线SEQ_W=6且ROB_ID_W=5，entry物理索引已经隐含完整seq_tag低5位，因此metadata只
保存seq_tag[5] generation。访问时以请求tag低5位选择entry，并比较保存的generation
与请求tag[5]；退休tag按{generation, rob_id}重构。该压缩物理编码与完整6 bit tag
比较语义等价，禁止只比较ROB ID。
Active dependency读取仍支持每周期最多4路任意ROB ID。Writeback沿用Scheduler的奇偶
分组：FE0/1只允许返回Bank0/2 entry，FE2/3只允许返回Bank1/3 entry。同周期最多4路
writeback ID互异；同组两路仍允许落入相同result bank的不同row，因此每个entry必须
保留独立写使能，不能引入bank冲突停顿。
Allocation commit packet先按rob_id低2位捕获到4组A1 bank-local寄存器。密集allocation tag保证
同一批次每个bank最多命中一次；A1下一沿按row写统一data阵列。A1只延迟宽packet写入，
valid、seq_tag和result_valid仍在D0B commit沿更新。D0A reservation不搬移packet；
D0B从commit bundle保存的FIFO槽位读取沿前旧packet并捕获bank-local row/data。
若grant后source gather与A1提交同周期命中相同bank和row，A1捕获值优先于data bank返回；
完整tag资格仍由ROB metadata检查。该转发不参与result或dependency数据优先级选择。

4.2 ROB Global State

  head_ptr[4:0]
  occupancy[5:0]
reserve_credit[5:0]
  retire_bank_row[4][2:0]

  occupancy_after_retire = occupancy - pending_retire_count

head_ptr按32自然回绕。Allocation物理索引由alloc_seq_tag低位直接产生，不保存tail_ptr。
retire_bank_row用于data/tag的物理读取、DONE选择和对外ready row。
occupancy范围为0..32，并包含最多一项已经reservation但尚未commit的batch。reserve_credit
free reservation credit表示不含当前pending-retire的物理空闲数量，复位值为32；Ingress
将它与同样寄存的pending-retire count相加后得到下一reservation沿可安全接收的entry数量。
free credit在同一更新中扣除当前接受的reservation count并加入沿前pending-retire；本沿
新扫描出的retire count只更新pending-retire寄存器，不进入当前credit组合路径。该策略
不会超卖ROB，且退休scan不进入Ingress容量路径。固定4-lane实现由Ingress直接提供0..4的窄
alloc_reserve_count，ROB只执行一次小位宽credit比较，不再对16种valid向量做重复译码。

4.3 Retired History Bank

共8个bank。每个bank保存：

  valid
  seq_tag[5:3]
  result_data[127:0]

bank编号直接等于seq_tag[2:0]。不保存独立seq_residue字段；bank命中必须同时检查
valid和保存的seq_tag高3位，低3位由被访问bank隐含。二者合并等价于完整seq_tag比较。

4.4 Retire Output State

  start_lane[1:0]
  out_valid[N]
  out_packet[N][127:0]

所有out_valid/out_packet必须由寄存器驱动。

================================================================================
5. 模块间逻辑接口
================================================================================

5.0 Top输入寄存边界与寄存反压

ppe_top将原始顶层in_valid、in_packet和in_desc只连接到ppe_ingress输入
捕获端口。其他PPE子模块不得读取这些原始端口。ppe_ingress的bkps_o由bkps_q寄存器
直接驱动，不得由FIFO占用、ROB状态、retire前缀或当前in_valid组合赋值。

Top外部多位lane端口使用unpacked array，以下方括号表示逻辑维度：

  in_valid_i[N]
  in_packet_i[N][127:0]
  in_desc_i[N][4:0]
  bkps_o

5.1 Ingress -> ROB/Scheduler：Reservation and Registered Commit

Ingress对FIFO寄存head保持原始lane索引，不对128 bit packet做物理压缩。D0A送往ROB的
容量reservation接口为：

  alloc_reserve_count_o[2:0]
  alloc_reserve_credit_i[5:0]
  alloc_pending_retire_count_i[2:0]

alloc_reserve_count是FIFO head保存的有效报文数量，来自已寄存FIFO head，取值为0..4；
alloc_reserve_credit和alloc_pending_retire_count均由ROB寄存输出，二者之和表示当前批次
可安全预留的entry数量。Ingress不再把四位lane-valid mask发送给ROB做容量译码，
reservation接受条件为：

  reserve_fire = (alloc_reserve_count != 0)
               && (alloc_reserve_count <=
                   alloc_reserve_credit + alloc_pending_retire_count)

D0A接受reservation时，ROB立即把reserve_count计入occupancy，Ingress弹出FIFO head、
推进next_seq_tag并寄存一项commit bundle。D0B commit不再携带ready或接受反馈：

  alloc_commit_valid_o[N]
  alloc_seq_tag_o[N][SEQ_W-1:0]
  alloc_packet_o[N][127:0]
  alloc_target_seq_tag_o[N][SEQ_W-1:0]
  alloc_delay_o[N][1:0]
  alloc_dep_required_o[N]

同一alloc_commit_valid同时送ROB和Scheduler。ROB以它写metadata并捕获bank-local
原始packet，原始packet在下一A1沿写入统一data阵列；Scheduler以它初始化entry。
commit bundle已经取得容量保证，禁止再次反压或部分提交。Scheduler和backend分别从
alloc_seq_tag低位派生本地entry索引。不存在allocation ROB ID请求/响应或独立residue接口。
完整desc不跨越ingress边界：desc[1:0]解码为alloc_delay，desc[4:2]是否非零解码为
alloc_dep_required；实际依赖距离已经体现在alloc_target_seq_tag中。

5.2 Allocation Physical Index

完整alloc_seq_tag是allocation的唯一跨模块身份。Issue table和backend在模块内部独立
派生：

  alloc_rob_id = alloc_seq_tag[ROB_ID_W-1:0]

该低位切片只作为本地数组索引，不形成端口或持久metadata字段。基线ROB_DEPTH=32且
seq tag密集分配，因此无需backend向issue table返回allocation ID或accept响应。采用此
映射时要求ISSUE_DEPTH=ROB_DEPTH=2^ROB_ID_W；非2次幂ROB必须先重新定义物理索引规则。

5.3 Scheduler <-> Backend：Dependency Resolve and Gather

ROB同时向Scheduler输出每个4-way interleaved bank的最老未退休row：

  ready_bank_head_row[4][2:0]

该信号直接来自ROB的bank-local退休游标。Scheduler只用它作为本bank READY环形扫描
起点，不据此改变依赖状态、候选合法性或FE匹配规则。

D0C为上一周期D0B提交的最多N个有依赖allocation发出小位宽状态请求：

  dep_status_valid[N]
  dep_status_target_seq_tag[N][SEQ_W-1:0]
  dep_status_available[N]

匹配grant后，PPE_SCHEDULER按FE形成寄存operand gather请求：

  source_bank_row[4][ROB_BANK_ROW_W-1:0]
  source_bank_tag_hi[4][SEQ_W-ROB_ID_W-1:0]
  source_bank_packet[4][127:0]
  gather_dep_required[FE_NUM]
  gather_target_seq_tag[FE_NUM][SEQ_W-1:0]
  gather_dep_data[FE_NUM][127:0]

Scheduler在D2A锁存grant时按source seq tag低2位直接更新对应bank的row和tag-high，
无新请求的bank保持旧地址。Backend对4个bank分别读取原始packet；Scheduler按
grant seq tag低2位把bank响应送入对应FE operand寄存器。gather_dep_required时，ROB先
在窄query寄存器中保存target tag，再在其后的组合周期按completion bypass、active ROB
和history顺序形成最终gather_dep_data；该数据经内部FE接口由FE输入寄存器采样。
正常状态下读取必须命中，该路径不设ready、fallback或replay端口。

请求无效时响应定义为：

  - dep_status_valid=0时，dep_status_available必须为0；
  - 无对应grant时，source_bank_packet不被有效selected operand采样；
  - gather_dep_required=0时，gather_dep_data不具有语义。

PPE_SCHEDULER直接管理请求资格、completion wakeup比较和gather响应语义适配，不设置中间
dependency模块或额外流水边界。

5.4 Unified Scheduler Interfaces

PPE_SCHEDULER接收D0B guaranteed commit bundle、D0C dependency status响应以及FE返回有效：

  ready_bank_head_row[4][2:0]
  issue_alloc_valid[N]
  alloc_seq_tag[N][SEQ_W-1:0]
  alloc_target_seq_tag[N][SEQ_W-1:0]
  alloc_delay[N][1:0]
  alloc_dep_required[N]
  dep_status_available[N]
  fe_out_valid[FE_NUM]

并输出D0C status请求、ROB gather请求、FE operand和completion tag：

  dep_status_valid[N]
  dep_status_target_seq_tag[N][SEQ_W-1:0]
  source_bank_row[4][ROB_BANK_ROW_W-1:0]
  source_bank_tag_hi[4][SEQ_W-ROB_ID_W-1:0]
  source_bank_packet[4][127:0]
  gather_dep_required[FE_NUM]
  gather_target_seq_tag[FE_NUM][SEQ_W-1:0]
  issue_valid[FE_NUM]
  issue_packet[FE_NUM][127:0]
  issue_delay[FE_NUM][1:0]
  issue_dep_required[FE_NUM]
  issue_dep_data[FE_NUM][127:0]
  completion_valid[FE_NUM]
  completion_seq_tag[FE_NUM][SEQ_W-1:0]

原Issue Table与FE Scheduler之间的candidate/select接口不存在。候选、匹配、grant、
candidate_present和future table均由PPE_SCHEDULER内部拥有；跨模块只传递已经寄存的
gather metadata和宽数据响应。重复多位端口使用unpacked array，逻辑通道0对应数组元素0。

D2A先从每bank两项候选中选取至多一项形成组合shortlist。Bank0/2只连接
FE0/1，Bank1/3只连接FE2/3。
每组固定2x2网络先并行判断直连和交叉双发映射；存在任一双发映射时必须发出两项，
两种映射同时合法时按group_rr_ptr选择。不存在双发映射时，再按group_rr_ptr选择一个
合法候选和一个合法FE。两个组不存在跨组请求、接受或retry逻辑。该网络保证一个候选
和一个FE每周期至多获得一次grant，并在各自2x2合法矩阵内取得最大基数。

Grant不可撤销。D2A沿锁存完整窄metadata和candidate one-hot。下一周期D2B使用one-hot
删除对应候选、清candidate_present、将entry置为ISSUE_SELECTED，同时允许同bank空槽
补入一个沿前READY entry；grant metadata并行驱动ROB gather并写future预约。D2B沿
gather响应进入per-FE operand
寄存器并送入FE，同时旧SELECTED entry转为FREE。接口没有ready、rollback或replay。

issue_valid=0时其余issue bundle字段输出0；下游使用

  fe_dep_valid = issue_valid && issue_dep_required

不设置独立issue_dep_valid端口。

5.5 Scheduler -> FE

每个FE使用一组独立命名端口：

  fe_in_valid0..3
  fe_in_data0..3[127:0]
  fe_dep_valid0..3
  fe_dep_data0..3[127:0]
  fe_desc_delay0..3[1:0]

每个FE每周期最多接受一路fe_in_valid。delay=d的请求固定在接收后的第d+1周期返回。
接口没有ready；scheduler必须通过6项相对未来表保证同一FE的所有在途请求目标输出周期
互不冲突。FE返回同周期允许接收新的无冲突请求。

5.6 FE/Scheduler Tag -> Backend Writeback

PPE_SCHEDULER接收fe_out_valid，并以每个FE的future slot0进行关联：

  completion_valid[FE_NUM]
  completion_seq_tag[FE_NUM][SEQ_W-1:0]

合法状态下：

  completion_valid[fe] = fe_out_valid[fe] && future_valid[fe][0]
  completion_seq_tag[fe] = future_seq_tag[fe][0]

completion valid/tag同时送Scheduler执行wakeup并送backend执行writeback。每个FE到
backend的数据接口为：

  wb_valid0..3
  wb_seq_tag0..3[5:0]
  wb_data0..3[127:0]

其中wb_valid/wb_seq_tag直接使用对应completion事件，wb_data直接来自FE，不经过
PPE_SCHEDULER。Backend内部以wb_seq_tag低ROB_ID_W位生成本地写地址。

5.7 ROB -> Retire Output -> Top

ppe_rob向ppe_retire_output提供：

  retire_valid[N]
  retire_data[N][127:0]

ppe_rob不输出物理lane编号或start_lane。ppe_retire_output不向ppe_rob返回ready、accept
或其他流控信号。

对外接口分别由对应状态所有者驱动：

  PPE_INGRESS       -> bkps
  PPE_RETIRE_OUTPUT -> out_valid[N]
  PPE_RETIRE_OUTPUT -> out_packet[N][127:0]

5.8 Top -> PPE子模块/FE：Internal Reset

ppe_top使用外部rst_n实现唯一的两级复位同步器，生成internal_rst_n。
internal_rst_n异步拉低、同步释放，并作为ingress、scheduler、PPE_ROB、
ppe_retire_output和四个FE
的共享低有效复位。各子模块不得再次同步复位或产生独立释放时序。

================================================================================
6. Ingress I0/D0：输入捕获、容量预留与分配
================================================================================

6.1 I0 Two-slot Elastic Input Capture

在上升沿且bkps_q=0时，ingress将全部lane的in_valid、in_packet和in_desc无条件写入
slot_wr_ptr选择的寄存槽位，同时推进写指针和占用计数。原始输入不参与任何其他状态
更新。两项槽位本身构成有序FIFO，不存在capture到FIFO的第二次宽数据搬移。下一周期
仅根据寄存head lane-valid和ROB提供的寄存credit判断：空批直接释放；非空批在
alloc_reserve_count不超过alloc_reserve_credit与alloc_pending_retire_count之和时完成
reservation、寄存commit bundle并
释放。tail capture与head release允许同沿发生。

6.2 D0 Registered-Head Rank

对于lane i：

  lane_rank[i] = elastic FIFO head中lane编号小于i且valid=1的lane数量

固定N=4基线对两个slot分别使用静态平衡网络，不以循环累加器形成串行依赖：

  lower_pair_count = valid[0] + valid[1]
  upper_pair_count = valid[2] + valid[3]
  lane_rank[0] = 0
  lane_rank[1] = valid[0]
  lane_rank[2] = lower_pair_count
  lane_rank[3] = lower_pair_count + valid[2]
  head_packet_count = lower_pair_count + upper_pair_count

每个slot独立计算上述rank和packet_count；slot_rd_ptr只在这些窄结果之后选择
非空FIFO head。对所选head：

  seq_tag[i]           = next_seq_tag + lane_rank[i]
  head_lane_valid[i]   = slot_lane_valid[slot_rd_ptr][i]
  alloc_reserve_count    = head_packet_count
  reserve_fire[i]        = head_lane_valid[i]
                         && (alloc_reserve_count <=
                             alloc_reserve_credit
                             + alloc_pending_retire_count)

当alloc_reserve_credit不足或internal_rst_n=0时，reserve_fire必须为0，FIFO head、
next_seq_tag和commit bundle不得接受该请求。上一周期已经寄存的commit bundle不受
当前ready影响，并在本沿无条件写ROB和Issue Table。

seq_tag使用固定位宽自然回绕。Ingress不读取ROB指针，也不产生rob_id或residue输出；
backend和issue table之间不存在ROB ID通路。

6.3 Dependency Input Contract

输入协议保证非零dep_offset不大于本次复位后排在当前报文之前的报文数量，其中包括
同周期lane编号更小且同时被接收的报文。Ingress不保存历史计数器，不检测或修改
非法dep_offset。desc_delay始终保持FIFO head中已寄存desc[1:0]不变。

6.4 Dependency Target Precompute

若dep_offset=K且K不为0：

  target_seq_tag = seq_tag - K mod 64

固定N=4实现必须先以4 bit补码计算delta=lane_rank-K，再执行一次SEQ_W位
next_seq_tag+sign_extend(delta)，避免seq加法与target减法形成两段SEQ_W宽串联算术。
两个slot的窄seq/target算术并行展开，slot_rd_ptr只选择最终结果；该物理改写与上述
模64语义等价。

密集seq分配建立并必须保持以下不变量：

  rob_id         = seq_tag[4:0]
  target_rob_id  = target_seq_tag[4:0]
  history_bank   = target_seq_tag[2:0]

ROB和history索引均由完整tag低位组合派生，不作为ingress输出或entry存储字段。

6.5 D0A Reservation / D0B Commit

|alloc_reserve_count != 0 && alloc_reserve_count <=
alloc_reserve_credit + alloc_pending_retire_count的D0A reservation沿同时完成：

  - backend把reserve_count计入occupancy，提前占用下一周期commit所需容量；
  - ingress把当前head预览标记为有效commit，并保存原FIFO槽位号；
  - ingress释放elastic FIFO head并按有效lane数量推进next_seq_tag。

FIFO非空时，Ingress的commit metadata寄存器每沿预览当前head的seq_tag、
target_seq_tag、delay和dep_required，不以credit比较结果作为metadata预览写使能。
alloc_commit_valid单独由reservation成功限定；因此未取得reservation的预览不得被
ROB或Issue Table使用，且ROB ready不广播到各metadata寄存器CE。

下一周期D0B无条件提交寄存bundle：

  - backend写ROB metadata并捕获原FIFO槽位中的沿前旧packet；
  - Issue Table使用alloc_seq_tag低位写metadata；无依赖entry写ISSUE_READY，
    有依赖entry写ISSUE_WAIT_DEP并捕获窄依赖状态探针。

再下一周期D0C使用Issue Table寄存探针查询依赖状态；响应以寄存consumer ROB ID直接
定址对应ISSUE_WAIT_DEP entry，available时将其转为ISSUE_READY。D0A、D0B和D0C可每周期处理相邻批次，
不降低4-wide allocation吞吐；新增D0A/D0B边界使无依赖报文的最短调度延迟增加一拍。

Issue Table物理写入先按alloc_seq_tag[1:0]把四路allocation静态路由到4个bank，再由
每个bank的alloc_seq_tag[4:2]生成8-row one-hot write enable。密集seq分配保证每批
每个bank至多命中一路，因此该网络没有仲裁语义；metadata与issue_state可以由关联但
独立的时序过程拥有。依赖target_seq_tag复用D0B状态探针寄存器，并在D0C按consumer
ROB ID写入entry。

外部输入被I0捕获后至少经过一个寄存边界才能进行D0 allocation，不允许组合直通
sequence allocation、ROB、Issue Table、FE或任何顶层输出。

================================================================================
7. Scheduler依赖初始化与事件唤醒
================================================================================

7.1 D0B Initialization / D0C Dependency Resolve

  dep_offset=0：dep_required <- 0, state <- ISSUE_READY

  dep_offset!=0：D0B沿先执行dep_required <- 1, state <- ISSUE_WAIT_DEP，并寄存
  consumer ROB ID和完整target_seq_tag。consumer ROB ID只作为模块内部D0C定址信息。
  D0C向G0发送寄存target_seq_tag；G0内部派生
  target ROB/history索引，并按completion bypass、retirement bypass、active ROB和
  retired history顺序返回available。D0C响应以寄存consumer ROB ID直接形成entry-local
  写使能；available时，在D0C沿将
  target_seq_tag写入entry并把state更新为ISSUE_READY；否则写入target_seq_tag并保持
  ISSUE_WAIT_DEP。状态探针尚未提交target metadata的一拍禁止completion scan该consumer，
  同周期completion由状态查询的completion bypass覆盖。该查询不进入bkps路径，不返回
  或复制128 bit依赖数据。D0B提交后到对应D0C响应前，该物理entry受状态所有权约束不得
  释放或重新分配，因此无需再次执行consumer完整tag反查。

7.2 Reverse Waiter Registration and Early Wakeup

D0B提交时以完整consumer seq tag和target seq tag计算模64差值K，并将K=1..7译码为
寄存的7 bit offset one-hot。D0C查询返回not available时复用该窄offset；合法输入
保证K位于1..7，Scheduler设置：

  waiter[target_seq_tag[ROB_ID_W-1:0]][K-1] <- 1

实现上target_seq_tag低2位选择waiter bank，高3位在该bank内生成8-row one-hot；每个
bank只对最多4路请求做offset mask局部OR，再形成上述逻辑行写入。该物理解码不改变
waiter的完整ROB ID索引语义。

同一周期最多4路登记按bit OR合并。生产者entry重新allocation或实际completion时清除
对应waiter行；D2B读取已grant生产者的waiter行后清除已读取bit，同周期新登记具有保留
优先级。waiter行的生产者身份由当前issue entry完整seq tag与grant seq tag一致保证，
consumer身份由producer完整tag与offset唯一推导；ROB ID或offset均不得单独构成命中。

D2B消费不可撤销grant时读取对应7 bit waiter行，将有效bit按producer seq tag加offset
展开为ISSUE_DEPTH项one-hot。delay 0..2写入一拍early_wake_hit；delay 3先进入额外一拍
窄token延迟。token生效沿仅对仍处于ISSUE_WAIT_DEP且不在D0C pending边界的entry置
ISSUE_READY。生产者在D2B预约后的下一沿才由D3进入FE，因此上述分级保证READY更新时
生产者距completion不超过3拍；消费者后续仍需经过D1、D2A、D2B gather和D3，故gather
不早于生产者completion。

实际Completion tag为S时仍并行检查32项issue entry作为兜底；仅当entry处于
ISSUE_WAIT_DEP、完整target_seq_tag等于S且不在D0C pending边界时置ISSUE_READY。
该兜底覆盖grant后才登记的消费者和所有并发边界，不读取或选择packet宽数据。

READY bank提名只读取沿前issue_state，不组合读取completion wake hit。因此被唤醒entry
最早下一周期写入本地候选槽，再由后续D2A选择。

7.3 Simultaneous Initialization and Completion

D0B新分配的依赖entry在本沿固定进入ISSUE_WAIT_DEP，不组合读取本周期completion。
若目标同周期completion，下一周期D0C状态探针从active ROB取得available并将entry转为
ISSUE_READY。若D0C查询时目标active ROB entry存在但result_valid=0且无completion
bypass，G0必须返回not available，禁止继续使用history。

Completion wakeup和D0C状态更新均在issue_state边界终止，不组合进入候选提名。
D0B allocation状态初始化具有最终优先权；D0C使用前一周期D0B提交并寄存的consumer
物理entry ID直接更新状态。

Early-wakeup token、completion wakeup和D0C available同时命中同一entry时均为幂等的
READY更新。Allocation仍具有最终优先权，selected更新优先于各类READY更新。

================================================================================
8. Scheduler D2A/D2B：候选匹配、原子消费和返回预约
================================================================================

8.1 READY Discovery and Admission

ISSUE_READY且candidate_present=0的entry可被发现。发现只使用沿前状态；allocation、
D0C状态更新和completion wakeup最早下一周期参与发现。entry按ROB ID低2位进入4个
交错bank，每bank从ready_bank_head_row开始环形扫描8个row并提名至多1项。该起点是
本bank最老未退休entry，因此优先级按全局退休年龄投影到各bank。每bank候选槽固定为
bank和4+bank。

若本bank有无效槽或本周期D2B消费grant删除槽，则允许一次提名。优先写入被删除或无效的way0，
否则写way1。Grant删除和提名在同一candidate next-state内合并；旧entry仍受沿前
candidate_present屏蔽，不能在同沿重新提名。无依赖allocation仅在没有沿前READY winner
时可直接进入空槽；依赖allocation不得走该旁路。winner实际写入候选槽时只更新对应
candidate_present，不保存独立READY扫描指针。

8.2 Shortlist and Legal Matrix

每bank的两个本地way并行检查当周期calendar，形成各自2 bit legal。仅一个way存在合法
FE时选择该way；两者均存在合法FE时按candidate_way_rr_ptr选择，形成最多4项组合
shortlist。未匹配候选保持原槽。delay 0/1/2
分别检查future slot3/4/5及上一拍grant的虚拟预约；delay 3直接形成2'b11合法向量，
不读取future table。一个FE已有其他在途请求并不使其整体不可用。

8.3 Fixed Local 2x2 Match

偶数组输入为Bank0/2 shortlist，输出为FE0/1；奇数组输入为Bank1/3 shortlist，输出为
FE2/3。每组并行计算straight和cross两种双发条件，任一成立时按固定映射双发；均不成立
时按group_rr_ptr轮换候选优先级和FE优先级，最多发出一项。网络静态展开，不执行动态
数组索引、跨组竞争或数据相关迭代。

8.4 Grant and Concurrent Update

D2A结果在上升沿锁存per-FE candidate one-hot、seq_tag、target_seq_tag、delay和
dep_required。grant锁存后不可取消；对应way在下一D2B沿从候选槽删除。

该D2B上升沿：

  - 合并grant one-hot形成candidate_remove；
  - 合并grant one-hot形成candidate_remove；
  - 清对应candidate_present；
  - 将issue entry转为ISSUE_SELECTED；
  - 允许各bank把一个沿前READY winner写入被释放槽。

Grant一旦锁存不得取消。D2A锁存grant的同一沿按source seq tag形成bank-local
source row/tag-high请求。下一周期D2B以寄存target metadata请求ROB dependency gather，
读取对应bank的source packet，并在future表的slot[delay+1]写入完整seq tag。无法匹配
的候选保持READY和candidate_present。

================================================================================
9. Scheduler D3：Operand Gather与FE Issue
================================================================================

每路有效grant使用其seq tag低2位选择bank-local source packet；需要依赖时，ROB先锁存
窄gather query，再在selected到FE的周期按completion bypass、active ROB、history优先级
形成最终gather_dep_data。请求不设置ready或重放，合法调度下读取必须命中。

source packet、issue metadata和selected valid在下一上升沿写入对应per-FE selected寄存器。
沿后dependency data从ROB query对应的内部组合结果进入FE，由FE输入寄存器采样。该内部
组合通路不改变顶层对外输出的寄存要求，也不增加FE发射周期。同沿将上一份selected entry
释放为ISSUE_FREE。Selected释放和D2B候选删除使用完整有效FE集合检查对应物理entry。
当前operand被消费时允许捕获下一份gather响应，因此不产生隔周期气泡。
候选窗不保存packet或dependency，宽数据只存在于ROB和4份operand寄存器。

grant metadata寄存器在grant_valid=0时保持旧值，跨模块gather tag不因valid=0而清零。
ROB在gather请求侧只锁存窄target tag和dep_required；selected_valid每周期捕获
grant_valid，selected metadata和source packet在selected_valid=0时内容不具有语义。
ROB的最终dependency data在query寄存器之后组合产生，并通过内部FE接口送入FE输入
寄存器；不额外复制scheduler宽候选寄存器，也不把grant_valid扇出到宽数据路径。

future slot1表示下一completion采样沿。Scheduler每沿以slot1为每个FE寄存
完整wb_pre_seq_tag和32 bit entry one-hot；slot1无效时one-hot清零并保持seq tag。
one-hot全0表示无预测，不设置独立wb_pre_valid端口。下一沿实际completion到达时，
ROB要求实际wb_valid、实际
wb_seq_tag等于wb_pre_seq_tag、one-hot目标active tag匹配且result_valid=0，才产生
entry-local write enable。预译码不代替实际completion写回资格检查。固定延迟FE协议下，
它同时是本沿必返回entry的精确预测，可用于13章的head completion预测退休；
实际writeback仍由wb_valid、完整tag及active entry状态独立确认。

================================================================================
10. Backend A0/A1：ROB Allocation
================================================================================

对于本周期每个alloc_commit_valid：

  alloc_rob_id = alloc_seq_tag[ROB_ID_W-1:0]
  rob[alloc_rob_id].valid          <- 1
  rob[alloc_rob_id].seq_generation <- alloc_seq_tag[SEQ_W-1:ROB_ID_W]
  rob[alloc_rob_id].result_valid   <- 0
  alloc_data_bank[alloc_rob_id[1:0]] <- {
      valid = 1,
      row   = alloc_rob_id[4:2],
      data  = alloc_packet
  }

A1在下一上升沿将各有效alloc_data_bank写入对应统一data槽。Grant后gather在D2B
读取该data槽；若与A1同周期命中则使用allocation forwarding。W0随后以处理结果原址覆盖同一data槽并
置result_valid。无效entry的
数据内容不要求清零。alloc_commit_valid来自上一周期已经接受的reservation，不设置
ready或重放端口。occupancy只在reservation沿增加，commit沿不再次增加。

Source gather使用D2A寄存的bank-local row和tag-high索引。ROB valid、完整tag匹配且result_valid=0是
合法gather的不变量；该条件区分原始packet与已经覆盖的结果，不允许把完成结果误作FE
输入。物理比较使用低位索引隐含部分与entry保存的tag高位，语义仍为完整tag匹配。
每bank直接产生一份packet响应；Scheduler按当前寄存grant的bank低位选择响应。
协议保证同一bank每周期最多一条source请求，D2A对bank-local地址的更新没有仲裁或
覆盖语义。

================================================================================
11. Backend G0：依赖状态与数据解析
================================================================================

11.1 Common Resolve Rule

给定target_seq_tag，先在backend内部派生：

  target_rob_id = target_seq_tag[ROB_ID_W-1:0]
  history_bank  = target_seq_tag[2:0]

然后每路请求按以下顺序解析：

  1) 按target_seq_tag[0]选择合法completion pair；若pair内任一wb_commit的完整seq_tag匹配：
       satisfied = 1, source = COMPLETION_BYPASS, data = wb_data
  2) 否则若任一retire entry的完整seq_tag匹配：
       satisfied = 1, source = RETIREMENT_BYPASS, data = 沿前rob_data
  3) 否则若rob[target_rob_id].valid且完整seq_tag匹配：
       result_valid=1时satisfied = 1, source = ACTIVE_ROB；
       result_valid=0时satisfied = 0，并立即停止，禁止查询history
  4) 否则以target_seq_tag[2:0]索引history：
       history.valid且完整seq_tag匹配时satisfied = 1, source = HISTORY；
       否则satisfied = 0

完整seq_tag匹配是必需条件，ROB ID或history bank低3位单独匹配不得视为命中。
物理实现中ROB和history分别只保存未被entry/bank索引隐含的tag高位；索引低位与保存
高位共同构成上述完整tag检查。
查询采样沿前，retire entry仍保持active valid、完整tag和result data，因此第2、3级
在物理实现中共用active ROB命中与数据，不重复生成retire head比较；该折叠不改变上述
优先级或沿上可见结果。

11.2 Query Width

D0C每周期最多提交N路status query，只返回dep_status_available，不要求切换128 bit数据。
D3每周期最多提交ISSUE_WIDTH路dependency data query，每路返回128 bit data。同一target被多路
请求命中时允许共享一次读取并广播；实现也可描述为等价的独立组合读取。
每个query的target ROB ID、history ID、active完整tag命中和history完整tag命中只生成
一次中间结果，并由available/data选择共同使用。RTL不增加运行时跨query合并器；综合
工具可对相同target请求共享组合读取，独立读取仍是周期语义等价的合法实现。
每路D3 query对四个completion lane并行形成one-hot完整tag命中，128 bit bypass data
使用两级平衡OR归并；最终在ROB窄query寄存器之后按completion、active、history固定
优先级选择。不得用source_resolved跨completion lane形成串行选择链。

11.3 Cycle Boundary Rules

Completion bypass可以使D0C查询的entry或ISSUE_WAIT_DEP entry在W0写ROB的同一沿得到available状态，
但该entry最早下一周期参加D2A，不允许同沿completion-to-FE直通。Retirement bypass
读取沿前旧ROB数据，并优先于沿后可能复用同一ROB ID的新allocation。上升沿后，目标
改由已更新history命中。该规则不依赖存储体未定义的read-during-write行为。

================================================================================
12. Backend W0：FE Writeback
================================================================================

每个wb_valid先计算轻量写保护：

  wb_rob_id = wb_seq_tag[ROB_ID_W-1:0]
  wb_commit = wb_valid
           && rob[wb_rob_id].valid
           && rob[wb_rob_id].seq_tag == wb_seq_tag
           && !rob[wb_rob_id].result_valid

仅当wb_commit=1时执行：

  rob[wb_rob_id].data         <- wb_data
  rob[wb_rob_id].result_valid <- 1

同周期最多4个有效writeback seq tag的低ROB_ID_W位必须互不相同。验证侧必须用SystemVerilog assertion
检查FE返回与当前日历槽valid一致、ROB valid、完整tag、未重复完成和同周期ID互异。
任何检查失败都是
验证错误，不设置可综合sticky异常状态，不参与bkps、派发或退休控制。

W0必须捕获全部符合协议的有效FE返回，不允许通过ready反压FE。物理实现必须支持
4路并发写回以及同一bank内两路不同row并发写，不能使用单写端口存储后串行处理。

每路writeback从seq tag派生ROB ID。entry按bank奇偶只接收固定FE pair，并在本地同时
完成ROB ID、generation、valid和result_valid资格检查：

  allowed_pair(even_bank) = FE0/FE1
  allowed_pair(odd_bank)  = FE2/FE3

  wb_entry_commit[entry][f] = wb_valid[f]
                             && f in allowed_pair(entry_bank)
                             && wb_rob_id[f] == entry
                             && rob[entry].valid
                             && rob[entry].generation == wb_tag_hi[f]
                             && !rob[entry].result_valid
  wb_entry_write_en[entry] = OR_f wb_entry_commit[entry][f]

每路wb_commit为该路全部合法entry命中的归约OR，供completion bypass和wakeup复用。
协议保证同一entry最多命中一路，因此entry-local固定2选1数据选择没有仲裁语义。
每个
128 bit data entry只在allocation或wb_entry_write_en有效时更新；metadata与data使用不同
时序过程，但每个状态元素仍只有一个owner。

entry地址比较隐含wb_seq_tag低5位，generation比较覆盖其余高位，因此上述资格检查
等价于完整seq_tag匹配。每个wb_commit同时形成completion bypass和scheduler wakeup事件，但不写retired
history。事件携带valid、完整seq_tag和128 bit data；本地ROB ID从tag低位派生，wakeup
只使用小位宽字段。

在cycle n上升沿，wb关联信息读取：

  wb_valid   = fe_out_valid && future_valid[fe_id][0]
  wb_seq_tag = future_seq_tag[fe_id][0]

该沿消费slot0并将future表向低位移位。合法协议下fe_out_valid必须与slot0 valid相等。
FE返回、D3发射、D2B select和下一批D2A match捕获允许同沿发生；D2B新预约写入沿后
slot1..4，不会与本周期slot0消费冲突。

================================================================================
13. Backend R0：保序退休与输出
================================================================================

13.1 Consecutive DONE Scan

从逻辑head开始检查最多4项：

  predicted_done[i] = rob[head+i].valid && !result_valid[i]
                      && |wb_pre_entry_onehot[*][head+i]
  raw_done[i]       = rob[head+i].valid
                      && (rob[head+i].result_valid || predicted_done[i])

  done01 = raw_done0 && raw_done1
  done23 = raw_done2 && raw_done3
  retire_valid = {raw_done0, done01, done01 && raw_done2,
                  done01 && done23}

  retire_count = decode_dense_prefix(retire_valid)

所有ROB索引按32自然回绕。物理head状态保存为head_bank和四个bank_row_cursor；
逻辑head ROB ID等价于{bank_row_cursor[head_bank], head_bank}。每个bank直接从其
寄存cursor选择一项DONE，再按head_bank固定旋转为上述逻辑顺序。retire_count只译码
0000、0001、0011、0111、1111五种合法编码，不使用逐项累加。

13.2 ROB Logical Retirement Bundle

ppe_rob输出按报文序排列的逻辑退休bundle：

  retire_valid[N]
  retire_data[N][127:0]

retire_valid从slot 0开始连续有效，不得留洞；slot j对应head+j的沿前ROB结果。
该bundle为组合退休事件，供ppe_retire_output在同一上升沿捕获，不使用ready或反压。
若slot的DONE来自predicted_done，retire_data必须从命中该entry的唯一FE
wb_data旁路；否则读取ROB data bank。同一entry不存在多路合法预测命中。

固定4-bank result实现由每个bank直接使用bank_row_cursor[b]读取数据/tag/DONE，再由head_bank控制的rotate-by-1/rotate-by-2固定网络恢复
slot 0..3逻辑顺序。bank cursor等价于原先由完整head动态计算的row，但不在读取前串联
比较和加法。每个bank的物理ROB ID直接取{bank_row_cursor[b], b}，tag_hi按同一cursor
执行bank-local读取；ROB ID、tag_hi和DONE复用相同固定旋转，不执行head+j和32:1
tag选择。数据置换不得改变dense-prefix valid。

13.3 Retirement Register Update

R0退休识别沿在ppe_rob内执行：

  - 从dense retire-valid五种合法编码生成head_bank两位模4 next-state（可用等价
    奇偶/XOR逻辑实现）；
  - 将本周期退休的逻辑valid反向旋转为physical-bank advance，每个命中bank的
    bank_row_cursor加一；
  - 将retire valid、tag、data和count写入pending-retire寄存器；
  - occupancy合并同周期allocation数量和上一周期pending retire count。

下一沿提交pending-retire：

  - 对每个退休报文写history[rob_seq_tag[2:0]]；
  - 清除对应ROB valid/result_valid。

Pending期间旧active entry保持有效；提交沿前由active提供依赖，沿后由history提供，
因此内部所有权延后但available语义无空窗。head_bank和bank_row_cursor的组合状态
与原5 bit自然回绕head_ptr严格等价，不生成ROB_DEPTH比较/减法路径。

同一退休沿在ppe_retire_output内同时执行：

  - 先将全4路out_valid的next value默认为0，再按start_lane映射K个退休slot；
  - 仅更新本周期out_valid=1的out_packet寄存器，其余out_packet保持；
  - start_lane按同一advance_mod4计算两位模4 next-state，保持固定的窄逻辑路径。

第j个逻辑退休slot映射到lane=(start_lane+j) mod 4，使用沿前start_lane。ROB状态
释放、history更新、输出寄存器装载和start_lane更新属于同一架构退休沿，不新增
流水级或跨模块握手。

固定N=4实现使用两级barrel rotate：第一级由start_lane[0]选择旋转0或1，第二级由
start_lane[1]选择继续旋转0或2。valid和128 bit data经过相同的固定连线置换，不使用
变量物理lane索引。retire_valid合法编码仅为0000、0001、0011、0111和1111；ROB的
retire_count支路直接译码为0..4，output的start_lane支路只生成modulo-4 advance；
RTL可用等价奇偶/XOR实现，避免引入宽计数加法器。
其他编码属于验证必须捕获的内部协议错误，不设置可综合恢复路径。
out_packet寄存器仍按物理lane使用mapped_valid作为公共clock-enable语义，RTL不手动
例化ICG。

当前N=4时，同周期退休的连续报文映射到不同history bank，不存在同bank多写。
未来N=8时，连续8个报文也分别映射到8个不同bank。

13.4 Writeback Visibility

future-slot预测命中head时，W0在本沿写回的entry可在同一沿由R0退休，
退休数据直接使用wb_data。非head或被前序未DONE entry阻塞的writeback仍落入ROB，
后续由常规DONE scan看到。若FE实际返回与future-slot不一致，属于验证必须捕获的
FE/calendar协议错误，RTL不设置可综合恢复通路。

================================================================================
14. 全局反压
================================================================================

Backend维护寄存的allocation reservation credit：

  occupancy_after_retire = occupancy - pending_retire_count
  reserve_capacity       = reserve_credit + pending_retire_count
  reserve_accept         = reserve_count != 0
                            && reserve_count <= reserve_capacity
  occupancy_next         = occupancy_after_retire
                            + (reserve_accept ? reserve_count : 0)
  reserve_credit_next    = reserve_credit - accepted_reserve_count
                            + pending_retire_count
  pending_retire_next    = retire_count

容量计算只借用已寄存且本沿必提交的pending-retire credit，避免当前retirement scan
进入Ingress容量路径。接受reservation的同一沿把reserve_count计入occupancy；新扫描
出的retire count写入pending-retire寄存器，随下一沿容量判断使用。free credit与pending
count分离寄存，既保持容量安全也避免把当前head scan串入credit D路径。
Ingress直接提供0..4的reserve_count，ROB不再对16种请求向量做宽译码。

Ingress以两项elastic FIFO吸收寄存反压延迟。定义：

  capture_batch   = !bkps_q
  head_nonempty   = (alloc_reserve_count != 0)
  reserve_batch   = (slot_count != 0) && head_nonempty
                    && (alloc_reserve_count <=
                        alloc_reserve_credit + alloc_pending_retire_count)
  head_release    = (slot_count != 0) &&
                    (!head_nonempty
                     || (alloc_reserve_count <=
                         alloc_reserve_credit + alloc_pending_retire_count))

沿后占用按capture与head release统一更新：

  {capture_batch, head_release} = 2'b10：slot_count_d = slot_count_q + 1
  {capture_batch, head_release} = 2'b01：slot_count_d = slot_count_q - 1
  其余组合：slot_count_d = slot_count_q

  bkps_d = (slot_count_d == 2)
  bkps_o = bkps_q

以上逻辑不读取任何当前原始输入。bkps_q=0时，本沿无条件捕获一个内容尚未知的完整
外部批次；若实际捕获为空批，下一周期根据寄存head lane-valid释放。bkps_q=1时不捕获，
当full FIFO的head释放后slot_count_d降为1，bkps在该沿后重新拉低。由于bkps是寄存反馈，
从一项占用到捕获第二项的沿已经预留了完整空槽，不会溢出或部分接收。

FIFO宽数据阵列使用两个显式bank-local写使能：

  slot_bank0_write = capture_batch && !slot_wr_ptr
  slot_bank1_write = capture_batch &&  slot_wr_ptr

每个bank仅由其本地使能更新packet、descriptor和lane-valid；write pointer只在
capture_batch时翻转。不得用动态bank索引形成覆盖全部宽存储的单一写使能mux，也不得
让原始lane-valid参与bank写使能。

复位期间bkps_q置1，slot_count和读写指针清零。复位释放后bkps只能在时钟沿拉低。
原始in_valid不得参与alloc_reserve_count、reserve_credit、bkps_d或任何其他功能组合逻辑。

ROB_DEPTH=32且issue table以seq_tag低位索引。ROB entry能够退休意味着对应issue entry
此前已经派发并释放，因此backend释放的物理槽在同沿也可由相同低位的新allocation复用。

================================================================================
15. 同周期并发更新
================================================================================

A0、G0、W0和R0允许同周期作用于不同entry。W0不写history；R0是history唯一写入
通路。G0的completion和retirement bypass读取本周期事件数据，不写任何权威存储。

必须满足：

  - 新reservation允许借用本沿提交的pending-retire credit；对应allocation commit
    在下一沿写入已经保证可用的entry；
  - 重叠entry的退休输出、retirement bypass和history写入读取沿前旧内容，allocation
    对沿后ROB valid、seq_tag和result_valid具有最终优先权；
  - allocation原始packet由A0按bank捕获并在A1提交；A1目标entry在正常流水下不可能
    同周期收到writeback，RTL仍以A1 packet写作为同址最终优先级；
  - 只有future-slot精确预测且位于连续head prefix的新writeback entry可同周期退休；
  - 已DONE退休entry不再次收到writeback；
  - 同周期4路writeback ID互不相同；
  - 同周期reservation和pending retirement数量统一合并更新occupancy；commit不再次
    修改occupancy；reserve_credit同步更新为下一沿可安全接收的容量；
  - ROB valid、result_valid、head和occupancy只有ppe_rob一个时序状态所有者；
  - start_lane和out_valid/out_packet只有ppe_retire_output一个时序状态所有者。

必须按统一next-state计算：

  occupancy_next = occupancy - pending_retire_count + accepted_reserve_count
  reserve_credit_next = reserve_credit - accepted_reserve_count
                         + pending_retire_count
  pending_retire_next = retire_count

valid/result_valid数组在同一个时序always block中按writeback、retire、allocation
顺序更新，使同址allocation最后赋值。退休数据选择仍由沿前数组组合产生，不受同沿
allocation非阻塞赋值影响。禁止多个always block驱动同一状态。

================================================================================
16. 复位
================================================================================

ppe_top是复位同步器的唯一所有者。外部rst_n异步拉低同步器两级寄存器，外部
rst_n拉高后经过两个clk上升沿释放internal_rst_n。PPE全部子模块和FE使用同一个
internal_rst_n。

复位清除：

  - ingress slot_count、读写指针，并将bkps_q置1；
  - issue table unified state；
  - reverse waiter和early-wakeup token；
  - candidate valid、candidate_present、candidate_way_rr_ptr和group_rr_ptr；
  - per-FE selected valid、grant valid和future valid；
  - ROB valid/result_valid/head/occupancy；
  - retired history valid；
  - next_seq_tag；
  - ppe_retire_output中的start_lane和out_valid。

无效状态下不要求清零宽数据数组。复位期间bkps_q=1，所有fe_in_valid和out_valid=0。

================================================================================
17. 初始实现风险与后续观察项
================================================================================

以下项目不改变首版功能和流水边界，实现后根据编译、仿真和后续时序数据观察：

  1) 四个8项READY bank提名、D2A每bank两项取一和两组固定2x2匹配组合深度；
  2) grant后gather的4个bank-local 8:1 source packet读取、最多4路32:1 active ROB读取
     和history dependency组合深度；
  3) completion/retirement bypass tag比较、优先mux和宽数据扇出；
  4) 奇偶组局部ROB writeback的entry decode和宽数据扇出；
  5) R0连续DONE scan、数据mux和输出旋转的组合深度。

若上述任一项需要改变流水级、pending storage、仲裁语义或查询端口，必须先更新
HLD和LLD，不属于首版RTL编码时的自由选择。

================================================================================
18. LLD不变量
================================================================================

  1) 同一issue entry不得被重复选择或重复派发。
  2) selected entry、FE launch和future预约必须成对建立。
  3) 有效future槽的seq_tag在返回前不得被覆盖。
  4) 依赖未满足时不得被select；ISSUE_SELECTED entry的source和所需依赖读取必须命中。
  5) 依赖查询必须完整匹配seq_tag。
  6) FE返回只设置active ROB result并形成completion事件，不直接写retired history。
  7) Active ROB tag命中但result_valid=0时必须等待，禁止继续查询history。
  8) 退休只从ROB head开始并且只退休连续DONE entry。
  9) 输出寄存器装载、ROB释放和history更新属于同一退休事件。
  10) ROB occupancy必须等于有效ROB entry数量。
  11) 无效宽数据内容不影响任何功能判断。
  12) 同一FE的有效future槽唯一对应一个目标返回周期，D2A不得生成冲突预约，
      D2B不得覆盖有效槽。
  13) 完整seq_tag是唯一跨模块报文身份；allocation、selection、writeback及dependency
      的本地ROB索引必须由对应完整tag低ROB_ID_W位临时导出，不设置ROB ID端口，也不在
      selected pipeline或future table中重复保存ID。Scheduler候选窗按第3.3节保存
      完整seq tag，并仅在entry访问处从低位临时派生物理索引。
  14) candidate_present=1的entry必须处于READY状态并在候选窗中恰好出现一次；
      D2A grant只能消费有效候选项，等待依赖entry不得进入候选窗。
  15) 原始顶层输入只允许写ingress中slot_wr_ptr所选的elastic FIFO输入槽位；槽位写使能
      不得读取原始输入。bkps_o必须由bkps_q直接驱动，input FIFO在任意合法输入和ROB
      停顿序列下不得溢出、丢批或部分接收。

验证必须覆盖ROB occupancy达到32、ROB物理索引31到0回绕、6 bit seq tag从63到0回绕、
依赖目标跨seq回绕，以及退休释放entry与同沿新allocation复用相同物理索引。
