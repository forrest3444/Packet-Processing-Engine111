PPE 功能规格
版本：Draft 1.0
状态：首版 RTL 功能语义已收口

================================================================================
1. 概述
================================================================================

PPE（Packet Processing Engine）接收 N 路并行输入报文，按内部规则分配全局报文
序，解析 per-packet 描述符中的依赖与延迟信息，将报文调度至 Forward Engine（FE）
阵列处理，最终严格按报文序输出。

FE 为黑盒处理单元，其内部算法不属于本规格范围。

================================================================================
2. 接口定义
================================================================================

2.1 系统接口

  信号              方向      位宽              描述
  ───────────────── ──────── ───────────────── ──────────────────────────
  clk               input     1                  时钟
  rst_n             input     1                  异步复位，低有效
  in_valid_i        input     1                  Lane i 输入有效
  in_packet_i       input     128                Lane i 输入报文
  in_desc_i         input     5                  Lane i 描述符
  bkps              output    1                  全局反压
  out_valid_i       output    1                  Lane i 输出有效
  out_packet_i      output    128                Lane i 输出报文

  当前设计侧赛题 N 固定为 4，lane 编号为 0..3。这里的 N 同时表示输入 lane
  数量和输出 lane 数量；二者仅数量相等，不存在输入 lane 与输出 lane 的一一映射
  关系。为支持后续验证侧赛题的抽屉化扩展，验证环境可能进一步支持 N = 4~8。

2.2 FE 接口

  以下信号为单个 FE 的接口规格；FE 阵列中的每个 FE 各自具有一组独立接口。
  clk 和复位由 PPE 与全部 FE 共享，表中仍列出以明确 FE 的时序和复位边界。

  信号              方向      位宽              描述
  ───────────────── ──────── ───────────────── ──────────────────────────
  clk               input     1                 与 PPE 相同的时钟
  rst_n             input     1                 与 PPE 同源的复位
  fe_in_data        output    128               输入报文
  fe_in_valid       output    1                 输入有效
  fe_dep_data       output    128               依赖结果数据（无依赖时为 0）
  fe_dep_valid      output    1                 依赖结果有效
  fe_desc_delay     output    2                 描述符低 2 bit，延迟控制
  fe_out_data       input     128               处理后报文
  fe_out_valid      input     1                 输出有效

  fe_out_data 同时作为该报文的最终输出数据和后续报文可引用的依赖结果，两种用途
  的数据内容一致，不区分端口。PPE必须把每个FE返回与原请求及其全局报文序正确关联。

  约束：
  - 每个 FE 为无阻塞流水线，同一周期最多接收一个报文，但允许多个报文同时在途。
  - FE 接口不使用 ready 信号。fe_in_valid 为单周期脉冲，请求在该周期的时钟
    上升沿被 FE 接收。PPE 只能发送不会造成该 FE 未来输出端口冲突的请求。
  - FE 完成处理时将 fe_out_valid 拉高一个周期，PPE 保证无条件接收该返回。
  - FE 请求在cycle n的上升沿被接收且fe_desc_delay=d时，结果固定在cycle
    n+d+1的上升沿以fe_out_valid返回。delay=0/1/2/3分别对应1/2/3/4周期延迟，
    不允许零周期组合返回。
  - FE 允许在产生fe_out_valid的同一周期继续接收一个新请求。新请求的目标输出
    周期仍按n+d+1计算，并且必须与所有尚未返回请求的目标输出周期不同。
  - 同一 FE 的多个在途请求如果目标输出周期相同，将竞争唯一的fe_out_data/
    fe_out_valid端口。FE不提供ready、拒绝或重放能力；这种输入属于PPE协议违规，
    必须由调度逻辑避免并由验证环境检查。

  首版可综合基线固定包含4个FE。FE数量与N均为4只是当前配置选择，输入lane与FE
  之间仍不存在一一映射关系。扩展其他FE数量不属于首版RTL的参数化保证。

2.3 顶层寄存器边界

  除clk和rst_n外，PPE面向外部环境的所有输入端口必须先由寄存器捕获，后续功能
  逻辑只能使用寄存后的副本。原始in_valid_i、in_packet_i和in_desc_i不得组合参与
  sequence allocation、descriptor解析、容量判断、调度、退休或任何顶层输出
  next-state计算。原始输入只能驱动顶层输入捕获寄存器；空输入批次也只能在捕获后
  根据寄存lane-valid识别并丢弃。

  PPE面向外部环境的所有输出端口必须由寄存器直接驱动，包括out_valid_o、
  out_packet_o以及全局反压bkps。任何内部状态、输入端口或组合选择结果均不得组合
  直通顶层输出。除异步复位断言使输出寄存器进入规定复位值外，所有输出只允许在
  clk有效沿后更新，并在相邻有效沿之间保持稳定；复位释放仍为同步行为。

  因此PPE顶层不得存在普通输入到普通输出的组合路径。当寄存bkps尚未生效时，PPE
  必须通过内部已预留容量吸收所有可能到达的最大宽度输入批次，不得丢包或部分接收。
  被外部接收的报文最早从下一周期开始参与sequence allocation和后续处理。输入缓冲
  的深度、组织和内部流水边界由HLD定义。

  上述寄存器要求仅约束 PPE 顶层输入和输出边界，不约束内部 FE 接口。
  fe_in_* 可由已寄存的输入信息和内部状态组合产生；fe_out_* 到 PPE
  内部状态的路径及寄存级数由设计人员决定。规格不要求 fe_in_* 或 fe_out_* 本身
  必须为寄存器接口。

================================================================================
3. 报文序
================================================================================

PPE 自主分配全局报文序，不依赖输入数据中的任何字段。

分配规则：
  a) 周期优先。后一周期的报文序严格大于前一周期的报文序。
  b) 同周期内，lane 编号递增分配。即 lane 编号较小的报文获得较小的报文序。

示例：当前全局计数器基值为 G，某周期 bkps = 0，且 lane0、lane2、lane3 同时
valid；该寄存批次后续获得内部allocation许可时：
  lane0 → seq = G
  lane2 → seq = G + 1
  lane3 → seq = G + 2
  下一周期基值 = G + 3。

输入 128 bit 数据低 32 bit 可携带调用方自维护的序号信息以辅助 debug，但 PPE
的设计语义不得依赖该字段。

功能语义中的seq视为从0开始无限递增的非负整数。有限位宽编码、回绕处理、内部索引
和身份匹配方法由HLD与LLD定义，但不得改变上述全局顺序或造成相关报文身份混淆。

================================================================================
4. 输入接收与全局反压
================================================================================

PPE 以全局反压信号 bkps 统一控制所有输入 lane。

  bkps = 0：将当前周期所有 valid 为 1 的 lane 作为一个批次捕获到输入寄存缓冲。
  bkps = 1：所有 lane 同时停止接收。上游必须保持各 lane 的 in_valid_i、
            in_packet_i 和 in_desc_i 稳定，直至 bkps 拉低且报文被接收。

bkps 不支持 per-lane 独立反压。bkps 表示PPE已经为下一接收沿的完整N-lane批次
预留接收能力。首版RTL不定义内部异常锁死状态。

外部接收沿只捕获lane valid、packet和descriptor；sequence allocation和descriptor
解析只能基于捕获后的寄存数据。

bkps是寄存输出，复位时置1。bkps next-state只能使用已寄存的输入缓冲状态和内部容量
状态，不得读取当前原始in_valid。bkps=0表示PPE已经为下一接收沿可能出现的任意合法
N-lane批次预留了完整接收能力。由于反压存在寄存反馈延迟，实现必须能够吸收bkps
生效前已经合法到达的完整批次；具体缓冲和容量管理由HLD定义。

================================================================================
5. 描述符
================================================================================

每个报文附带一个 5 bit 描述符，不包含在 128 bit 报文数据内。

  desc[1:0]：延迟参数，送入 FE 控制其内部处理行为。该参数同时影响 FE 的数据
             处理延迟和输出数据内容；同一输入在不同延迟参数下的输出数据可能
             不同。参数到具体延迟周期及输出内容的映射由 FE 定义，PPE 不解释、
             修改或干预该参数。
  desc[4:2]：依赖偏移 dep_offset。0 表示无依赖，1~7 表示依赖前第 K 个报文。

================================================================================
6. 依赖机制
================================================================================

6.1 依赖语义

  报文 P 的报文序为 S，dep_offset = K（K ∈ [1, 7]），则 P 依赖报文序为 S-K
  的报文对应的 FE 内部处理结果。

  依赖满足前，报文不得进入 FE。

  依赖仅取决于全局报文序和 dep_offset，与输入 lane、FE 分配、FE 完成顺序无关。

  正常输入应满足：对于报文序为 S 的报文，dep_offset <= S。若 dep_offset > S，
  则其依赖目标位于本次复位建立的报文序起点之前，属于非法依赖。

  验证环境必须保证不产生非法依赖。PPE不检测或修正超出本次复位后已建立历史范围
  的dep_offset，也不为非法输入定义完成、输出或错误恢复行为。合法输入的依赖目标
  始终直接使用desc[4:2]计算，不存在内部依赖降级。

6.2 依赖结果可见性

  FE返回的fe_out_data从返回沿起成为该报文的依赖结果。PPE必须保证所有合法后续
  报文在进入FE前能够取得与目标报文完全一致的结果，不得因目标报文已经对外输出、
  内部存储复用或FE乱序完成而取得错误结果或丢失结果。

  被依赖结果唤醒的报文最早从下一周期参与FE派发，不允许形成FE completion到另一
  FE输入的同周期组合直通。依赖读取为非破坏性，同一结果允许被多个报文引用，同周期
  多个请求引用同一结果也必须得到一致数据。结果保存结构、生命周期、查询优先级、
  bypass和索引方式由HLD与LLD定义。

================================================================================
7. FE 调度
================================================================================

PPE只能在依赖已经满足且不会违反第2.2节FE接口约束时把报文派发至FE。持续满足
派发条件的报文最终必须进入FE，不得永久饥饿。具体派发宽度、FE选择策略、公平策略、
返回关联结构和冲突规避方法由HLD定义。

派发时 PPE 向 FE 提供：
  - fe_in_data：当前 128 bit 报文
  - fe_dep_data：依赖结果数据（无依赖时为 0）
  - fe_dep_valid：是否有有效依赖
  - fe_desc_delay：desc[1:0]

FE 仅返回一个 128 bit 数据 fe_out_data。PPE 将该数据关联到正确的报文序；
fe_out_data 既作为该报文最终对外输出的数据，也作为该报文供后续依赖使用的
处理结果，两者不是两个独立对象。某个依赖结果在上升沿返回后，等待该结果
的报文最早从下一周期开始参与 FE 派发；规格不要求同周期组合唤醒路径。

================================================================================
8. 保序输出
================================================================================

输出严格按报文序递增顺序提交。即使后序报文先于前序报文完成 FE 处理，也不得
越过前序报文输出。

在报文被接收后未发生复位，且对应 FE 最终返回结果的前提下，每个成功
接收的报文必须恰好输出一次，不丢、不重、不错配、不破序。当前设计不主动丢弃
已接收报文。

================================================================================
9. 输出 Lane 分配
================================================================================

输出 lane 按固定循环顺序使用：lane0 → lane1 → ... → lane(N-1) → lane0 → ...

顶层输出接口没有 ready。某个时钟上升沿 out_valid_i = 1，表示 out_packet_i 在
该上升沿完成一次传输，下游不得拒绝。每个周期的 valid 独立表示一次传输；当同一
lane 在连续周期均有报文时，out_valid_i 可以连续保持为 1，此时每个上升沿传输的
是一个新报文。PPE 不因等待确认而保持或重发报文。out_valid_i = 0 时，
out_packet_i 的值不作要求。out_valid_i 和 out_packet_i 必须来自同一级输出
寄存器并保持周期内稳定。

从尚未输出的最早报文开始，连续已经完成FE处理的报文数记为C。每周期实际输出数必须为：

  K = min(C, N)

只允许输出其中前K个连续已完成报文；不得越过尚未完成的最早报文或中间报文，
也不得在存在连续已完成报文时任意少发。

将前K个报文装入顶层输出寄存器的时钟沿即为这些报文的提交沿。由于顶层输出没有
ready，装入输出寄存器即视为架构上提交，不需要等待额外确认。

PPE 维护输出起始 lane 指针 start_lane。第 j 个输出报文映射到：

  lane = (start_lane + j) mod N，j = 0..K-1

因此同周期报文的逻辑顺序从 start_lane 开始，而不是按物理 lane 编号从小到大
解释；K 个有效 lane 之间不得留洞。本周期映射使用更新前的 start_lane，完成输出
后更新为：

  next_start_lane = (start_lane + K) mod N

K = 0 时 start_lane 保持不变。

同周期输出多个连续报文时，从起始 lane 开始依次映射到后续 lane，到达 lane(N-1)
后从 lane0 继续。复位后起始 lane 为 lane0。

FE在某个上升沿以fe_out_valid返回后，该报文最早从下一周期开始参与外部输出选择；
规格不要求FE返回到顶层输出的同周期直通路径。

================================================================================
10. 复位
================================================================================

复位采用异步拉低、同步释放。外部rst_n拉低时内部复位立即生效；外部rst_n拉高后，
PPE与全部FE在同步释放完成前仍按复位状态处理，并使用同一内部复位域，同时取消
所有在途事务。同步器级数和分发结构由HLD定义。

复位状态下：
  - 取消全部已接收、等待、执行中和已完成但尚未输出的报文；
  - 清空全部依赖结果可见状态；
  - 输出起始 lane 复位为 lane0；
  - 全局报文序计数器归零；
  - bkps 强制为 1；
  - 所有 out_valid_i 强制为 0；
  - 所有 fe_in_valid 强制为 0。

复位期间忽略全部 FE 返回数据。全部 FE 在复位后必须处于 idle，fe_out_valid = 0，
且复位前已接收的请求不得在复位释放后继续返回。valid = 0 时对应 data 的值不作
要求。

复位视为事务中止。复位前已经接收但尚未输出的报文在复位后不保证继续处理或
输出。

================================================================================
11. 异常处理
================================================================================

以下情况属于正常等待或流控，不视为异常：
  a) 依赖目标报文已经接收但其 FE 结果尚未生成；
  b) FE 处理延迟较长；
  c) 内部容量暂时耗尽并通过bkps对输入实施反压。

dep_offset超出本次复位后已经建立的历史范围属于输入协议违规。RTL不检测、不降级，
验证环境必须在输入侧报告该错误。

以下情况属于内部一致性错误：
  a) 报文身份发生冲突或FE返回关联到错误报文；
  b) 合法依赖结果被过早丢弃，导致等待方无法取得结果；
  c) PPE向同一FE派发目标返回周期冲突的请求。

当前规格不定义 FE timeout，因此不得仅因 FE 长时间未返回而触发异常；若后续需要
超时机制，须另行定义可验证的 timeout 周期或参数。

首版 RTL 不定义异常上报、恢复或内部锁死机制。判分验证环境应保证合法输入和
FE 接口协议；内部身份、关联和结果一致性错误由验证侧 assertion、scoreboard
和 timeout 检出。这些检查位于验证用 .sv 文件，不产生可综合的全局异常状态，
不参与 bkps、派发或退休控制。

================================================================================
12. 核心不变量
================================================================================

  1) 报文序由 PPE 内部按周期优先、lane 编号次优先分配。
  2) 输入数据中的任意字段不得作为报文序的设计语义依据；有限编码不得造成相关
     报文身份混淆。
  3) dep_offset = 0 表示无依赖，1~7 表示依赖前第 K 个报文；非零dep_offset必须
     不大于本次复位后排在当前报文之前的报文数量，RTL不实现非法依赖降级。
  4) 依赖未满足时，报文不得进入 FE。
  5) desc[1:0] 传入 FE，同时影响数据处理延迟和输出数据内容，PPE 不干预。
  6) FE 可乱序完成，最终输出必须严格按报文序。
  7) 若最早未输出报文起有C个连续已完成报文，每周期必须输出min(C,N)个；输出
     lane 按固定循环分配，空闲周期不推进指针。
  8) 在未发生复位且 FE 最终返回的前提下，每个成功接收的报文
     恰好输出一次。
  9) bkps 拉高时所有输入 lane 统一停止。
  10) 单个 FE 支持多 inflight；每周期最多接收一个请求，且所有在途请求的目标
      返回周期必须互不冲突。
  11) fe_out_data同时是最终输出数据和依赖结果；所有合法消费者必须取得对应目标
      报文的准确结果。
  12) 复位异步生效、同步释放，并同时取消 PPE 与全部 FE 的在途事务。
  13) 除clk/rst_n外，所有顶层输入必须先寄存再参与任何功能处理；原始输入只能驱动
      输入捕获寄存器，不允许参与bkps或其他顶层输出的组合next-state逻辑。
  14) 所有顶层输出data、valid和bkps必须由寄存器直接驱动，不允许组合逻辑直通端口。
      该寄存器边界要求不适用于内部 fe_in_* 和 fe_out_* 接口。
