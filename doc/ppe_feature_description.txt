PPE 功能规格
版本：Draft 0.9
状态：首版 RTL 功能语义已收口

================================================================================
1. 概述
================================================================================

PPE（Packet Processing Engine）接收 N 路并行输入报文，按内部规则分配全局报文
序，解析 per-packet 描述符中的依赖与延迟信息，将报文调度至 Forward Engine（FE）
阵列处理，最终严格按报文序输出。

FE 为黑盒处理单元，其内部算法不属于本规格范围。

================================================================================
2. 接口定义
================================================================================

2.1 系统接口

  信号              方向      位宽              描述
  ───────────────── ──────── ───────────────── ──────────────────────────
  clk               input     1                  时钟
  rst_n             input     1                  异步复位，低有效
  in_valid_i        input     1                  Lane i 输入有效
  in_packet_i       input     128                Lane i 输入报文
  in_desc_i         input     5                  Lane i 描述符
  bkps              output    1                  全局反压
  out_valid_i       output    1                  Lane i 输出有效
  out_packet_i      output    128                Lane i 输出报文

  当前设计侧赛题 N 固定为 4，lane 编号为 0..3。这里的 N 同时表示输入 lane
  数量和输出 lane 数量；二者仅数量相等，不存在输入 lane 与输出 lane 的一一映射
  关系。为支持后续验证侧赛题的抽屉化扩展，验证环境可能进一步支持 N = 4~8。

2.2 FE 接口

  以下信号为单个 FE 的接口规格；FE 阵列中的每个 FE 各自具有一组独立接口。
  clk 和复位由 PPE 与全部 FE 共享，表中仍列出以明确 FE 的时序和复位边界。

  信号              方向      位宽              描述
  ───────────────── ──────── ───────────────── ──────────────────────────
  clk               input     1                 与 PPE 相同的时钟
  rst_n             input     1                 与 PPE 同源的复位
  fe_in_data        output    128               输入报文
  fe_in_valid       output    1                 输入有效
  fe_dep_data       output    128               依赖结果数据（无依赖时为 0）
  fe_dep_valid      output    1                 依赖结果有效
  fe_desc_delay     output    2                 描述符低 2 bit，延迟控制
  fe_out_data       input     128               处理后报文
  fe_out_valid      input     1                 输出有效

  fe_out_data 同时用于两个目的：
    a) 进入保序输出队列，等待按报文序对外输出；
    b) 作为该报文的依赖结果，在报文退休时写入依赖结果缓存。
  两种用途的数据内容一致，不区分端口；FE 返回时先统一写入对应 ROB entry。

  约束：
  - 每个 FE 同时最多处理一个报文（single-inflight）。
  - FE 接口不使用 ready 信号。PPE 仅在目标 FE 处于 idle 状态时发送请求，
    fe_in_valid 为单周期脉冲，请求在该周期的时钟上升沿被 FE 接收。
  - FE 完成处理时将 fe_out_valid 拉高一个周期，PPE 保证无条件接收该返回。
    FE 从接收请求起保持 busy，直至产生 fe_out_valid；该 busy 状态由 PPE 根据
    请求和返回进行跟踪。
  - FE 请求在周期 T 的上升沿被接收后，fe_out_valid 最早在后续周期的上升沿
    有效，不允许零周期组合返回。FE 返回当周期不接收新请求，最早从下一周期
    重新参与派发。
  - FE 处理延迟不固定，输入到输出的延迟受 fe_desc_delay 影响，但非精确周期
    对应关系，具体特性需通过性能验证摸底。

  FE_NUM 表示 FE 阵列包含的 FE 数量，合法选择范围为 1~32。FE_NUM 是设计人员
  根据吞吐、面积和时序目标选择的微架构参数，不要求等于 N，也不固定为 4。

2.3 顶层寄存器边界

  输入必须经过寄存器打拍。当 bkps = 0 时，PPE 在接收沿将所有有效 lane 的
  in_valid_i、in_packet_i 和 in_desc_i 对应信息捕获到内部寄存器；后续报文序
  分配、ROB 管理及 FE 调度均基于寄存后的信息。顶层输入不得通过组合路径直接
  驱动 FE 输入或顶层输出。被接收的报文最早从下一周期开始参与 FE 派发。

  顶层输出必须为寄存器输出。所有 out_valid_i 和 out_packet_i 均只能由输出
  寄存器驱动，只允许在 clk 上升沿后更新，并在两个相邻上升沿之间保持稳定。
  ROB 状态、FE 返回及内部选择逻辑不得通过组合路径直接驱动顶层输出端口。

  上述寄存器要求仅约束 PPE 顶层输入和输出边界，不约束内部 FE 接口。
  fe_in_* 可由已寄存的输入信息、ROB 状态及调度逻辑组合产生；fe_out_* 到 PPE
  内部状态的路径及寄存级数由设计人员决定。规格不要求 fe_in_* 或 fe_out_* 本身
  必须为寄存器接口。

================================================================================
3. 报文序
================================================================================

PPE 自主分配全局报文序，不依赖输入数据中的任何字段。

分配规则：
  a) 周期优先。后一周期的报文序严格大于前一周期的报文序。
  b) 同周期内，lane 编号递增分配。即 lane 编号较小的报文获得较小的报文序。

示例：当前全局计数器基值为 G，某周期 bkps = 0，且 lane0、lane2、lane3 同时
valid：
  lane0 → seq = G
  lane2 → seq = G + 1
  lane3 → seq = G + 2
  下一周期基值 = G + 3。

输入 128 bit 数据低 32 bit 可携带调用方自维护的序号信息以辅助 debug，但 PPE
的设计语义不得依赖该字段。

功能语义中的 seq 视为从 0 开始无限递增的非负整数。RTL 不要求实现无限位宽，
推荐按以下方式使用有限位宽的模计数器：

  MAX_DEP = 7
  SEQ_W  = $clog2(ROB_DEPTH + MAX_DEP)

RTL seq 按 2^SEQ_W 回绕。严格输出顺序由 ROB 的 head/tail 指针维护，不得使用普通
无符号大小比较推断两个回绕 seq 的先后关系。依赖目标按 SEQ_W 位模减法计算：

  dep_seq = seq - dep_offset

所有按 seq 查找或匹配的结构必须保存并比较完整的 SEQ_W 位 tag；低位索引只能
用于选择候选槽位，不能单独作为命中依据。上述位宽同时覆盖最多 ROB_DEPTH 个
ROB 在途报文，以及 ROB head 之前最多 MAX_DEP 个仍可能被引用的历史结果，从而
保证有限位宽 seq 在整个相关窗口内不会产生身份混淆。

为支持 7-bank 依赖结果缓存，RTL 还必须独立维护 3 bit seq_residue，表示抽象
全局报文序对 7 取模的结果，并按 0→1→...→6→0 循环。seq_residue 不得通过
已经按 2^SEQ_W 回绕的有限位宽 seq_tag 直接计算。每个 ROB entry 同时保存
seq_tag 和 seq_residue。同周期接收多个报文时，二者均按 lane 递增顺序逐一推进。

================================================================================
4. 输入接收与全局反压
================================================================================

PPE 以全局反压信号 bkps 统一控制所有输入 lane。

  bkps = 0：接收当前周期所有 valid 为 1 的 lane 上的报文，并为这些报文分配 seq。
  bkps = 1：所有 lane 同时停止接收。上游必须保持各 lane 的 in_valid_i、
            in_packet_i 和 in_desc_i 稳定，直至 bkps 拉低且报文被接收。

bkps 不支持 per-lane 独立反压。bkps 仅由 ROB 容量不足产生：ROB 空闲条目数
小于当前 valid 输入数时拉高。首版 RTL 不定义内部异常锁死状态。

ROB_DEPTH 必须满足 ROB_DEPTH >= N，保证任意一个 N 路全 valid 的输入批次最终
能够被整体接收。输入接收沿可直接将 packet、descriptor、seq_tag 和 seq_residue
写入新分配的 ROB entry；该 ROB 写入本身满足顶层输入寄存器打拍要求，不强制增加
独立 input FIFO。

当前首版基线中 bkps 为组合输出：

  input_count = popcount(in_valid[0:N-1])
  bkps = !internal_rst_n || (rob_free_count < input_count)

rob_free_count 使用本周期上升沿之前已经空闲的 ROB 条目数，不计入本周期将要退休
释放的条目。该定义允许牺牲满 ROB 边界处的一个周期吞吐，以缩短退休路径到 bkps
的组合时序。

================================================================================
5. 描述符
================================================================================

每个报文附带一个 5 bit 描述符，不包含在 128 bit 报文数据内。

  desc[1:0]：延迟参数，送入 FE 控制其内部处理行为。该参数同时影响 FE 的数据
             处理延迟和输出数据内容；同一输入在不同延迟参数下的输出数据可能
             不同。参数到具体延迟周期及输出内容的映射由 FE 定义，PPE 不解释、
             修改或干预该参数。
  desc[4:2]：依赖偏移 dep_offset。0 表示无依赖，1~7 表示依赖前第 K 个报文。

================================================================================
6. 依赖机制
================================================================================

6.1 依赖语义

  报文 P 的报文序为 S，dep_offset = K（K ∈ [1, 7]），则 P 依赖报文序为 S-K
  的报文对应的 FE 内部处理结果。

  依赖满足前，报文不得进入 FE。

  依赖仅取决于全局报文序和 dep_offset，与输入 lane、FE 分配、FE 完成顺序无关。

  正常输入应满足：对于报文序为 S 的报文，dep_offset <= S。若 dep_offset > S，
  则其依赖目标位于本次复位建立的报文序起点之前，属于非法依赖。

  RTL 可使用一个饱和到 7 的 history_count 实现上述启动阶段检查。
  history_count 表示本次复位后排在当前报文之前的报文数量，并包含同周期内 lane
  编号更小且同时被接收的报文。正常依赖条件为 dep_offset <= history_count。
  计数器达到 7 后保持为 7，不受内部 seq 回绕影响。

  验证环境应保证不产生非法依赖。作为防御性处理，若检测到
  dep_offset > history_count，PPE 将该报文的内部 effective_dep_offset 置为 0；
  否则 effective_dep_offset = dep_offset。降级后的报文按
  无依赖报文继续接收、调度和输出；desc[1:0] 保持不变。降级后派发至 FE 时
  fe_dep_valid = 0、fe_dep_data = 0。

6.2 依赖结果缓存

  PPE 维护 7 个依赖结果 bank，bank 编号为 0..6。每个 bank 固定保存
  seq_residue 等于该 bank 编号的已退休报文结果。每个 bank entry 至少包含：
    - valid；
    - 完整 SEQ_W 位 seq_tag；
    - 128 bit result_data。

  FE 返回时，fe_out_data 先写入对应 ROB entry，并设置该 entry 的 result_valid；
  FE 乱序完成不得直接覆盖 result bank。

  报文查找依赖目标时：
    a) 若目标 seq_tag 对应的 entry 仍在 ROB 中，则从该 ROB entry 读取结果；若其
       result_valid 尚未置位，当前报文继续等待，不得转而使用 result bank 中的
       同 residue 历史结果。
    b) 若目标报文已经从 ROB 退休，则以 target_residue 选择 result bank，并要求
       bank.valid = 1 且 bank.seq_tag 与 target_seq_tag 完整匹配后方可使用。

  target_seq_tag 由当前 seq_tag 减 effective_dep_offset 得到；target_residue
  由当前 seq_residue 减 effective_dep_offset 并按模 7 回绕得到。当
  effective_dep_offset = 7 时，target_residue 与当前 seq_residue 相同。

  报文装入顶层输出寄存器时视为从 ROB 退休。退休沿同时将该报文的 fe_out_data
  写入 result_bank[seq_residue]，随后释放 ROB entry。由于退休严格按 seq 顺序，
  当 R+7 退休并覆盖 R 所在 bank 时，所有可能依赖 R 的报文 R+1..R+7 均已退休，
  因此覆盖是安全的。

  当前设计 N = 4，同周期退休的连续报文不会写入同一 bank。未来 N 扩展至 8 时，
  若同周期多个退休报文映射到同一 bank，仅执行其中 seq 较新的写入。

  读取为非破坏性。同一结果可被多个后续报文引用；同周期多个 FE 请求相同依赖
  结果时允许读取一次并广播给多个 FE。

================================================================================
7. FE 调度
================================================================================

PPE 在满足以下全部条件时将报文派发至 FE：
  1) effective_dep_offset = 0，或其依赖结果已在 ROB/result bank 中有效；
  2) 存在空闲 FE。

每周期最大派发数 ISSUE_WIDTH 的合法范围为 1..FE_NUM，由微架构选择。调度策略
不要求每周期占满全部空闲 FE，但必须保证持续处于可派发状态的报文最终能够进入
FE，不得产生永久饥饿。

派发时 PPE 向 FE 提供：
  - fe_in_data：当前 128 bit 报文
  - fe_dep_data：依赖结果数据（无依赖时为 0）
  - fe_dep_valid：是否有有效依赖
  - fe_desc_delay：desc[1:0]

FE 仅返回一个 128 bit 数据 fe_out_data。PPE 将该数据关联到正确的报文序；
fe_out_data 既作为该报文最终对外输出的数据，也作为该报文供后续依赖使用的
处理结果，两者不是两个独立对象。某个依赖结果在上升沿写入 ROB 后，等待该结果
的报文最早从下一周期开始参与 FE 派发；规格不要求同周期组合唤醒路径。

================================================================================
8. 保序输出
================================================================================

输出严格按报文序递增顺序提交。即使后序报文先于前序报文完成 FE 处理，也不得
越过前序报文输出。

在报文被接收后未发生复位，且对应 FE 最终返回结果的前提下，每个成功
接收的报文必须恰好输出一次，不丢、不重、不错配、不破序。当前设计不主动丢弃
已接收报文。

================================================================================
9. 输出 Lane 分配
================================================================================

输出 lane 按固定循环顺序使用：lane0 → lane1 → ... → lane(N-1) → lane0 → ...

顶层输出接口没有 ready。某个时钟上升沿 out_valid_i = 1，表示 out_packet_i 在
该上升沿完成一次传输，下游不得拒绝。每个周期的 valid 独立表示一次传输；当同一
lane 在连续周期均有报文时，out_valid_i 可以连续保持为 1，此时每个上升沿传输的
是一个新报文。PPE 不因等待确认而保持或重发报文。out_valid_i = 0 时，
out_packet_i 的值不作要求。out_valid_i 和 out_packet_i 必须来自同一级输出
寄存器并保持周期内稳定。

从 ROB head 开始连续处于 DONE 状态的报文数记为 C。每周期实际输出数必须为：

  K = min(C, N)

只允许输出从 ROB head 开始的前 K 个连续 DONE 报文；不得越过尚未 DONE 的 head
或中间报文，也不得在有连续 DONE 报文时任意少发。

将前 K 个报文装入顶层输出寄存器的时钟沿即为这些报文的退休沿。由于顶层输出
没有 ready，装入输出寄存器即视为架构上提交，不需要等待额外确认。该退休沿同时
推进 ROB head、释放对应 ROB entries，并将其结果写入 7-bank 依赖结果缓存。

PPE 维护输出起始 lane 指针 start_lane。第 j 个输出报文映射到：

  lane = (start_lane + j) mod N，j = 0..K-1

因此同周期报文的逻辑顺序从 start_lane 开始，而不是按物理 lane 编号从小到大
解释；K 个有效 lane 之间不得留洞。本周期映射使用更新前的 start_lane，完成输出
后更新为：

  next_start_lane = (start_lane + K) mod N

K = 0 时 start_lane 保持不变。

同周期输出多个连续报文时，从起始 lane 开始依次映射到后续 lane，到达 lane(N-1)
后从 lane0 继续。复位后起始 lane 为 lane0。

FE 在某个上升沿以 fe_out_valid 返回的数据先写入 ROB，该报文最早从下一周期开始
参与外部输出选择；规格不要求 FE 返回到顶层输出的同周期直通路径。

================================================================================
10. 复位
================================================================================

复位采用异步拉低、同步释放。外部 rst_n 拉低时，内部复位立即生效；外部 rst_n
拉高后，通过两级同步器同步释放内部复位。在同步释放完成前，PPE 与全部 FE 仍按
复位状态处理。PPE 与全部 FE 必须使用同一内部同步复位，保证复位同时取消所有
在途事务。

复位状态下：
  - 清空所有 ROB 条目及关联状态；
  - 清空依赖结果缓存；
  - 清空 FE 调度状态（busy flag、tag）；
  - 输出起始 lane 复位为 lane0；
  - 全局报文序计数器归零；
  - bkps 强制为 1；
  - 所有 out_valid_i 强制为 0；
  - 所有 fe_in_valid 强制为 0。

复位期间忽略全部 FE 返回数据。全部 FE 在复位后必须处于 idle，fe_out_valid = 0，
且复位前已接收的请求不得在复位释放后继续返回。valid = 0 时对应 data 的值不作
要求。

复位视为事务中止。复位前已经接收但尚未输出的报文在复位后不保证继续处理或
输出。

================================================================================
11. 异常处理
================================================================================

以下情况属于正常等待或流控，不视为异常：
  a) 依赖目标报文已经接收但其 FE 结果尚未生成；
  b) FE 处理延迟较长；
  c) ROB 暂时耗尽并通过 bkps 对输入实施反压。

若报文的 dep_offset 超出本次复位后已经建立的历史范围，按第 6.1 节将其依赖降级
为无依赖并继续处理，不视为内部一致性错误。验证环境仍应避免产生此类输入。

以下情况属于内部一致性错误：
  a) ROB entry 的 valid、tag 或 seq 发生冲突；
  b) 合法依赖结果被过早覆盖，导致等待方无法取得结果；
  c) FE 返回与当前记录的 busy/tag 状态不一致。

当前规格不定义 FE timeout，因此不得仅因 FE 长时间未返回而触发异常；若后续需要
超时机制，须另行定义可验证的 timeout 周期或参数。

首版 RTL 不定义异常上报、恢复或内部锁死机制。判分验证环境应保证合法输入和
FE 接口协议；ROB/tag/writeback 等内部一致性错误由验证侧 assertion、scoreboard
和 timeout 检出。这些检查位于验证用 .sv 文件，不产生可综合的全局异常状态，
不参与 bkps、派发或退休控制。

可综合 RTL 可对写回使用 valid 和完整 seq_tag 匹配作为轻量写保护，但匹配失败
不设置 sticky 异常状态。正常协议下该匹配必须恒成立。

================================================================================
12. 核心不变量
================================================================================

  1) 报文序由 PPE 内部按周期优先、lane 编号次优先分配。
  2) 输入数据中的任意字段不得作为报文序的设计语义依据。
     RTL seq 可按规定的 SEQ_W 回绕，但相关窗口内的 tag 匹配不得产生混淆。
  3) dep_offset = 0 表示无依赖，1~7 表示依赖前第 K 个报文；超出已建立历史范围
     的依赖降级为无依赖。
  4) 依赖未满足时，报文不得进入 FE。
  5) desc[1:0] 传入 FE，同时影响数据处理延迟和输出数据内容，PPE 不干预。
  6) FE 可乱序完成，最终输出必须严格按报文序。
  7) 若 ROB head 起有 C 个连续 DONE 报文，每周期必须输出 min(C, N) 个；输出
     lane 按固定循环分配，空闲周期不推进指针。
  8) 在未发生复位且 FE 最终返回的前提下，每个成功接收的报文
     恰好输出一次。
  9) bkps 拉高时所有输入 lane 统一停止。
  10) 单个 FE 不支持多 inflight。
  11) fe_out_data 返回时先写 ROB；报文退休时再写入对应的 7-bank 依赖结果缓存。
  12) 复位异步生效、同步释放，并同时取消 PPE 与全部 FE 的在途事务。
  13) 顶层输入必须先寄存再参与内部处理，不允许从顶层输入组合直通 FE 或输出。
  14) 所有顶层输出 data/valid 必须由寄存器驱动，不允许内部状态组合直通端口。
      该寄存器边界要求不适用于内部 fe_in_* 和 fe_out_* 接口。
