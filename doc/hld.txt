PPE High-Level Design
版本：Draft 0.4
状态：首版 RTL 系统架构与流水边界已收口

本文档描述 PPE 的系统架构、模块职责、状态所有权、主要数据流和流水级边界。

文档层级：

  1) doc/ppe_feature_description.txt：功能语义和外部行为；
  2) doc/hld.txt：系统架构、模块边界和高层流水；
  3) doc/lld.txt：内部接口、数据结构、状态机和逐周期行为；
  4) RTL：按照上述文档实现。

若不同层级发生冲突，应先从较高层文档澄清设计意图，再同步更新下层文档和实现。

================================================================================
1. 设计目标与基线配置
================================================================================

PPE按状态所有权划分为以下主要逻辑模块：

  1) ppe_top：顶层集成及FE阵列例化；
  2) ppe_ingress：两项elastic batch FIFO、寄存bkps、报文序分配、依赖目标预计算和allocation bundle生成；
  3) scheduler：issue table、依赖等待、候选选择、FE匹配、operand gather和返回日历；
  4) backend：ROB、FE写回、依赖结果解析、保序退休、history和内部allocation容量判断。

SystemVerilog实现可将scheduler和backend中的状态所有者、纯组合选择器进一步拆为独立
文件，但不得因此形成多模块共同写同一状态数组。具体文件和接口在LLD中定义。

第一版基线配置：

  N            = 4
  FE_NUM       = 4
  MAX_DEP      = 7
  ISSUE_WIDTH  = 4
  ROB_DEPTH    = 32
  ISSUE_DEPTH  = 32
  ROB_ID_W     = 5
  SEQ_W        = 6
  RTL_LANGUAGE = SystemVerilog

共享基线配置由ppe_types_pkg统一定义，跨模块使用且必须保持一致的结构参数不得在子模块
例化处重复硬编码。ISSUE_DEPTH由ROB_DEPTH派生，ISSUE_WIDTH由FE_NUM派生；ROB_ID_W、
SEQ_W和history索引宽度继续由基础配置推导。只有直接定义可复用模块端口数据宽度的
PACKET_W/DESC_W保留为模块参数，并由顶层统一向下传递。模块私有存储深度和计数器宽度
使用localparam，不向外暴露。

新架构可综合RTL位于rtl-sv目录，使用.sv文件和可综合SystemVerilog语法。现有rtl目录
中的Verilog-2001实现保留为旧基线参考，不作为新架构内部接口和模块所有权的来源。

1.1 设计优化优先级

功能正确性是硬门槛。在功能正确的前提下，性能是首要优化方向，重点保持 FE 利用率、
多发射能力、多退休能力，并避免不必要的停顿和过长的关键组合路径。

功耗和面积作为辅助收敛目标，主要通过减少无效翻转、避免重复宽数据存储、合理使用
寄存器使能、清晰划分状态所有权以及遵循可综合编码规范进行控制。

当前环境不使用定量评分模型指导编码取舍。缺少工具数据时，PPA 判断仅作为定性分析，
不得为了未经验证的功耗或面积收益主动牺牲明确的吞吐能力。

1.2 阶段性时序目标

当前Nangate45比较环境的系统级阶段性目标频率固定为350 MHz，对应时钟周期2.857 ns。
该目标用于前端综合和pre-CTS布局后的相对收敛判断，不代表公司工艺签核结论。默认使用
typical Liberty、0.050 ns时钟不确定度和0.200 ns输入输出延迟，并在报告中明确寄生参数
模型和时钟阶段。

为给跨模块连线、setup和后续时钟实现保留余量，scheduler各寄存边界之间的数据到达
时间以不超过2.3 ns为局部优化目标；超过2.5 ns的单级路径必须进入结构复审。局部目标
是设计预算而非功能语义，不得通过降低多发射吞吐、取消公平性或改变FE返回冲突规则
换取时序。新增流水边界时必须同步本HLD和LLD中的逐周期定义。

2. 系统框图
================================================================================

                               ppe_top
  +------------------------------------------------------------------------+
  |                                                                        |
  |  Top Inputs                                                            |
  |       |                                                                |
  |       v                                                                |
  |  +-------------+      +---------------------------+                    |
  |  | ppe_ingress |----->|         scheduler         |                    |
  |  | skid/bkps   |      | issue / wakeup / matching |                    |
  |  +------+------+      | gather / return calendar  |                    |
  |         |             +-------------+-------------+                    |
  |         | allocation metadata       | FE requests                      |
  |         |                           v                                  |
  |         |                FE0 / FE1 / FE2 / FE3                         |
  |         |                           | completion + tag                  |
  |         v                           v                                  |
  |  +------------------------------------------------------------------+  |
  |  |                           backend                                |  |
  |  |  ROB: allocation / writeback / dependency resolve / retire      |  |
  |  |       active results / bypasses / 8-bank retired history        |  |
  |  |  retire_output: lane mapping / registers / start-lane rotation  |  |
  |  +---------------------------+--------------------------------------+  |
  |                              +--> allocation ready / output             |
  |  ingress registered bkps ------------------------------------------->  |
  +------------------------------------------------------------------------+

主数据流：

  Top Input -> Ingress -> Scheduler -> FE Array -> Backend ROB -> Registered Output

主要控制回馈：

  Backend -> Ingress：基于注册请求批次的内部allocation ready
  Ingress -> Top/Input：寄存全局bkps
  Top Input -> Ingress：仅连接输入捕获寄存器
  Backend -> Scheduler：依赖满足状态、依赖结果数据和retirement事件
  Scheduler -> Backend：分配metadata、依赖目标请求和FE writeback关联信息

================================================================================
3. 模块职责与状态所有权
================================================================================

3.1 ppe_top

ppe_top 保持轻量，负责：

  - 例化ingress、scheduler、ppe_rob、ppe_retire_output和4个FE；
  - 顶层外部输入/输出lane和SystemVerilog内部重复lane/FE通路均使用有明确字段含义的
    packed array表达，不展开固定编号的独立lane端口；
  - 实现唯一的两级复位同步器，将异步拉低、同步释放的内部复位同时分发给
    全部PPE子模块和FE；
  - 将ppe_retire_output的寄存器输出连接到顶层端口。

ppe_top 不保存报文级状态，不参与报文序、依赖或保序决策。

3.2 ppe_ingress

ppe_ingress负责：

  - 顶层输入批次准入和两项整批elastic FIFO；
  - 生成并保存寄存全局bkps；
  - 有效lane rank计算和密集seq tag分配；
  - 从完整seq tag预计算target seq tag；
  - 将输入descriptor解码为delay和dep_required语义字段；
  - 向ROB形成寄存head request/metadata，并向issue table形成同一被接受allocation
    事件的valid和seq metadata。

ppe_ingress拥有两项输入批次槽位、读写指针、占用计数、bkps寄存器和next_seq_tag。两项
槽位同时承担顶层输入寄存和有序FIFO存储，不设置独立capture数据副本。它不拥有ROB容量、等待
状态、依赖结果或FE调度状态。
完整seq tag是allocation的唯一跨模块身份；issue table和backend分别从其低位派生本地
物理索引。History bank索引直接从完整seq tag低3位派生，ingress不产生、不输出独立
ROB ID或residue字段。

两项输入FIFO按固定深度结构实现：沿后占用由capture/head release组合更新，宽
packet/descriptor存储采用bank-local写使能，避免动态bank写索引进入宽寄存器使能路径。
固定N=4配置下，lane rank和有效报文计数采用平衡的小位宽前缀网络；这些实现策略不改变
I0/D0寄存边界、整批准入语义或allocation吞吐能力。

3.3 scheduler

scheduler管理尚未进入FE的报文，负责：

  - 等待依赖和等待 FE 的报文管理；
  - 接收沿依赖状态初始化和FE completion tag唤醒；
  - 4个局部READY bank、每bank两项候选缓冲和多路FE选择；
  - per-FE 6项相对未来返回表及返回tag关联；
  - 最多4路权威依赖结果gather控制；
  - 将FE completion关联为带完整seq tag的writeback事件。

Scheduler只拥有报文进入FE之前的调度状态。报文成功进入FE后，长期顺序和输出
状态继续由backend ROB保存。

其中ppe_issue_table拥有32项窄issue metadata、32-bit候选成员位图和4组两项本地候选缓冲。
Completion并行比较32项窄target tag，只更新沿后的entry状态，不组合进入READY提名。
READY entry按ROB ID低2位分为4个交错bank，每个bank从8项中每周期至多提名1项，
并写入该bank的空闲候选槽；不存在全局空槽compact、跨bank候选重排或refill plan。

ppe_fe_scheduler拥有两级D2、每bank两项取一的组合预选、静态4x4单轮匹配网络、per-FE
6项相对未来返回移位表以及FE公平轮询指针。D2A0组合预选与D2A1固定匹配共同构成
一个窄控制流水级，末端只捕获不可撤销grant；D2B下一周期提交grant并写返回表。
D2A必须屏蔽仍未由D2B提交的grant，避免相邻周期重复选择。FE返回时以每个FE返回表
的当前项保存的完整tag形成completion事件。
FE的128 bit结果数据不经过该控制模块，直接连接ROB。

ppe_fe_scheduler按FE编号向ppe_issue_table返回一次不可撤销的候选槽one-hot。ppe_issue_table
从本地候选槽取得完整seq tag并保存每个FE的selected metadata，下一周期形成D3 bundle，
随后在FE接收沿释放旧entry。完整seq tag仍是报文跨状态结构的唯一身份，候选槽one-hot只在
相邻D2B接口用于删除已确认候选。D3原始packet和依赖data均由ROB按该metadata并行读取。D0 status query、
completion完整tag唤醒比较和D3 dependency请求资格归ppe_issue_table管理；所有本地
ROB ID从完整tag低位临时派生。

3.4 ppe_rob

ppe_rob是全局顺序、结果和容量状态的唯一所有者，负责：

  - ROB allocation、head/occupancy和严格按序的逻辑retirement prefix；
  - allocation原始packet保存和D3 source packet读取；
  - FE completion 写回；
  - completion bypass、retirement bypass、active ROB和retired history四级依赖解析；
  - 8-bank已退休history生命周期管理；
  - 根据注册的输入FIFO头批次和沿前空闲credit生成内部allocation ready。

ppe_rob不保存物理输出lane状态，也不直接驱动顶层输出寄存器。它向ppe_retire_output输出
按报文序排列、从slot 0开始无空洞的逻辑retirement bundle。

固定ROB_DEPTH=32、N=4实现将128 bit统一data按ROB ID低2位组织为4个bank，每个bank含
8项；valid和result_valid作为独立小位宽metadata阵列。完整seq_tag的低5位由entry
物理索引隐含，ROB entry仅保存高位generation；所有命中仍等价检查完整seq_tag。
Allocation把
原始packet写入data并清result_valid；FE completion原址覆盖data并置result_valid。
为切断退休容量计算到宽data阵列写使能的路径，A0在allocation沿更新metadata并按低2位
bank捕获原始packet，A1下一沿提交到对应data bank。密集seq tag保证一个allocation批次
对每个bank至多一写；A1在最早D3读取前完成，不增加输入到FE的流水延迟。
Allocation容量判断不组合借用本周期retirement prefix释放的entry；退休释放的credit在
下一周期通过occupancy可见。该保守边界切断retirement scan到allocation metadata的路径，
满载后首次释放可能产生一个allocation停顿，但稳态retire与allocate仍可同周期持续执行。
四路writeback共享低位entry decode，并在entry本地完成完整tag资格检查和数据选择。
不得以动态宽数组写索引生成覆盖全部data存储的写数据网络。连续4项退休先从每个bank
各读取一个8项窗口，再按head低2位通过固定两级置换恢复逻辑顺序。该物理组织不改变
ROB ID、同周期四路任意写回、active dependency读取或退休周期语义。
Scheduler每周期从每个READY bank最多发射一项，且READY bank等于报文seq_tag低2位，
因此D3 source packet读取按4个data bank各执行一次8:1 row选择，再按请求所属FE进行
固定小规模路由；不复制四份独立32:1 source读取。该约束只适用于报文本身的source
读取，dependency target仍允许同bank冲突并保持最多4路任意地址读取。
依赖查询采样沿前，retirement prefix仍是有效且result_valid的active ROB entry，因此
retirement bypass与active读取数值相同；实现将二者折叠为一条active读取，避免把head
比较广播到D0/D3，同时保持completion、retirement/active、history的可见性顺序。

3.5 ppe_retire_output

ppe_retire_output是backend功能域内独立的最终输出子模块，负责退休结果的外部呈现：

  - 将逻辑retirement bundle按当前start_lane映射到物理输出lane；
  - 保存并更新start_lane；
  - 驱动同一级顶层out_valid/out_packet寄存器。

ppe_retire_output不封装ppe_rob，也不转发allocation、依赖查询或writeback接口。
ppe_top分别例化并连接两者。该拆分不增加ready或额外流水级；ROB状态释放、history
写入、输出寄存器装载和start_lane更新仍发生在同一个退休上升沿。

================================================================================
4. 高层数据流
================================================================================

4.1 输入接收

当寄存bkps允许接收时，ingress只把当前所有lane的valid、packet和descriptor写入
两项elastic FIFO的寄存tail槽位，不在该沿执行sequence allocation、空批判断或ROB容量
计算。FIFO保持批次顺序；下一周期起，寄存head为空批时直接释放，非空head获得backend
内部allocation ready后，ingress才计算密集seq tag和dependency
target，并在同一内部allocation沿送入Issue Table和ROB。完整descriptor不离开ingress；
scheduler只接收delay和dep_required。一次输入周期必须整体接收或整体停止，禁止部分lane接收。

4.2 依赖处理

无依赖报文可以直接进入READY状态。有依赖的报文以完整target seq tag查询backend
提供的依赖满足状态；目标结果尚未完成时进入ISSUE_WAIT_DEP，已经完成时进入ISSUE_READY。
初始化查询只读取小位宽valid/tag/result_valid状态，不复制128 bit依赖数据。

输入协议保证dep_offset不超出本次复位后已经建立的历史范围。Ingress使用输入FIFO
寄存head中保存的dep_offset预计算依赖目标，不保存历史计数器，也不检测或降级非法依赖。

Scheduler维护小位宽dependency状态。FE completion并行检查ISSUE_WAIT_DEP entry的完整
target tag；该路径只读取窄控制metadata，不访问packet或依赖结果数据。
Completion bypass允许同一接收沿的新entry识别该completion，被唤醒报文只能从下一周期
开始参与D2A。D3对最多4个ISSUE_SELECTED依赖报文从backend执行权威数据gather，
依次检查completion bypass、retirement bypass、active ROB和8-bank retired history。
依赖宽数据不复制到所有issue entry中，也不存在fast-cache、fallback或replay状态。

4.3 FE 调度

ISSUE_READY报文不按delay分类，也不进入严格年龄队列。Issue Table按ROB ID低2位形成
4个8项交错bank，每个bank拥有两个固定候选槽：槽bank保存way0，槽4+bank保存way1。
当本地候选槽存在沿前空位或被D2B删除时，该bank从8项READY entry中轮询提名至多1项，
直接在本沿写入空闲槽。每bank每周期最多补入一项，不存在全局空槽compact、跨bank
候选重排、动态计数树或refill plan。两个本地槽覆盖D2A/D2B在途周期，使连续流量下
每bank仍可逐周期提供一个不同候选。

Completion只在本沿把匹配的ISSUE_WAIT_DEP entry更新为ISSUE_READY；READY提名只读取
沿前issue state，因此被唤醒entry最早下一周期进入本地候选槽。D0 allocation同样只在
本沿初始化entry，最早下一周期参与提名。candidate_present覆盖8个本地候选槽，防止
同一entry重复提名；D2B删除与本地补充在同沿合并。

调度器从每个bank的两个候选槽中轮转选择至多1项，屏蔽仍处于D2B的pending grant，
形成固定4项shortlist，再建立4x4 FE legal matrix。一个bank、一个候选和一个FE在
每周期均最多获得一次grant。该策略允许bank内乱序和候选到FE的动态映射，但不允许
同一bank同周期双发；它以有限分区损失换取固定的8选1提名、2选1预选和规则物理结构。

FE本身是固定1~4周期延迟的无阻塞流水线，每周期最多接收一个请求，并允许输入和
输出同周期发生。Scheduler维护per-FE 6项相对未来返回移位表。D2A1按请求delay计算
D3发射后的目标返回周期，只能选择正式future项和当前grant虚拟预约均未占用的FE；
D2B下一周期提交候选槽one-hot并写入完整seq_tag。Issue table为每个FE设置一份D2B到
D3 selected-metadata寄存器；无冲突流量下D2A、D2B和D3可分别处理相邻三批请求，每个FE仍
可以逐周期接收请求。

返回表每周期向当前返回项移位。沿前slot0对应本沿返回，slot1..5对应随后1..5个沿；
本沿D2B grant在沿后写slot[delay+1]。D2A1对delay 0..2的
合法性分别检查沿前slot3..5；delay 3的目标比沿前已存在预约最远再远一沿，因此天然
为空。六项是该两级D2流水和最长FE延迟所需的最小相对窗口。合法选择保证D3权威依赖gather必定available；D3不以
gather响应设置ready、取消或重放通路。依赖未available属于内部状态不一致，验证侧
必须报错。

4.4 FE 写回

每个FE通过scheduler返回日历当前周期槽保存的ROB tag将结果写回对应ROB entry。
FE可以乱序完成，但completion只写active ROB并形成tag wakeup/bypass事件，不写retired
history，也不得绕过ROB直接输出。

4.5 保序退休

ppe_rob从ROB head开始退休最多4个连续DONE报文，并向ppe_retire_output提供无空洞的逻辑
退休前缀。退休事件同时完成：

  - ppe_retire_output将结果映射并装入顶层输出寄存器；
  - 更新8-bank retired history；
  - 释放 ROB entry；
  - 推进ROB head，并由ppe_retire_output推进输出lane指针。

严格保序可能产生 head-of-line blocking，这是功能要求。调度策略应避免无必要地延迟
接近 ROB head 的可派发报文。

4.6 全局反压

bkps由ingress寄存器直接驱动，任何原始顶层输入或ROB状态均不得组合直通该端口。
两项elastic FIFO槽位直接终止所有原始输入，总计提供两批物理容量。bkps next-state
只根据寄存占用、当前bkps状态和寄存head是否将在本沿释放计算；不读取任何当前原始输入。

Backend仍根据ROB沿前空闲容量与本周期连续DONE退休数量，对已经寄存的head批次
产生精确内部allocation ready。因此内部allocation仍可在同一上升沿复用退休空间，且当
ROB持续每周期退休4项、FIFO持续非空时，可保持4-wide内部allocation和外部连续接收。
当bkps_q=0时，tail capture和head release允许同沿发生，因此连续可分配流量不产生结构
气泡。若capture后两槽占满，则下一拍bkps拉高；满状态中的head释放后，bkps在下一有效沿
重新拉低。相较三批结构，本方案减少一批宽数据存储和一级搬移选择，代价是依赖重载或ROB
停顿时更早施加反压；不得以此为由降低内部4-wide allocation能力。

同址 retirement 与 allocation 可以在同一上升沿发生。retirement 使用沿前 ROB
内容产生输出并更新retired history，allocation对沿后ROB entry状态具有优先权，
从而使该 entry 立即代表新报文且 result 尚未有效。

================================================================================
5. 初步流水线划分
================================================================================

5.1 Ingress与Scheduler主流水

输入到FE发射划分为六个寄存边界阶段，并包含一条并行依赖事件通路：

  I0：External Input Capture
      在寄存bkps允许时将完整原始输入无条件写入两项elastic FIFO的tail槽位；
      不执行功能解析或capture到FIFO的数据搬移。

  D0：Input Admission / Allocation
      对elastic FIFO寄存head执行空批释放、顺序分配、依赖目标预计算和
      ROB/issue-table allocation。

  D1：Bank-local READY Nomination
      四个8项bank并行各提名至多1项，写入本bank两项候选缓冲；D0 allocation和
      本周期completion wakeup不得组合进入提名。

  D2A：Candidate Shortlist / Static FE Match
      组合D2A0从每bank两个候选中轮转提取至多1项，组合D2A1执行固定4x4单轮匹配，
      本级末端只锁存不可撤销grant。shortlist不单独打拍，也不是架构选择。

  D2B：Return-slot Commit / Issue Select
      将上一周期grant的候选槽one-hot原子提交到Issue Table selected流水，并把返回预约
      写入相对未来表；本级没有ready或rollback。

  D3：Operand Read / FE Issue
      从ROB读取launch原始报文，通过同一ROB四级权威解析读取最多4路依赖数据，并完成FE路由。

  Dependency Event Path：
      D0以active ROB/history状态及completion/retirement bypass初始化entry；后续
      completion tag唤醒ISSUE_WAIT_DEP entry。该通路不增加输入流水级，也不允许同沿直通FE。

D2A、D2B和D3必须保持逻辑分离。READY发现和队列入队不进入匹配关键路径；D2A0
组合8取4和D2A1固定4x4网络之间不设置寄存边界，D2A末端只捕获grant。D2B只提交
selection与返回预约，D3再读取宽报文与依赖数据。

5.2 Backend并行通路

Backend不采用单一线性流水，而是包含四条并行通路：

  A0/A1：ROB Metadata Allocation / Bank-local Packet Commit
  G0：Dependency Status / Data Gather
  W0：FE Writeback
  R0：In-order Retire / Registered Output

A0、G0、W0和R0可以在同周期处理不同ROB entry。它们共享的ROB状态必须由统一
状态所有权和 next-state 逻辑协调。

5.3 高层流水关系

  Input I0 -> D0 -> D1 -> D2A -> D2B -> D3 -> FE(fixed delay + 1 cycles)
                  |
                  v
          Backend W0 -> R0 -> Output Registers

  Backend A0与Input D0并行工作；A1只提交上一沿已经接受的bank-local packet，
  不改变Issue Table可见的allocation时刻。
  Backend G0为D0提供最多4路小位宽available状态，并为D3提供最多4路128 bit依赖数据。
  G0按completion bypass、retirement bypass、active ROB、retired history优先级解析。

================================================================================
6. 高风险路径与可优化点
================================================================================

6.1 FE 服务能力

4个FE均支持无阻塞流水，每个FE理论上可逐周期接收请求，但同一FE的目标输出周期
不得冲突。6项相对返回表和可同周期消费/重填的selected-metadata寄存器释放FE流水吞吐；实现后
重点检查混合delay造成的槽碎片、D2A匹配效率以及长流下是否接近4路持续issue。

6.2 D2A 多发射仲裁

8项候选按way组织为{way0[bank0..3], way1[bank0..3]}。组合D2A0对每个bank屏蔽pending
grant后执行固定2选1，并按本地way轮询避免单槽长期阻塞；shortlist槽号固定等于bank号。
FE轮转起点仅在产生grant后推进。D2A1只建立固定4x4 legal
matrix：候选按错位FE优先级并行提名，再按候选优先级接受。该网络不保证任意稀疏
矩阵的最大匹配，但必须在全合法矩阵下
达到4-wide，且不得包含动态数组索引或跨四轮greedy依赖。返回预约在D2B使用寄存grant
提交；D2A1合法性检查必须把当前grant视为虚拟预约。

6.3 D3 宽数据路径

D3正常路径包含ROB source packet选择、最多4路active ROB/history权威依赖读取以及
4路FE数据路由。source packet与active dependency结果共享ROB统一data存储，但使用
独立的读请求语义。Source请求继承scheduler的每bank最多一项发射不变量，使用4个共享
bank-local 8:1读取后路由到FE；active dependency目标bank可以冲突，仍保持每路独立
读取语义。两类读取都由完整tag低ROB_ID_W位索引，并以保存的tag高位确认完整身份。
history由target seq tag低3位索引并比较完整tag。这些宽mux可能成为关键路径，ROB扩深
带来的吞吐收益必须与其时序代价一并评估。

6.4 G0多路依赖读取

G0需要在同周期支持最多4个已选依赖报文的数据解析，并允许同一结果向多个FE广播。
Completion和retirement bypass均先做小位宽ID/tag比较，再选择128 bit数据。若综合结果
表明4路ROB/history读取限制频率，可以在保持每周期4路吞吐的前提下增加gather流水级，
但必须同步更新返回日历预约距离和LLD周期定义。

6.5 W0 多路写回

W0必须无条件接收最多4路任意seq tag写回，并从tag低位派生本地ROB写地址。不得依赖单写端口存储或通过反压FE解决。
多路地址decode和宽数据扇出是主要实现风险。
固定基线使用共享小位宽decode生成per-entry one-hot commit；每个result entry只在自身
commit有效时更新128 bit数据。RTL仅描述clock-enable语义，不手动例化ICG。

6.6 R0 多路退休

R0需要完成连续DONE检查、最多4路数据选择、输出旋转和history更新。第一版保持
单级退休；若后续拆分流水，必须继续支持连续每周期最多4个报文退休。
Active result的4-bank组织保证连续4个ROB ID分别落入不同bank。R0对每个bank只执行
一次8:1行选择，再按head低2位以固定rotate-by-1/rotate-by-2网络恢复slot 0..3顺序，
避免四份相互独立的32:1宽数据选择。
ppe_retire_output在固定N=4基线下使用由start_lane两位分别控制的rotate-by-1和
rotate-by-2两级barrel网络，不使用动态物理lane写索引。retire_count由合法dense-prefix
valid的五种编码直接译码。每个物理输出lane继续使用公共packet寄存器使能，以保留自动
clock-gating推断机会并抑制无效lane宽数据翻转。

6.7 实现后的优化观察方向

首版结构按第7节固定。实现完成后可根据时序与性能数据观察：

  1) 单个D2A级内8取4shortlist和固定4x4单轮legal/multi-grant网络组合深度；
  2) D3 payload、active ROB/history多路读取和FE宽数据路由；
  3) completion/retirement bypass的tag比较、优先选择和宽数据扇出；
  4) W0四路任意地址写回的decode和数据扇出；
  5) R0单级退休和输出旋转的组合深度；
  6) FE_NUM=4下的实际FE利用率和服务能力。

================================================================================
7. 首版基线与后续优化边界
================================================================================

首版 RTL 固定采用：

  1) FE_NUM=4、ISSUE_WIDTH=4；
  2) D2拆为D2A匹配/claim和D2B预约/commit，D2B与D3之间继续保持selected-metadata流水边界；
  3) issue table为每个FE实现一份可同周期消费/重填的selected-metadata寄存器，scheduler维护
     一组grant寄存器和每FE 6项相对未来返回表；
  4) FE completion只写active ROB，只有retirement写8-bank history；
  5) dependency gather按四级优先级支持最多4路读取，不在issue entry中复制宽依赖；
  6) R0使用单级退休并直接更新顶层输出寄存器；
  7) 不定义可综合的异常上报、恢复或全局锁死状态，内部一致性由验证侧检查。
  8) scheduler把32项issue状态静态划分为4个8项交错bank，每bank每周期提名至多1项
     并维护两个固定本地候选槽。D2A从每bank两个槽中选出至多1项参与4x4匹配；
     不维护全局候选compact、跨bank重排或严格年龄队列，宽报文数据只保存在ROB。
  9) ingress使用两项整批elastic FIFO并寄存输出bkps；两个槽位均是输入边界寄存器，
     原始顶层输入不进入任何功能组合路径，backend只对寄存head提供内部allocation ready。

上述项目只有在后续时序或性能数据证明有必要时才重新评估。变更任一项都必须先同步
HLD和LLD，不得在RTL中自行启用。

内部端口命名、entry字段、状态编码、索引计算、端口冲突处理和逐周期更新规则不在
HLD中展开，统一维护在doc/lld.txt。

================================================================================
8. 核心架构不变量
================================================================================

  1) backend是ROB allocation、retirement和occupancy的唯一所有者。
  2) ingress拥有输入skid FIFO、寄存bkps和next_seq_tag，scheduler只管理尚未进入FE的调度状态。
  3) FE completion只写active ROB并形成bypass/wakeup事件，不写retired history。
  4) 报文装入顶层输出寄存器时视为退休，并同步更新retired history。
  5) 依赖解析严格按completion bypass、retirement bypass、active ROB、history排序。
  6) active ROB命中但result_valid=0时必须等待，禁止继续使用history。
  7) 所有依赖查询必须检查完整seq tag，bank低位索引不得单独作为命中。
  8) Packet和FE仲裁不得产生永久饥饿。
  9) 全局反压禁止部分接收一个多lane输入周期。
  10) 除clk/rst_n外，顶层输入只能驱动ingress输入捕获寄存器；所有顶层输出包括bkps
      均只能由寄存器直接驱动。
