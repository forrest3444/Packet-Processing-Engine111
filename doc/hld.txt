PPE High-Level Design
版本：Draft 0.4
状态：首版 RTL 系统架构与流水边界已收口

本文档描述 PPE 的系统架构、模块职责、状态所有权、主要数据流和流水级边界。

文档层级：

  1) doc/ppe_feature_description.txt：功能语义和外部行为；

================================================================================
1. 设计目标与基线配置
================================================================================

PPE按状态所有权划分为以下主要逻辑模块：

  1) PPE_TOP_SV：顶层集成及FE阵列例化；
  2) PPE_INGRESS：两项elastic batch FIFO、寄存bkps、报文序分配、依赖目标预计算和allocation bundle生成；
  3) scheduler：issue table、依赖等待、候选选择、FE匹配、operand gather和返回日历；
  4) backend：ROB、FE写回、依赖结果解析、保序退休、history和内部allocation容量判断。

RTL实现可将scheduler和backend中的状态所有者、纯组合选择器进一步拆为独立
文件，但不得因此形成多模块共同写同一状态数组。具体文件和接口在LLD中定义。

第一版基线配置：

  N            = 4
  FE_NUM       = 4
  MAX_DEP      = 7
  ISSUE_WIDTH  = 4
  ROB_DEPTH    = 32
  ISSUE_DEPTH  = 32
  ROB_ID_W     = 5
  SEQ_W        = 6
  RTL_LANGUAGE = SystemVerilog

共享基线配置由受include guard保护的ppe_config.vh统一定义，跨模块使用且必须保持一致的结构参数不得在子模块
例化处重复硬编码。ISSUE_DEPTH由ROB_DEPTH派生，ISSUE_WIDTH由FE_NUM派生；ROB_ID_W、
SEQ_W和history索引宽度继续由基础配置推导。只有直接定义可复用模块端口数据宽度的
PACKET_W/DESC_W保留为模块参数，并由顶层统一向下传递。模块私有存储深度和计数器宽度
使用localparam，不向外暴露。

可综合RTL统一位于rtl目录，使用小写文件名；设计模块名使用大写字母，并采用.v文件。
重复多位通道使用SystemVerilog unpacked array，其余逻辑保持克制的Verilog风格。
仓库不再保留旧版实现或自动生成镜像，避免形成两套设计源和维护分叉。

1.1 设计优化优先级

功能正确性是硬门槛。在功能正确的前提下，性能是首要优化方向，重点保持 FE 利用率、
多发射能力、多退休能力，并避免不必要的停顿和过长的关键组合路径。

功耗和面积作为辅助收敛目标，主要通过减少无效翻转、避免重复宽数据存储、合理使用
寄存器使能、清晰划分状态所有权以及遵循可综合编码规范进行控制。

当前环境不使用定量评分模型指导编码取舍。缺少工具数据时，PPA 判断仅作为定性分析，
不得为了未经验证的功耗或面积收益主动牺牲明确的吞吐能力。

1.2 阶段性时序目标

当前Nangate45比较环境的系统级阶段性目标频率固定为350 MHz，对应时钟周期2.857 ns。
该目标用于前端综合和pre-CTS布局后的相对收敛判断，不代表公司工艺签核结论。默认使用
typical Liberty、0.050 ns时钟不确定度和0.200 ns输入输出延迟，并在报告中明确寄生参数
模型和时钟阶段。

为给跨模块连线、setup和后续时钟实现保留余量，scheduler各寄存边界之间的数据到达
时间以不超过2.3 ns为局部优化目标；超过2.5 ns的单级路径必须进入结构复审。局部目标
是设计预算而非功能语义，不得通过降低多发射吞吐、取消公平性或改变FE返回冲突规则
换取时序。新增流水边界时必须同步本HLD和LLD中的逐周期定义。

2. 系统框图
================================================================================

                               PPE_TOP_SV
  +------------------------------------------------------------------------+
  |                                                                        |
  |  Top Inputs                                                            |
  |       |                                                                |
  |       v                                                                |
  |  +-------------+      +---------------------------+                    |
  |  | PPE_INGRESS |----->|         scheduler         |                    |
  |  | skid/bkps   |      | issue / wakeup / matching |                    |
  |  +------+------+      | gather / return calendar  |                    |
  |         |             +-------------+-------------+                    |
  |         | allocation metadata       | FE requests                      |
  |         |                           v                                  |
  |         |                FE0 / FE1 / FE2 / FE3                         |
  |         |                           | completion + tag                  |
  |         v                           v                                  |
  |  +------------------------------------------------------------------+  |
  |  |                           backend                                |  |
  |  |  ROB: allocation / writeback / dependency resolve / retire      |  |
  |  |       active results / bypasses / 8-bank retired history        |  |
  |  |  retire_output: lane mapping / registers / start-lane rotation  |  |
  |  +---------------------------+--------------------------------------+  |
  |                              +--> reservation mask/ready / output        |
  |  ingress registered bkps ------------------------------------------->  |
  +------------------------------------------------------------------------+

主数据流：

  Top Input -> Ingress -> Scheduler -> FE Array -> Backend ROB -> Registered Output

主要控制回馈：

  Backend -> Ingress：基于occupancy和已寄存退休lookahead的reservation ready
  Ingress -> Top/Input：寄存全局bkps
  Top Input -> Ingress：仅连接输入捕获寄存器
  Backend -> Scheduler：依赖满足状态、依赖结果数据和retirement事件
  Backend -> Scheduler：每个READY bank的最老未退休row
  Scheduler -> Backend：分配metadata、依赖目标请求和FE writeback关联信息

3. 模块职责与状态所有权
================================================================================

3.1 PPE_TOP_SV

PPE_TOP_SV 保持轻量，负责：

  - 例化PPE_INGRESS、PPE_SCHEDULER、PPE_ROB、
    PPE_RETIRE_OUTPUT和4个FE；
  - 顶层外部输入/输出lane和内部重复多位lane/FE通路均使用unpacked array表达，
    不展开固定编号的独立lane端口；逻辑索引0固定对应数组元素0；单比特valid、enable
    和mask在需要按位运算时仍使用packed vector；
  - 实现唯一的两级复位同步器，将异步拉低、同步释放的内部复位同时分发给
    全部PPE子模块和FE；
  - 将ppe_retire_output的寄存器输出连接到顶层端口。

PPE_TOP_SV 不保存报文级状态，不参与报文序、依赖或保序决策。

3.2 PPE_INGRESS

ppe_ingress负责：

  - 顶层输入批次准入和两项整批elastic FIFO；
  - 生成并保存寄存全局bkps；
  - 有效lane rank计算和密集seq tag分配；
  - 从完整seq tag预计算target seq tag；
  - 将输入descriptor解码为delay和dep_required语义字段；
  - 在ROB接受容量reservation后寄存allocation metadata和原FIFO槽位号；
  - 下一周期向ROB和issue table形成同一保证提交的allocation事件；无依赖entry直接
    初始化为READY，有依赖entry先初始化为WAIT_DEP并捕获窄依赖状态探针。

ppe_ingress拥有两项输入批次槽位、读写指针、占用计数、bkps寄存器、next_seq_tag和一项
窄allocation commit bundle。两项
槽位同时承担顶层输入寄存和有序FIFO存储，不设置独立capture数据副本。它不拥有ROB容量、等待
状态、依赖结果或FE调度状态。
完整seq tag是allocation的唯一跨模块身份；issue table和backend分别从其低位派生本地
物理索引。History bank索引直接从完整seq tag低3位派生，ingress不产生、不输出独立
ROB ID或residue字段。

两项输入FIFO按固定深度结构实现：沿后占用由capture/head release组合更新，宽
packet/descriptor存储采用bank-local写使能，避免动态bank写索引进入宽寄存器使能路径。
固定N=4配置下，两个slot各自并行形成lane rank、有效报文计数和窄allocation metadata，
slot_rd_ptr只在算术之后执行末级2:1 head选择。target tag直接按
next_seq_tag+sign_extend(rank-dep_offset)形成，不串联seq加法与target减法。
FIFO非空时commit metadata寄存器预览当前head；commit valid仍只在reservation成功时
置位，因此ROB ready不进入metadata寄存器写使能。以上实现不复制128 bit packet，
也不改变I0/D0寄存边界、整批准入语义或allocation吞吐能力。

3.3 scheduler

PPE_SCHEDULER是报文进入FE前的唯一调度状态所有者，负责issue状态、依赖
唤醒、READY提名、候选缓冲、FE匹配、operand gather流水和返回日历。原
Issue Table与FE Scheduler之间的candidate/select反馈接口取消，候选的选择、删除和
同bank补位由Scheduler内部统一完成。

Scheduler保留32项窄issue metadata和4组两项窄候选槽。候选只保存seq tag、
target seq tag、delay和dep_required，不保存packet或dependency data。每bank并行计算
两个本地way的legal，仅一个合法时选择该way，两者均合法时按轮询选择。Bank0/2只在
FE0/1组成的偶数组内匹配，Bank1/3只在FE2/3组成的
奇数组内匹配；每组使用固定最大基数2x2网络，允许两个本地bank在组内借用FE，但不
允许跨组匹配。匹配结果不可撤销。

READY提名使用ROB输出的4个bank-local退休row年龄提示，在每个bank中优先发现最老的
可派发entry。Scheduler先在D1边界捕获该提示，后续bank扫描使用上一拍的已寄存起点；
该一拍提示只改变候选可见时延，不改变年龄投影、依赖合法性或候选way/组内轮询公平。

Scheduler在D2A使用当周期calendar并行计算两个本地way的legal，选出至多一个合法way
后执行固定2x2匹配。delay 3直接形成全合法向量，不读取future table。D2A捕获不可撤销grant；
D2B消费grant时释放候选槽、将issue entry转为SELECTED并允许同bank补位。
依赖查询与grant在同一个D2A沿发起，使用当前D2A组合grant的target tag和dep_required；
ROB在D2A沿锁存窄query。D2A到D2B之间，completion bypass、active ROB和history分别形成
候选命中与数据，D2B沿按固定优先级流水寄存这些候选。D3/FE周期只执行已寄存候选的
浅层优先级选择，避免下一条query覆盖当前grant的响应。scheduler不复制长期依赖状态，
ROB中的候选寄存器只作为单拍响应流水。

Scheduler继续拥有per-FE 6项相对未来返回表和完整tag关联。Grant提交时使用
已锁存seq tag/delay写入返回表；FE结果数据仍直达ROB，不经过Scheduler宽数据
组合通路。返回表按FE静态分区，并由固定delay case选择写入槽，禁止用跨FE和跨槽的
动态写索引实现。Scheduler不拥有报文的长期顺序、处理结果或输出状态。

Scheduler按生产者ROB ID维护每项7 bit反向waiter关系。D0B先将consumer与target完整
seq tag之差译码并寄存为offset 1..7，D0C确认依赖尚不可用时复用该窄编码登记；D2B消费不可撤销grant时读取对应
窄waiter行并寄存early-wakeup token。token下一沿才更新WAIT_DEP状态，因此delay 3
额外经过一拍窄token延迟，保证所有生产者在READY更新时均已进入距完成不超过3拍的
安全窗口。D0C状态查询和实际completion唤醒继续作为晚到消费者及并发边界的正确性
兜底；反向关系不保存或转发依赖数据。

waiter注册沿用ROB ID低2位的4-bank、每bank 8-row物理划分。每个依赖lane先在目标
bank内生成3 bit row one-hot，再由同一bank的最多4路请求按7 bit offset做局部OR；
不构造跨32项的重复producer比较网络。waiter的逻辑编号和完整tag语义不变，该划分
只改变注册写使能的物理展开。

维护版调度允许同一delay的多个候选在同周期映射到不同FE，只要对应FE目标返回槽
均合法；不按delay固定绑定FE。该多发策略属于维护版微架构与吞吐目标，不属于外部
功能spec。实验架构可以在独立HLD中选择不同策略，但不得替换维护版RTL。

3.4 PPE_ROB

ppe_rob是全局顺序、结果和容量状态的唯一所有者，负责：

  - ROB allocation、head/occupancy和严格按序的逻辑retirement prefix；
  - allocation原始packet保存和grant后operand gather；
  - FE completion 写回；
  - completion bypass、retirement bypass、active ROB和retired history四级依赖解析；
  - 8-bank已退休history生命周期管理；
  - 维护ROB occupancy和pending-retire count，并按Ingress reservation mask输出ready；
  - reservation沿提前计入occupancy，使下一周期allocation commit无需再次反压；
  - ready只在ROB内部按固定1/2/3/4项case判断，不把宽容量算术搬到Ingress。

ppe_rob不保存物理输出lane状态，也不直接驱动顶层输出寄存器。它向ppe_retire_output输出
按报文序排列、从slot 0开始无空洞的逻辑retirement bundle。

固定ROB_DEPTH=32、N=4实现将128 bit统一data按ROB ID低2位组织为4个bank，每个bank含
8项；valid和result_valid作为独立小位宽metadata阵列。完整seq_tag的低5位由entry
物理索引隐含，ROB entry仅保存高位generation；所有命中仍等价检查完整seq_tag。
Allocation把
原始packet写入data并清result_valid；FE completion原址覆盖data并置result_valid。
为切断退休容量计算到宽data阵列写使能的路径，A0在allocation沿更新metadata并按低2位
bank捕获原始packet，A1下一沿提交到对应data bank。D0A只寄存原FIFO槽位号和窄metadata；
D0B commit沿从该槽读取沿前旧packet并捕获bank-local row/data。
密集seq tag保证一个allocation批次对每个bank至多一写；若grant后source gather与A1
捕获寄存命中同一bank/row，从A1捕获寄存器转发，否则读取data bank。
Allocation容量判断不组合借用本周期retirement prefix释放的entry，只借用已经寄存且
本沿必提交的pending-retire count。ROB按reservation mask的有效lane数做固定case判断；
D0A接受reservation时立即更新occupancy，D0B使用寄存bundle无条件提交metadata和packet
捕获。该边界切断FIFO head解析到ROB/Issue Table状态阵列的路径，同时允许满载稳态retire、
reservation和commit逐周期并行。
Writeback复用Scheduler的奇偶bank约束：FE0/1只写Bank0/2，FE2/3只写Bank1/3。
每个entry只检查所属FE pair并在本地完成完整tag资格检查和固定2选1数据归并；同一bank
仍允许对应FE pair同时写不同row，不设置bank冲突停顿。不得以动态宽数组写索引生成
覆盖全部data存储的写数据网络。连续4项退休先从每个bank
各读取一个8项窗口，再按head低2位通过固定两级置换恢复逻辑顺序。该物理组织不改变
ROB ID、同周期四路写回总带宽、active dependency读取或退休周期语义。
Scheduler每周期从每个READY bank至多grant一项，且READY bank等于报文seq_tag低2位，
因此grant后source gather按4个data bank各执行一次8:1 row选择；不复制四份独立
32:1 source读取。Bank0/2只接收FE0/1请求并只向FE0/1返回，Bank1/3只接收FE2/3请求
并只向FE2/3返回，请求归并和响应选择均为固定2路。该约束只适用于报文本身的source
读取，dependency target仍允许同bank冲突并保持最多4路任意地址读取。
依赖查询采样沿前，retirement prefix仍是有效且result_valid的active ROB entry，因此
retirement bypass与active读取数值相同；实现将二者折叠为一条active读取，避免把head
比较广播到D0/D3，同时保持completion、retirement/active、history的可见性顺序。
Completion bypass按dependency target的bank奇偶只检查对应FE pair：偶数target检查
FE0/1，奇数target检查FE2/3，并以固定2选1归并128 bit数据；
ROB在D2A query寄存器之后分别形成completion、active、history候选，并在D2B寄存候选
数据和命中信息。D3只在per-FE路径上进行固定优先级选择，不使用跨四路串行greedy
选择链。selected metadata、source packet和对应依赖响应在D2B末端对齐，不额外增加
FE发射周期。
为避免grant valid同时控制ROB宽数据查询并驱动selected operand大量寄存器CE，grant
metadata在无效周期保持，ROB dependency datapath不使用gather valid门控；selected
operand数据字段允许无条件捕获，只有selected valid定义其语义。该策略不改变流水边界，
以少量潜在时钟功耗换取更低的valid控制扇出；无效周期地址稳定以限制无意义数据翻转。
D2A在锁存grant的同一沿按seq tag低位形成4份bank-local source row/tag-high寄存请求；
D2B的ROB source读取不再把per-FE grant valid和tag组合归并为bank地址。ROB按bank直接
返回4份packet，Scheduler按寄存grant的bank选择对应数据，因此不增加流水级并切断
grant valid到source packet宽数据通路。

Scheduler利用future table中表示下一返回沿的slot提前一拍寄存每个FE的完整seq tag和
ROB entry one-hot。one-hot在future slot无效时寄存为全0，自身具备valid语义，避免独立
valid广播到entry-local预测网络。实际FE返回沿，ROB以该预译码控制定位entry，并仍使用实际completion
valid/tag、active ROB tag和result-valid状态完成最终资格检查。预测信息不单独提交写回，
不改变completion或dependency bypass的功能时序。
由于FE延迟固定且不支持取消，future slot对下一返回沿是精确信息。ROB还使用该
寄存one-hot将本沿必完成的active entry纳入head DONE prefix；若退休项由该预测
命中，退休数据从对应FE writeback data旁路，不等待result-valid落入ROB后再扫描。
one-hot由完整future seq tag生成，且active entry在其completion之前不可退休复用；因此
预测DONE只检查one-hot、active valid和result-valid，不重复完整tag比较。实际writeback
路径仍执行完整tag及状态检查。
这使head completion、逻辑退休和retire-count寄存在同一沿发生，容量判断仍只借用
沿前已寄存的retire-count，不引入当前退休扫描到reservation ready的组合通路。
退休DONE prefix以两组两项AND平衡生成；ROB head-bank和output start-lane都从
dense retire-valid推导两位modulo-4 advance并计算next-state，不串接3 bit retire-count
编码和通用加法。实现可使用等价的奇偶/XOR逻辑，retire-count仍在独立支路上寄存，
仅供occupancy容量判断使用。

3.5 PPE_RETIRE_OUTPUT

ppe_retire_output是backend功能域内独立的最终输出子模块，负责退休结果的外部呈现：

  - 将逻辑retirement bundle按当前start_lane映射到物理输出lane；
  - 保存并更新start_lane；
  - 驱动同一级顶层out_valid/out_packet寄存器。

ppe_retire_output不封装ppe_rob，也不转发allocation、依赖查询或writeback接口。
ppe_top分别例化并连接两者。retirement bundle先在ppe_retire_output内部捕获，下一拍
再执行固定旋转并装载顶层输出寄存器；该边界不增加ready或反压接口，仅增加一拍输出延迟。
ROB状态释放和history写入仍由ROB在原退休沿完成，start_lane与输出寄存器由输出模块独立维护。

================================================================================
4. 高层数据流
================================================================================

4.1 输入接收

当寄存bkps允许接收时，ingress只把当前所有lane的valid、packet和descriptor写入
两项elastic FIFO的寄存tail槽位，不在该沿执行sequence allocation、空批判断或ROB容量
计算。FIFO保持批次顺序；下一周期起，寄存head为空批时直接释放，非空head获得backend
ROB ready允许后，ingress计算密集seq tag和dependency target并在
D0A末端寄存；D0B再把同一commit bundle送入Scheduler和ROB。完整descriptor不离开ingress；
scheduler只接收delay和dep_required。一次输入周期必须整体接收或整体停止，禁止部分lane接收。

4.2 依赖处理

依赖报文在allocation时保存完整target seq tag。D0C状态探针和FE completion tag只更新
issue状态；被唤醒报文最早下一周期参与READY提名。Scheduler不保存非权威依赖副本。

候选获得最终grant后，在D2A沿使用当前grant组合结果发起窄target query。Backend
在D2A到D2B之间并行检查completion bypass、active ROB和8-bank retired history，并在D2B
按per-FE寄存候选响应。D3/FE周期只做候选数据的固定优先级选择。宽依赖数据不复制到
32项issue entry或8项候选窗；ROB响应寄存器仅保存一拍候选，不形成fast-cache、fallback
或replay状态。

4.3 FE 调度

ISSUE_READY报文按ROB ID低2位进入4个8项交错bank，每bank维护两个固定窄候选槽。
每bank每周期最多提名1项；若D2B消费寄存grant并释放一个槽，同沿可以从沿前READY集合补入一项。
各bank从ROB对应bank的最老未退休row开始环形扫描，优先提名最接近退休头的READY项；
不保存独立READY扫描指针。
无依赖allocation在没有旧READY winner时可直接进入空槽。Completion和D0C更新不组合
直通提名。

D2A从每bank两个way中选择至多1项合法候选形成4项shortlist；仅在两个way均合法时使用
way轮询状态。偶数bank和奇数bank分别进入
两个独立的固定2x2匹配网络。每组优先选择可双发的直连或交叉映射；不能双发时由本组
1 bit轮询状态决定候选和FE优先级。Grant不可撤销。D2A锁存窄metadata和candidate
one-hot，并同时发起依赖窄query；D2B再原子删除候选、更新candidate_present和issue状态，
同时接收与该grant对应的分源依赖候选。同bank另一way不受阻塞。

Scheduler维护per-FE 6项相对未来返回表。delay 0..2分别检查future slot3..5和上一拍
grant的虚拟预约，delay 3对所有FE合法。D2B以寄存grant metadata写入预约slot[delay+1]，
并与ROB的D2B依赖候选响应对齐；D3从per-FE selected operand路径完成最终数据选择并送入FE。
流水允许连续周期grant、query、candidate response和FE issue并行，不因候选释放或响应
寄存器产生隔周期气泡。

4.4 FE 写回

每个FE通过scheduler返回日历当前周期槽保存的ROB tag将结果写回对应ROB entry。
FE可以乱序完成，但completion只写active ROB并形成tag wakeup/bypass事件，不写retired
history，也不得绕过ROB直接输出。

4.5 保序退休

ppe_rob从ROB head开始退休最多4个连续DONE报文，并向ppe_retire_output提供无空洞的逻辑
退休前缀。ROB退休事件完成顺序状态更新；ppe_retire_output在其后捕获并延迟一拍呈现输出：

  - 更新8-bank retired history；
  - 释放 ROB entry；
  - 推进ROB head；
  - ppe_retire_output按捕获bundle映射并装入顶层输出寄存器，推进输出lane指针。

严格保序可能产生 head-of-line blocking，这是功能要求。调度策略应避免无必要地延迟
接近 ROB head 的可派发报文。

4.6 全局反压

bkps由ingress寄存器直接驱动，任何原始顶层输入或ROB状态均不得组合直通该端口。
两项elastic FIFO槽位直接终止所有原始输入，总计提供两批物理容量。bkps next-state
只根据寄存占用、当前bkps状态和寄存head是否将在本沿释放计算；不读取任何当前原始输入。

Backend维护occupancy和pending-retire count。Ingress把已寄存head的lane-valid mask送入ROB，
ROB按有效lane数直接case判断occupancy减去pending-retire后的容量；ready返回Ingress后，
Ingress只在ready为真时释放head并产生reservation。这样当前retirement scan不进入容量路径，
同时保留pending-retire带来的同周期容量复用，不会因容量反馈延迟超卖ROB。
当bkps_q=0时，tail capture和head release允许同沿发生，因此连续可分配流量不产生结构
气泡。若capture后两槽占满，则下一拍bkps拉高；满状态中的head释放后，bkps在下一有效沿
重新拉低。相较三批结构，本方案减少一批宽数据存储和一级搬移选择，代价是依赖重载或ROB
停顿时更早施加反压；不得以此为由降低内部4-wide allocation能力。

同址 retirement 与 allocation 可以在同一上升沿发生。retirement 使用沿前 ROB
内容产生输出并更新retired history，allocation对沿后ROB entry状态具有优先权，
从而使该 entry 立即代表新报文且 result 尚未有效。

================================================================================
5. 初步流水线划分
================================================================================

5.1 Ingress与Scheduler主流水

输入到FE发射划分为六个寄存边界阶段，并包含一条并行依赖事件通路：

  I0：External Input Capture
      在寄存bkps允许时将完整原始输入无条件写入两项elastic FIFO的tail槽位；
      不执行功能解析或capture到FIFO的数据搬移。

  D0A：Input Admission / Capacity Reservation
      对elastic FIFO寄存head执行空批释放、顺序分配和依赖目标预计算；ROB接受
      reservation时推进FIFO和seq状态，并在本级末端寄存commit bundle。

  D0B：Allocation Commit
      将D0A已获容量保证的commit bundle无条件写入ROB和Scheduler。ROB捕获原始
      packet，Scheduler初始化READY或WAIT_DEP并寄存窄依赖状态探针。

  D0C：Dependency Status Resolve
      使用D0B寄存的状态探针查询依赖available；命中时将对应WAIT_DEP entry转为
      READY。响应使用D0B寄存的consumer物理entry ID直接形成entry-local写使能，
      不对32项issue entry执行consumer完整tag反查。本级不保存或搬移128 bit packet。

  D1：Bank-local READY Nomination
      四个8项bank并行各提名至多1项，写入本bank两项窄候选槽。D0B
      allocation、D0C状态更新和本周期completion wakeup不组合进入提名。

  D2A：Candidate Shortlist / Local Pair Match
      组合从每bank两个候选中按legal和轮询提取至多1项，按bank奇偶进入两个固定2x2匹配网络。
      本级末端锁存不可撤销grant的candidate one-hot、seq tag、target tag、delay和
      dep_required；已grant way在下一周期被屏蔽。

  D2B：Return-slot Commit / Operand Gather
      消费寄存grant，删除候选、更新issue状态并允许同bank补位；同时使用寄存metadata
      写入返回预约并向ROB发出gather请求。ROB在请求侧寄存窄query，随后组合返回原始
      packet和所需的权威dependency data。

  D3：Registered Operand Issue
      在per-FE selected寄存器捕获metadata和source packet；沿后从ROB窄query对应的
      内部组合结果获得dependency data，并由FE输入寄存器采样；同沿释放对应
      ISSUE_SELECTED entry。

  Dependency Event Path：
      D0C以active ROB/history状态及completion/retirement bypass更新entry；后续
      D0C未命中时登记7 bit反向waiter。D2B不可撤销grant读取waiter并寄存提前唤醒
      token，下一沿更新ISSUE_WAIT_DEP entry；completion tag保留兜底唤醒。该通路
      不允许同沿直通FE。

D2A、D2B和D3必须保持逻辑分离。READY发现和队列入队不进入匹配关键路径；
D2A末端捕获窄grant metadata，D2B执行ROB gather和返回预约，D3从selected寄存器
驱动内部FE接口；dependency最终选择位于窄query寄存器之后，不再挤占grant到selected
metadata的宽数据时序窗口。

5.2 Backend并行通路

Backend不采用单一线性流水，而是包含四条并行通路：

  A0/A1：ROB Metadata Allocation / Bank-local Packet Commit
  G0：Dependency Status / Data Gather
  W0：FE Writeback
  R0a：In-order Retire / Retirement Bundle
  R0b：Retire Bundle Capture / Registered Output

A0、G0、W0和R0a可以在同周期处理不同ROB entry；R0b只消费上一沿的退休bundle。它们共享的ROB状态必须由统一
状态所有权和 next-state 逻辑协调。

5.3 高层流水关系

  Input I0 -> D0A -> D0B -> D0C -> D1 -> D2A -> D2B -> D3
                  |       |                               |
                  v       v                               v
           ROB Reservation A0/A1               FE(fixed delay + 1 cycles)
                                                    |
                                                    v
                                         Backend W0 -> R0a -> R0b -> Output

  D0A只预留ROB容量并形成寄存bundle；Backend A0与D0B commit并行，A1只提交上一沿
  已经捕获的bank-local packet。D0B中无依赖entry直接初始化为READY；只有依赖状态
  探针经过D0C。新增边界增加一拍最短输入到READY延迟，但reservation和commit允许
  相邻批次逐周期并行，不降低每周期4路allocation吞吐。
  Backend G0为D0C提供最多4路小位宽available状态，并为grant后gather提供最多4路128 bit依赖数据。
  G0按completion bypass、retirement bypass、active ROB、retired history优先级解析。

================================================================================
6. 高风险路径与可优化点
================================================================================

6.1 FE 服务能力

4个FE均支持无阻塞流水，每个FE理论上可逐周期接收请求，但同一FE的目标输出周期
不得冲突。6项相对返回表和可同周期消费/重填的selected-operand寄存器释放FE流水吞吐；实现后
重点检查混合delay造成的槽碎片、D2A匹配效率以及长流下是否接近4路持续issue。

6.2 D2A 多发射仲裁

8项候选按4 bank × 2 way组织。D2A先做四组固定2选1，再将Bank0/2送入FE0/1、
Bank1/3送入FE2/3。每个2x2网络直接检查直连和交叉双发条件；若均不可双发，再按
1 bit轮询状态选择单个合法映射。两个网络完全并行，不存在跨组legal、请求、接受或
retry链。该结构牺牲跨组FE借用能力，以缩短匹配路径并降低控制扇出；不得退化为
数据相关greedy循环。

6.3 D2B Operand Gather

Grant后source gather仍包含4个bank-local 8:1 source读取；依赖查询在D2A沿发起，D2A到D2B
之间并行执行completion pair、active ROB和history的局部读取与tag匹配。Source请求来自
四个不同issue bank，因此每个source data bank至多一读；dependency target允许同bank冲突，
继续保持每路独立语义。Bank0/2的请求和响应只连接FE0/1，Bank1/3只连接FE2/3；每bank
请求归并和每FE响应选择均为固定2路，不形成通用4x4交叉网络。
D2B寄存各依赖来源候选，D3只保留固定优先级宽mux，不进入D2A匹配路径。ROB扩深或增加
依赖读取端口时必须重新评估D2A-D2B局部读取、候选寄存器面积以及D3宽mux时序。

6.4 G0多路依赖读取

G0需要支持最多4个D2A已发起依赖报文的候选解析并允许一份结果广播到多个FE。Completion
bypass根据target_seq_tag[0]选择合法completion pair：偶数target只比较FE0/1，奇数
target只比较FE2/3，再以固定2选1形成completion候选；active和history各自形成局部候选，
在D2B寄存后由D3按固定优先级选择。该拆分不增加FE发射周期，也不得降低每周期4路
gather能力。

6.5 W0 多路写回

W0必须无条件接收最多4路任意seq tag写回，并从tag低位派生本地ROB写地址。不得依赖单写端口存储或通过反压FE解决。
多路地址decode和宽数据扇出是主要实现风险。
固定基线使用共享小位宽decode生成per-entry one-hot commit；每个result entry只在自身
commit有效时更新128 bit数据。RTL仅描述clock-enable语义，不手动例化ICG。

6.6 R0 多路退休

R0需要完成连续DONE检查、最多4路数据选择和history更新。第一版保持逐周期4-wide
退休。Head和逻辑retirement bundle在R0生成；entry清除和history写入由一项逐周期
pending-retire寄存器在下一沿提交。提交前旧active entry继续提供依赖数据，提交后history
接替，禁止产生不可用空窗。ppe_retire_output在ROB bundle之后增加一项内部capture寄存器，
把输出旋转与ROB退休扫描解耦；Occupancy使用寄存的上一周期retire_count释放空间，
allocation容量可安全借用该已寄存且本沿必提交的retirement lookahead，不依赖当前head扫描。
Active result的4-bank组织保证连续4个ROB ID分别落入不同bank。R0对每个bank只执行
一次8:1行选择。物理head拆分为2 bit head bank和每bank一个3 bit row cursor，
各bank直接以寄存cursor读取DONE和data；退休沿只推进被消费bank的cursor。
读取结果再按head bank以固定rotate-by-1/rotate-by-2网络恢复slot 0..3顺序，
避免动态row修正和四份相互独立的32:1宽数据选择。dense-prefix count由五种合法编码
直接译码，不得描述为跨四项的累加链。退休ROB ID由各bank的{row cursor, bank ID}
直接形成，tag generation和DONE也按同一固定网络旋转，不从重建的完整head执行
head+j加法或32项动态tag选择。
ppe_retire_output在固定N=4基线下使用由start_lane两位分别控制的rotate-by-1和
rotate-by-2两级barrel网络，不使用动态物理lane写索引。start_lane由合法dense-prefix
valid直接生成modulo-4 advance。每个物理输出lane继续使用公共packet寄存器使能，以保留自动
clock-gating推断机会并抑制无效lane宽数据翻转。

6.7 实现后的优化观察方向

首版结构按第7节固定。实现完成后可根据时序与性能数据观察：

  1) 单个D2A级内8取4shortlist和两组固定2x2匹配网络组合深度；
  2) grant后payload/dependency gather的ROB/history多路读取；
  3) completion/retirement bypass的tag比较、优先选择和宽数据扇出；
  4) W0奇偶组局部写回的entry decode和数据扇出；
  5) R0单级退休和输出旋转的组合深度；
  6) FE_NUM=4下的实际FE利用率和服务能力。
  7) 反向waiter行读取、wake token展开相对32项completion广播扫描的时序和面积收益。

================================================================================
7. 首版基线与后续优化边界
================================================================================

首版 RTL 固定采用：

  1) FE_NUM=4、ISSUE_WIDTH=4；
  2) D2拆为D2A局部2x2匹配/claim和D2B gather/预约，D2B与D3之间保持selected-operand流水边界；
  3) PPE_SCHEDULER为每个FE实现一份可同周期消费/重填的selected-operand寄存器，并维护
     一组grant寄存器和每FE 6项相对未来返回表；
  4) FE completion只写active ROB，只有retirement写8-bank history；
  5) grant后dependency gather按固定优先级支持最多4路读取，不在issue entry或候选窗复制宽依赖；
  6) R0保持单级保序退休，ppe_retire_output在bundle后增加一拍capture再更新顶层输出寄存器；
  7) 不定义可综合的异常上报、恢复或全局锁死状态，内部一致性由验证侧检查。
  8) scheduler把32项issue状态静态划分为4个8项交错bank，每bank每周期提名至多1项
     并维护两个固定本地候选槽。D2A从每bank两个槽中选出至多1项，按bank奇偶参与
     两个固定2x2匹配；
     不维护全局候选compact、跨bank重排或严格年龄队列；候选槽只保存窄metadata，
     packet和所需dependency在grant后从ROB gather。
  9) ingress使用两项整批elastic FIFO并寄存输出bkps；两个槽位均是输入边界寄存器，
     原始顶层输入不进入任何功能组合路径，Ingress与backend之间使用已寄存head mask和reservation ready。

上述项目只有在后续时序或性能数据证明有必要时才重新评估。变更任一项都必须先同步
HLD和LLD，不得在RTL中自行启用。

内部端口命名、entry字段、状态编码、索引计算、端口冲突处理和逐周期更新规则不在
HLD中展开，统一维护在doc/lld.txt。

================================================================================
8. 核心架构不变量
================================================================================

  1) backend是ROB allocation、retirement和occupancy的唯一所有者。
  2) ingress拥有输入skid FIFO、寄存bkps和next_seq_tag，scheduler只管理尚未进入FE的调度状态。
  3) FE completion只写active ROB并形成bypass/wakeup事件，不写retired history。
  4) 报文装入顶层输出寄存器时视为退休，并同步更新retired history。
  5) 依赖解析严格按completion bypass、retirement bypass、active ROB、history排序。
  6) active ROB命中但result_valid=0时必须等待，禁止继续使用history。
  7) 所有依赖查询必须检查完整seq tag，bank低位索引不得单独作为命中。
  8) Packet和FE仲裁不得产生永久饥饿。
  9) 全局反压禁止部分接收一个多lane输入周期。
  10) 除clk/rst_n外，顶层输入只能驱动ingress输入捕获寄存器；所有顶层输出包括bkps
      均只能由寄存器直接驱动。
