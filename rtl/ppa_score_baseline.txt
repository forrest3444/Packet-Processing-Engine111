PPA Score Baseline and Target
=============================

1. Score Formula
----------------

  score = (t0 / tx)^2 * (p0 / px)^0.5 * (a0 / ax)^0.5 * 100

where:

  t  : total packet transmission time; determined by clock period and throughput
  p  : power
  a  : area
  0  : standard baseline
  x  : design under evaluation


2. Standard Baseline
--------------------

  Baseline clock period : 0.4 ns
  t0                    : 31283
  p0                    : 0.0891
  a0                    : 16920

The company-provided FE is a black box:

  Area per FE           : 3500
  Four-FE total area    : 14000

The FE can meet the 0.4 ns upper-limit period and is not expected to be a
timing bottleneck.


3. Current Four-FE Result in the Company Environment
----------------------------------------------------

  Target clock period   : 0.5 ns
  tx                    : 31188
  px                    : 0.096
  ax                    : 42086
  Worst slack           : approximately -0.05 ns
  TNS                   : approximately -280 (retain the original report unit)

The 0.5 ns constraint is not closed. The observed critical delay is therefore
approximately 0.55 ns; the nominal tx=31188 result must not by itself be
treated as a timing-clean score.

Area decomposition, assuming ax includes all four FE black boxes:

  Fixed four-FE area    : 14000, or 33.26% of ax
  Non-FE design area    : 28086


4. Score From the Reported Nominal Data
---------------------------------------

  Performance factor   = (31283 / 31188)^2       = approximately 1.0061
  Power factor         = sqrt(0.0891 / 0.096)    = approximately 0.9634
  Area factor          = sqrt(16920 / 42086)     = approximately 0.6341

  Nominal score        = approximately 61.46

The area factor is currently the largest score penalty. This statement only
describes the score composition and is not an optimization proposal.

If execution time is scaled from the unclosed 0.5 ns target to the approximate
0.55 ns critical delay, the timing-clean equivalent is:

  tx at 0.55 ns        = 31188 * 0.55 / 0.5 = 34306.8
  Equivalent score     = approximately 50.79


5. Threshold Required for Score Greater Than 100
-------------------------------------------------

First hold px=0.096 and ax=42086 constant. Solving score > 100 for tx gives:

  tx < t0 * ((p0 / px) * (a0 / ax))^0.25
     < 24449.82

The current workload takes an inferred 31188 / 0.5 = 62376 clock cycles.
With the same cycle count and throughput behavior, the company-environment
clock period must therefore satisfy:

  period_company < 24449.82 / 62376
                 < 0.39198 ns

This is the zero-margin mathematical threshold. It assumes that tighter timing
does not increase power or area.


6. Corresponding Local Nangate45 Target
---------------------------------------

The current measured correspondence is:

  Local synthesis critical period      : approximately 1.0 ns
  Company-environment critical period  : approximately 0.55 ns

Using this single empirical scale point only as a first-order estimate:

  period_local_threshold = 0.39198 / 0.55 * 1.0
                         = approximately 0.713 ns
  frequency_local_threshold
                         = approximately 1.40 GHz

Therefore:

  Mathematical local threshold : below 0.713 ns
  Minimum practical experiment : 0.70 ns, approximately 1.43 GHz

At 0.70 ns, with power and area artificially held constant, the projected
score is only approximately 103.66. This leaves little margin for the power or
area increase caused by tighter synthesis. A 0.65 ns local constraint would
provide more timing-score headroom, but no score above 100 can be claimed until
power and area are remeasured under that constraint.

The local/company conversion is not a process-signoff model. It is inferred
from one observed design point and should be recalibrated whenever a new
company-environment synthesis result is available.
